# kinekino Hugging Face 클라우드 추론 확장 설계안 (읽기 전용 분석)

- 작성: 2026-10-29 21:50 KST (UTC+9) · 기준 커밋: `/workspace/kinekino` `refactor/workspace-restructure` `0c5dc4f` (리팩터링 진행 중이라 경로가 바뀔 수 있음)
- 이 문서를 쓰는 동안 파일 수정, 커밋, 추론 호출, 유료 호출은 하지 않았음. HF 커넥터는 읽기 전용 조회(whoami, repo 메타데이터)만 사용함.

## 1. 현재 구조 (AI 실행 경로와 HF 관련 코드)

### 1.1 설계 정본
- `docs/spec/adrs/player/adr-006-huggingface-local-model-pipeline.md`: HF Hub는 카탈로그와 아티팩트 유통 용도이고, 실행은 **작업별 로컬 추론**이 기본임. "항상 클라우드 추론"은 네트워크, 요금, 미디어 전송 때문에 기본 경로에서 **기각**됨. 이번 확장은 이 ADR을 개정(또는 새 ADR 작성)해서 "클라우드는 사용자가 명시적으로 고르는 선택 경로"로 추가해야 함.
- 고정 규칙: main/latest를 따라가지 않고 commit(40자 hex), 파일 sha256, 토크나이저, 양자화, 변환 계보, 라이선스, 런타임 버전을 고정함. 저장소의 임의 코드는 실행하지 않음. 결과에는 원본 시간과 모델 revision을 유지함.
- 관련 문서: `adr-010-measured-ai-candidates.md`, `docs/spec/sots/verification/ai/*`(e5, qwen-onnx, gguf, embeddinggemma 등)

### 1.2 코드 경계 (현재 루트 크레이트 `src/`)
```
domain/model_catalog.rs        ModelManifest{model_id, task(ModelTask), repo_id, revision(40hex), files[sha256], format(Safetensors|Gguf|Onnx), quantization, license, runtime, min_runtime_version, declared_measured_memory, evaluation_id}
                               ModelTask = Asr|Text|Ocr|Subject|Depth|SpeakerSegmentation|SpeakerEmbedding|Vad|Alignment
                               fixed_revision(): 40자 hex 강제
application/model_catalog.rs   models.list / models.inspect / models.verify CLI·API 명령
                               응답이 항상 runtime_admitted=false, quality_approved=false, license_permission=not_verified
infrastructure/model_catalog/  로컬 파일 해시 검증(verification.rs)
application/sdk_execution/     작업 실행 호스트: admission, budget(ExecutionBudget), cancel(CancelDisposition), snapshot/progress, terminal, recovery, close
application/ai_provenance/     과거 증거(historical evidence) import와 verify_bound, 제안(proposal)과 바인딩
application/proposals/ + infrastructure/proposals/   AI 결과는 "제안"이고 사용자가 수락(guarded.rs: revision과 sha256 앵커)
infrastructure/model_review/, presentation/studio/model_review/   결과 검토 UI(사용자 품질 승인)
crates/kinekino-vad, -vad-executor, -vad-worker   VAD는 별도 worker 프로세스
crates/kinekino-subtitles      자막 도메인(ASR 결과 소비)
crates/kinekino-catalog        reqwest =0.12.28 (blocking, rustls-tls)가 이미 의존성에 있음
```
- 확인 결과: 실제 ASR, 피사체 분할, 생성용 **추론 런타임 코드는 저장소에 없음**(onnx 등 grep 결과는 fixture뿐). 지금 있는 건 카탈로그·증거·실행 호스트·제안·검토 골격이고 VAD worker만 실행 경로가 있음. 그래서 클라우드 백엔드를 "첫 실제 추론 어댑터"로 만들어도 기존 로컬 경로와 충돌하지 않음.
- 설계안에 따른 목표 위치: `kinekino-core::studio::models`

### 1.3 계정 상태 (HF 커넥터 `hf_whoami`, 읽기 전용)
- 사용자 `cw4196`, **Pro 아님**. `modootoday` 조직에서 admin 역할임. 지금 커넥터 OAuth 범위에 `inference-api`가 포함돼 있음(커넥터용 토큰이고 앱에서 쓸 토큰이 아님).
- 공식 가격표상 Free 계정은 월 크레딧이 없어서 Inference Providers를 쓰려면 크레딧을 구매해야 함. PRO는 월 $2 크레딧이 있음. ([pricing](https://huggingface.co/docs/inference-providers/pricing)) 사용자가 말한 Pro는 GitHub Pro이고 HF Pro와는 별개임.

## 2. HF 클라우드 실행 옵션 비교

| 항목 | Inference Providers (router) | Inference Endpoints (전용) | Spaces / ZeroGPU |
|---|---|---|---|
| 형태 | 서버리스 프록시 `https://router.huggingface.co`. 여러 제공자(hf-inference, fal-ai, replicate, together 등)를 묶음 | 전용 컨테이너 배포(vLLM, TGI, 커스텀). 오토스케일 | Gradio 앱 API. ZeroGPU는 공유 GPU 할당 |
| ASR | 지원(HF Inference, fal, Replicate, Together) ([index](https://huggingface.co/docs/inference-providers/index)). `whisper-large-v3-turbo`는 hf-inference와 deepinfra가 live (커넥터 확인) | 아무 모델이나 배포 가능 | Space마다 다름 |
| 이미지 분할 | `image-segmentation` 태스크 있음. 입력은 base64 이미지, 출력은 label, mask(base64), score ([task](https://huggingface.co/docs/inference-providers/tasks/image-segmentation)). `briaai/RMBG-2.0`은 fal-ai live, gated, license other. `sam2-hiera-large`(apache-2.0)은 제공자 없음 | SAM2 같은 비지원 모델을 커스텀 핸들러로 배포 | 데모 Space는 많지만 API 안정성은 보장되지 않음 |
| 텍스트/이미지 생성 | 지원. chat은 OpenAI 호환 `/v1/chat/completions`, text-to-image도 지원 | 지원 | 지원 |
| 인증 | fine-grained 토큰의 "Make calls to Inference Providers" 권한 ([index](https://huggingface.co/docs/inference-providers/index)) | 토큰 권한 범위 **미확인**(엔드포인트 관리와 호출 권한) | 공개 Space는 토큰이 없어도 됨. ZeroGPU 쿼터는 토큰 기준(**미확인**) |
| 과금 | 제공자 단가를 그대로 넘겨받음(마크업 없음). hf-inference는 연산 시간×하드웨어 단가. 조직 과금은 `X-HF-Bill-To` 헤더 ([pricing](https://huggingface.co/docs/inference-providers/pricing)) | 인스턴스 시간당 과금(구체 단가 **미확인**). 켜 둔 시간 전체가 과금되니 scale-to-zero 필요 | ZeroGPU 일일 쿼터와 초과분 크레딧(수치 **미확인**) |
| 업로드 크기 한계 | **미확인**(공식 문서에서 찾지 못함). 오디오는 청크로 나눠 보내는 걸 전제로 함 | 페이로드 한계 **미확인** | **미확인** |
| 지연, 비동기 | 동기 HTTP. provider auto는 장애 시 자동 failover. 비동기 큐 API는 **미확인** | 콜드 스타트 있음(**미확인** 수치) | 큐 대기 있음 |
| 프라이버시 | HF 프록시를 거쳐 제3 제공자로 전송됨. 제공자별 보존 정책은 **미확인**이라 확인 필요 | 전용 인스턴스라서 통제가 가장 강함(정책 세부 **미확인**) | Space 소유자가 입력을 볼 수 있음. 미디어 업로드에 부적합 |
| Rust 연동 | 공식 Rust SDK는 없음(**미확인**). 순수 HTTP(JSON/바이너리)로 reqwest에서 바로 쓸 수 있음 | HTTP | Gradio HTTP API |

**결론:** 1차는 Inference Providers를 쓰고, 제공자는 **고정 지정**(auto 금지, provenance 재현성 때문)함. 2차로 SAM2 같은 미지원 모델이나 프라이버시 요구가 있으면 Inference Endpoints를 선택지로 둠. Spaces는 제품 경로에서 제외하고 개발 실험에만 씀.

## 3. 설계: 같은 포트 뒤의 로컬/클라우드

```
kinekino-core::studio::models/
  catalog/        ModelManifest (+ execution: Local | Cloud 선언)
  backend/mod.rs  trait InferenceBackend (포트)
  backend/local/  기존 worker 방식 어댑터 (VAD 등)
  backend/hf_router/   Inference Providers HTTP 어댑터
    request/  response/  transport/ (reqwest)
  backend/hf_endpoint/ (2차)
  selection/      BackendPolicy, 폴백
  guard/          CostGuard, OfflineGuard
  credentials/    TokenSource (keyring | env)
```

```rust
pub trait InferenceBackend: Send + Sync {
    fn descriptor(&self) -> BackendDescriptor;          // Local | HfRouter{provider} | HfEndpoint{url_id}
    fn supports(&self, task: &ModelTask, model: &ModelRef) -> Support; // 지원 여부와 이유
    fn estimate(&self, job: &InferenceJob) -> CostEstimate;  // 로컬은 0. 클라우드는 상한(USD, 바이트)
    fn run(&self, job: InferenceJob, ctl: &JobControl) -> Result<InferenceOutput, InferenceError>;
}
// JobControl: cancel 토큰, progress 콜백(청크 i/n), deadline. sdk_execution의 ExecutionBudget과 CancelDisposition에 매핑
```

- **ModelRef:** `repo_id + revision(40hex)`. 클라우드 쪽에서는 제공자가 실제로 어떤 revision을 서빙하는지 보장되지 않음(**미확인**). 그래서 provenance에 `served_revision: "provider_reported" | "unverifiable"`를 구분해서 남김. 로컬처럼 sha256로 고정할 수 없다는 점을 명시함.
- **선택 정책:** 기본은 `local_only`(ADR-006 유지)임. 사용자가 작업별로 `prefer_local`(로컬이 불가하면 승인 후 클라우드), `cloud`(명시적)를 고름. **자동 폴백으로 클라우드에 업로드하는 건 금지**하고, 폴백은 항상 승인 프롬프트를 거침. 클라우드에서 로컬로 가는 폴백은 자동 허용함.
- **취소, 재시도, 진행률:** 오디오와 영상은 VAD 구간 단위로 청크로 나눠서 청크마다 요청함. 진행률은 청크 기준임. 취소하면 남은 청크를 보내지 않음(이미 보낸 요청의 비용은 발생). 재시도는 429와 5xx만 지수 백오프로 최대 3회 함. 4xx(권한, gated)는 즉시 실패시킴. 청크 결과는 idempotency 키(job_id+chunk_idx)로 캐시해서 재개할 때 다시 내지 않음.
- **Provenance 확장:** ai_provenance와 제안 메타데이터에 `execution_site: local|cloud`, `backend`, `provider`, `endpoint_host`, `repo_id`, `requested_revision`, `served_revision_status`, `request_ids`, `started/finished(UTC)`, `estimated/billed_cost`, `input_sha256`(업로드한 청크), `bill_to`를 추가함. **토큰과 헤더는 기록하지 않음.**
- **오프라인과 비용 가드:** `OfflineGuard`(네트워크 금지 모드에서는 클라우드 백엔드 비활성화), `CostGuard`(작업별·월별 사용자 승인 한도 USD, 업로드 바이트 한도). 실행 전에 견적을 보여주고, 한도를 넘으면 실행 전에 중단함. 실측 비용은 HF 사용량 페이지와 대조해서 사후 기록함(개인 계정 API는 Enterprise 전용이라 수동 대조함).
- **사용자 승인 원칙 유지:** 클라우드 결과도 항상 `quality_approved=false`인 제안으로만 저장하고 수락은 사용자가 함. 라이선스는 `license_permission=not_verified`를 유지하고, gated 모델(RMBG-2.0)은 사용자 약관 동의가 필요함.

## 4. 토큰 보안 (Rust)
- **TokenSource 우선순위:** ① 환경변수 `KINEKINO_HF_TOKEN`(CI와 box용) ② OS 키체인(`keyring` 크레이트. Windows Credential Manager, macOS Keychain, Linux Secret Service). `HF_TOKEN`은 일부러 읽지 않음(다른 도구 토큰이 섞여 들어오는 걸 막음. 결정 질문 4 참고).
- CLI: `kinekino models auth set`(stdin에서 받고 echo하지 않음, 인자로 받는 것 금지), `auth status`(앞 4자와 권한 확인 결과만 표시), `auth clear`. 설정 파일에는 토큰을 저장하지 않음.
- **메모리:** `secrecy::SecretString`(또는 zeroize)로 감싸고, Debug와Display는 `hf_****`로 표시함. reqwest 헤더는 `HeaderValue::set_sensitive(true)`로 설정함.
- **로그 마스킹:** tracing 출력 계층에서 `hf_[A-Za-z0-9]{20,}` 패턴을 치환하고, 에러 본문을 기록하기 전에도 마스킹함. 산출물, provenance, 리포트에는 토큰 필드 자체를 두지 않음.
- **.gitignore:** `.env`, `*.token`, `runtime/`. xtask lint에 `hf_` 토큰 패턴 스캔을 추가하고, CI에서 gitleaks 또는 그에 준하는 스캔(Rust 자체 구현 가능)을 돌림.
- **최소 권한:** fine-grained 토큰에 "Make calls to Inference Providers"만 줌(gated 모델이면 해당 repo read 추가). 조직 과금이 필요하면 `X-HF-Bill-To: modootoday`를 씀.
- **의존성:** reqwest 0.12.28은 이미 있어서 추가 비용이 없음(라이선스 MIT/Apache). `keyring`(MIT/Apache, Linux에서는 D-Bus Secret Service 의존이라 box에 서비스가 없으면 env로 폴백), `secrecy`(MIT/Apache). 바이너리 증가는 작을 것으로 예상하지만 수치는 **미측정**임.

## 7. 미확인 목록
- Inference Providers 파일, 페이로드 업로드 크기 한계와 요청 타임아웃
- 제공자가 실제 서빙하는 모델 revision을 확인하는 방법(응답 헤더 등)
- 제공자별 데이터 보존, 학습 사용 정책
- 비동기, 큐 API 유무
- Inference Endpoints 단가, 콜드 스타트, 토큰 권한 범위
- ZeroGPU 쿼터 수치와 토큰 기준
- 공식 Rust 클라이언트 유무
- keyring, secrecy 추가 시 바이너리 크기 영향(미측정)
- Windows Credential Manager 실동작(나중에 build-host에서 검증)
