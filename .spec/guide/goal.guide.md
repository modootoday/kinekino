# 일시정지한 구현 goal 원문

상태: 사용자 요청으로 paused. 아래 과거 milestone 표현은 당시 지시 원문이며 현재 상태는 HANDOFF.md의 R250/R252/R253 구분을 우선한다. 이관 완료가 구현 goal 완료를 뜻하지 않는다.

현재 goal을 이어받아 중앙 PM으로 Source Player의 구현·자동 검증을 가능한 범위까지 무인으로 진행해주세요. 이 요청은 새 채팅 생성이나 별도 goal 중복 등록 지시가 아닙니다.

목표는 배포가 아니라 승인 설계의 실제 제품 구현입니다. 탐색·작품/회차·제공자 접근·광고차단·재생·자막·카드·숏폼·피사체 분할·자산 생성·투영 패키지·일괄 작업·AI 결과 검토를 공통 Rust SDK/application/domain과 CLI·GUI에 연결하세요. 최신 요구사항 추적표와 설계 정본을 대조하고, 명시적으로 후속 단계로 승인된 범위도 누락 없이 추적하세요.

최신 AGENTS.md와 담당별 결정·소유권·선택 소스·기존 WIP·원본 증거·첫 실패·미검증 범위를 유지하세요. source375와 후속 변경은 canonical 적용 전 private overlay로 구분하고, 과거 성공을 현재 입력이나 새 호스트 성공으로 계상하지 마세요. 다른 담당 소유권을 임의로 인수하거나 WIP를 덮어쓰지 마세요.

현재 실제 상태부터 재확인하세요. R145의 SDK·CLI 실제 검증/전체190/정상 bins와 R146의 source admission 합성4시험·strict/no-run/fmt·custody는 서로 다른 검증 범위입니다. 다음은 clock 기준 stream·duration 의미·관측 SHA와 tool pin 계약을 고정하고 실제 native source probe·encoder·숏폼 렌더를 원 Jobs에 연결하는 작업입니다. 합성 선언·카탈로그 등록·schema·컴파일 성공을 실제 기능 완료로 대체하지 마세요.

진행 원칙:
1. 요구사항마다 구현 위치·실제 검증 근거·남은 공백을 연결하고, 가장 중요한 미완료 제품 여정을 구현하세요. 완료된 경계의 반복 시험만으로 진행을 대체하지 마세요.
2. 모든 기능 정책과 새 테스트·개발 도구는 Rust로 구현하세요. 승인된 React/TSX UI 선언 예외와 단일책임·계층 분리를 유지하세요.
3. 공통 SDK·CLI의 기능별 정상·오류·취소·저장 인수를 GUI 기능 검증보다 먼저 완료하세요. GUI는 동일 typed SDK를 사용하는 표시·입력 계층으로 연결하고, 원본/후보 비교·재생·수정·명시 판정·이력을 구현하세요.
4. 필요한 최소 의존성은 기존 승인 범위에서 설치하고 버전·출처·라이선스·해시와 변경 이유를 기록하세요. 설치 승인을 보류 작업의 일괄 재개로 해석하지 마세요.
5. C-only NVMe 정책을 유지하세요. 빌드·증분 캐시·임시 파일은 runtime/build-cache 아래 native·meari-native·resource-runner·tmp 문맥으로 분리하세요. producer 독점과 무거운 작업 1개 중앙 배정을 유지하고 전역 Cargo/Rustup·다른 프로젝트는 변경하지 마세요.
6. 변경 전 preimage와 입력·lock/toolchain/font/tool/producer pin을 보존하세요. 변경에 맞는 fmt·type/no-run·strict·실제 기능 시험을 수행하고 통합 이정표에서 지정 전체190(Product145/Core18/Native26/OS1)과 정상 player/player-cli bins를 검증하세요. 사후 custody로 실제 입력 동일성을 확인하세요.
7. 실행 중인 프로세스는 원 handle로 종료를 확인하세요. 관측 timeout만으로 중단됐다고 판단하거나 중복 실행하지 마세요. 첫 실패를 보존한 뒤 원인을 수정하고 새 입력·로그로 재검증하세요.
8. WARP 설정 변경·추론·모델/미디어 다운로드·수동 GUI 시험·push는 명시적으로 해제되기 전까지 재개하지 마세요. commit·canonical 적용·배포도 이번 무인 진행의 완료 조건으로 추가하지 마세요.
9. 기존 승인으로 결정 가능한 구현 선택은 자율적으로 처리하세요. 실제로 필요한 사용자 결정만 근거·선택지·영향을 정리해 요청하고, 그동안 독립 가능한 작업은 계속하세요.
10. 매 단계 실제 결과와 남은 범위를 .spec/sots·.spec/plans에 기록하세요. 보고를 위한 반복 문서나 불필요한 전체 재시험을 늘리지 말고 구현과 검증에 집중하세요.

완료 판정:
전체 요구사항을 하나씩 현재 소스·실제 실행·산출물·회귀 결과와 대조하세요. CLI와 GUI 완성률은 명령 수나 빌드 성공률로 계산하지 말고 목표별 인수 항목을 기준으로 산정하세요.

AI 결과 품질 승인은 사용자만 할 수 있습니다. 시각 일치도 실제 실행과 기준 시안의 세부 대응 검토 없이 완료로 표시하지 마세요. 무인으로 구현·자동 검증 가능한 범위를 끝내고 사용자 검토에 필요한 GUI·실제 표본·비교 자료·실행 절차를 준비하세요. 남은 보류·수동 시각 검토·AI 사용자 승인을 구분한 최종 인수표와 검토 빌드를 제공하세요.

부분 구현이나 일부 시험 통과로 전체 goal을 완료 처리하지 마세요. 미완료 요구가 있으면 goal을 유지하고 계속 진행하며, 사용자 조치 없이는 더 진행할 수 없는 경우에만 구체적인 차단 근거와 준비된 검토 결과를 보고하세요.
