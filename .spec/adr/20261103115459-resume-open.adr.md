# 이어보기 열기 경로 연결

## Context

adr:kinekino/20261103035240(M1-5)은 이어보기 저장 형식, 키 규칙(`ResumeKey`), 정책(`ResumePolicy`)을 정했지만 플레이어는 아직 저장소를 쓰지 않는다. 로드맵 plan:kinekino/20261031153240의 M1-6(PL-7)은 이것을 플레이어 열기 경로에 잇는 조각이다. 플레이어 컨트롤러(`kinekino-player-ui::controller`)는 엔진을 비동기로 연다(adr:kinekino/20261102075636). 열기 요청 시점에는 새 파일의 길이를 모르고, 열기가 끝난 뒤에야 엔진에서 길이를 읽을 수 있다. 정해야 할 것은 언제 복원하고 언제 저장하는지, 컨트롤러가 저장소를 어떻게 받는지, 저장소가 실패하면 어떻게 하는지, 사용자에게 무엇을 보여 주는지다.

## Decision

1. **주입.** 컨트롤러는 `ResumeStore` 포트만 안다. `Controller::with_resume(Box<dyn ResumeStore>)`로 받고, 정책은 `ResumePolicy::default()`다. 저장소가 없으면 이어보기를 하지 않는다. `FileResumeStore`와 `default_resume_file` 조립은 진입점(`kinekino watch`)이 한다. `--smoke` 실행은 저장소를 붙이지 않는다. 시험 실행이 사용자의 위치를 지우거나 바꾸면 안 되기 때문이다.
2. **키.** 로컬 파일 항목만 `ResumeKey::for_source`로 키를 만든다. 작업 디렉터리 기준 상대 경로(`kinekino watch movie.mkv`)는 먼저 절대 경로로 바꾼다. 열기가 끝난 항목의 키를 기억해 두고 저장할 때 쓴다. 플러그인 항목과 원격 URL은 키가 없으므로(None) 저장소를 조회하지도, 쓰지도 않는다.
3. **복원 시점.** 비동기 열기가 끝난 뒤(엔진이 첫 프레임을 알린 뒤) 엔진에서 길이를 읽고 `ResumePolicy::start(saved, 새 길이)`로 다시 검증한다. 시작점이 0보다 크면 `seek <초> absolute`를 보내고 화면 위치를 맞춘다. mpv의 시크는 비동기라 엔진이 한동안 옛 위치(0 근처)를 알릴 수 있으므로, 엔진 위치가 복원 지점 10초 안에 들어오거나 사용자가 시크하기 전까지는 어떤 저장도 하지 않고 기존 항목을 둔다. 엔진이 길이를 알려 주지 않으면 저장된 길이로 검증한다. `begin_load`의 시작 위치 인자로 넘기지 않는 이유는 그 시점에 새 길이를 몰라 재검증을 할 수 없기 때문이다.
4. **저장 시점.** 현재 항목이 열려 있고(열기 진행 중이 아님) 키가 있을 때만 저장한다. 저장 시점은 다음과 같다.
   - 재생 중 `poll`: 재생 위치가 마지막 저장 위치에서 10초 이상 움직였을 때. 벽시계가 아니라 미디어 시간 기준이라 시험에서 결정적이다.
   - 일시정지 명령.
   - 항목 전환(다음·이전·목록 선택·자동 다음) 직전, 바뀌기 전 항목에 대해.
   - 창 닫기 명령, 그리고 창 실행이 끝날 때(창 관리자가 닫은 경우 포함).
   - eof: 끝까지 재생했으므로 항목을 지운다.
   저장 값은 `ResumePolicy::record`가 정한다. 처음 10초 미만이나 끝 근처(남은 60초 이하, 95% 이상)면 항목을 지운다. 길이를 아직 모르면(0) 판단할 수 없으므로 쓰지도 지우지도 않고 기존 항목을 둔다. 마지막으로 쓴 위치와 같으면 다시 쓰지 않는다(닫기 명령과 창 실행 종료가 겹치는 경우). eof로 지운 뒤에는 시크나 처음으로 되감기 전까지 저장하지 않아, 자동 다음이 끝난 항목을 다시 쓰지 않는다.
   진입점은 기존 환경 스냅샷에 `XDG_STATE_HOME`과 `LOCALAPPDATA`를 더해 저장 위치 규칙(adr:kinekino/20261103035240 2번)을 그대로 따른다.
5. **실패.** 저장소 오류는 열기, 재생, 닫기를 막지 않는다. 컨트롤러는 오류를 삼키고, 창 실행 동안 한 번만 표준 오류에 오류 코드만 담은 경고를 남긴다. 미디어 경로, 키, 저장소 파일 경로는 출력하지 않는다.
6. **표시.** 위치를 복원하면 기존 알림 줄(토스트)에 "이어서 재생 m:ss"를 잠깐 보여 준다. 처음부터 시작하지 않은 이유를 사용자가 알 수 있게 하기 위해서다. 새 UI 요소는 만들지 않는다.

## Rationale

- 포트만 주입: 컨트롤러 시험은 메모리 저장소로 돌고, 파일 경로와 환경 해석은 진입점 한 곳에 모인다. 계층 규칙(application은 포트, 조립은 진입점)과도 맞다.
- 미디어 시간 간격: 벽시계 간격은 일시정지 중에도 쓰기를 만들고, 시험에서 시간을 기다려야 한다. 위치 차이 기준이면 재생한 만큼만 쓴다. 10초면 갑작스러운 종료에서 잃는 위치가 짧고, 파일 쓰기는 많아야 10초 재생에 한 번이다.
- 닫기를 두 군데서 저장: 앱 안의 닫기 버튼은 명령으로, 창 관리자 닫기는 창 실행 종료로 들어온다. 둘 중 하나만 처리하면 다른 경로에서 위치를 잃는다.
- 기각한 대안: (a) 컨트롤러가 `FileResumeStore`를 직접 만드는 방식. 시험이 실제 파일 시스템과 환경에 묶인다. (b) 기존 `ResumingPlayback`(core)으로 감싸는 방식. 이 타입은 동기 `PlaybackBackend`를 가정해 비동기 열기와 길이 재검증 시점에 맞지 않는다. (c) 저장 실패 시 토스트로 알리는 방식. 디스크 문제처럼 사용자가 재생 중에 고칠 수 없는 일을 반복해서 알리게 된다. (d) 열기 요청 때 저장 위치를 `begin_load`에 넘기는 방식. 새 길이로 재검증할 수 없다.

## Consequences

- 로컬 파일을 다시 열면 3초 앞에서 이어 재생하고, 끝까지 보거나 처음 몇 초만 본 파일은 기록이 남지 않는다.
- 저장소가 고장 나도 재생은 그대로다. 대신 위치가 저장되지 않았다는 사실은 표준 오류의 경고 한 줄로만 드러난다.
- 같은 파일을 여러 창에서 동시에 재생하면 마지막에 저장한 창의 위치가 남는다(adr:kinekino/20261103035240의 잠금 범위 밖 결정을 따른다).
- 복원 시크가 엔진에서 조용히 실패해 처음부터 재생되면, 위치가 복원 지점 10초 앞에 닿기 전까지 그 항목은 저장되지 않는다(기존 항목은 남는다). 실제 mpv에서 시크 반영 시점의 관측은 아직 없다(미검증).
- 알림 문구 "이어서 재생"은 기존 토스트를 쓰지만 실제 GUI에서의 사용자 확인이 필요하다.
- 남은 일: 플러그인 항목 키(안정 항목 ID), 이어보기 끄기 설정과 "처음부터 보기" 선택(M1-7 환경설정과 함께), 여러 창 동시 쓰기.

## Reversal conditions

- 엔진이 열기 요청 전에 길이를 알려 줄 수 있게 되면 복원을 `begin_load` 시작 위치로 옮기는 것을 다시 검토한다.
- 사용자 GUI 검토에서 복원 알림이 방해된다고 판단되면 6번을 뺀다.
- 갑작스러운 종료에서 잃는 위치가 문제로 보고되면 저장 간격(10초)을 다시 정한다.
