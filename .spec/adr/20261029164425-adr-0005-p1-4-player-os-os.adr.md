# ADR 0005: P1 4단계 — player OS 분기의 포트화(중앙 포트·OS별 구현·팩토리)

## Context
- P1 4단계(plan:kinekino/20261029151512). 3단계(ADR 0004, adr:kinekino/20261029163426) 이후 adapter 밖 OS `cfg`가 R-cfg 99건 allowlist에 남아 있다. player `src` 29건, 테스트 약 49건, 그 외 크레이트가 나머지다.
- 사용자 원칙(2026-10-30 KST): 단순 이동이 아니라 Cross-OS 설계여야 한다. 중앙 인터페이스(core 포트)가 반드시 있어야 하고, OS별로 갈라야 하는 것은 OS별 어댑터·모듈로 나누고 팩토리로 선택한다. Windows 전용 통합 테스트는 어댑터 쪽으로 옮긴다. lint 완화와 런타임 스킵은 하지 않는다.
- 관측(Linux, 2026-10-30 KST): `infrastructure/mod.rs`의 Windows 게이트를 모두 풀면 182개 해석 오류가 난다. 원인은 `std::os::windows`, `windows`/`wry`/`webview2_com` 크레이트, `kinekino_process::infrastructure::windows`, 명명 파이프 등 Win32 API를 직접 쓰는 코드가 약 35개 모듈에 퍼져 있기 때문이다.

## Decision
1. **공통 구조**: OS 분기는 세 층으로 나눈다.
   - (a) `kinekino-core`의 포트 트레이트·능력표
   - (b) `kinekino-platform-{windows,unix}`(필요하면 `-macos`)의 OS별 구현
   - (c) `kinekino-platform`의 단일 `cfg` 선택(팩토리)과 `install()` 등록
   domain 크레이트는 `infrastructure::os_policy`(설치된 포트 호출부)만 거쳐 OS를 묻는다. 단위 테스트는 `CurrentOs`를 명시 주입한다.
2. **묶음 A, 실행 능력**:
   - `PlatformHost::has_native_desktop_window()`를 추가했다. Windows 어댑터는 true, Unix는 false를 돌려준다.
   - `OsPolicy::host() -> &dyn PlatformHost`를 추가했다. `kinekino-platform`의 `const HOST`가 빌드 OS 구현을 고른다.
   - player의 `cfg!(all(windows, feature = "native-proposal-window"))` 5곳은 `os_policy::native_proposal_window_available()`로 바꿨다. 이 함수는 feature `cfg!`(빌드 구성)와 OS 능력(런타임 포트)의 AND다.
   - 기능이 없을 때 테스트는 건너뛰지 않고 실제 거부 코드(`Unsupported`/`InvalidArgument`)를 검증한다.
   - 카드 export 테스트의 OS별 절대경로는 `temp_dir()` 기반 OS 중립 경로로 바꿨다.
3. **묶음 B, 파일·식별자 포트**:
   - `OsPolicy`에 네 연산을 추가했다.
     - `file_identity_128`: Windows `FILE_ID_INFO`, Unix dev+inode.
     - `is_local_fixed_path`: Windows 드라이브 문자 접두사, Unix 절대경로.
     - `try_lock_exclusive`: Windows는 배타 share mode로 이미 충족되므로 no-op, Unix는 `flock` 계열 `File::try_lock`.
     - `fresh_guid`: Windows `CoCreateGuid`(표시 순서 바이트), Unix `/dev/urandom`.
   - 구현은 `kinekino-platform-{windows,unix}`의 `fs`·`id`에 두었다.
   - player 모듈 5개를 포트 위에 다시 써서 OS 게이트를 해제했다: `immutable_storage_paths`, `storage_directory_identity`, `skip_session_identity`, `review_host_identity`, `content_digest`.
   - `proposals::output_review_ids`도 포트로 바꿨다. 상위 `proposals`가 아직 게이트 안에 있다.
   - SHA-256은 OS 기능이 아닌 알고리즘이라 BCrypt 대신 OS 중립 `sha2`를 쓴다.
   - 식별자 문자열 형식은 이전과 같다: 32자리 소문자 hex, 출력 결정 ID는 `output-` 접두사.
4. **묶음 C, 게시·공유 포트와 OS 중립 모듈 게이트 해제**:
   - `OsPolicy`에 넷을 더했다.
     - `create_publication_stage`: Windows는 `GENERIC_WRITE|DELETE`, 읽기 공유, 재분석 지점 비추종. Unix는 `O_NOFOLLOW`.
     - `rename_no_replace`: Windows는 `FILE_RENAME_INFO` 핸들 rename. Unix는 `link(2)` 뒤 원래 이름 제거.
     - `create_transient_lock`: Windows는 배타·삭제 시 닫힘. Unix는 지속 파일과 `flock`. 점유 중이면 `AlreadyExists`.
     - `normalize_local_path`: Windows는 verbatim disk 접두사 제거, UNC 거부. Unix는 절대경로.
   - `PlatformHost::has_mandatory_share_modes()`를 추가했다. Windows는 true, Unix는 false.
   - 플레이어의 `OpenOptionsPolicy`(`share`, `flags`) 빌더 확장과 `NO_FOLLOW`, `NO_FOLLOW_DIRECTORY` 상수로 `std::os::windows` 사용을 걷어냈다. 대상: projects, card_projects, proposals, model_review, asset_build_jobs, job_batches, native_immutable_publication, jobs.
   - 이 묶음에서 OS 게이트를 해제한 모듈: asset_build_jobs, asset_inputs, asset_projects, asset_source_archives, card_projects, catalog, clip_presets, clip_projects, clip_working_file, fonts, historical_evidence, job_batches, jobs, model_catalog, model_review, native_immutable_publication, native_proposal_request, projects, proposals, review_startup_settings, snapshot_export, speaker_annotation_files.
   - 테스트 규칙:
     - 쓰기 배제·디렉터리 rename 거부처럼 share mode에 기대는 단언은 `has_mandatory_share_modes()`와 같은지 비교한다. 두 OS 모두 실제로 단언하며 건너뛰지 않는다.
     - Windows 경로 접두사 사례는 `platform-windows`의 `normalize_local_path` 테스트로 옮겼다.
     - Win32 share mode와 junction fixture가 필요한 native proposal request 테스트 2개는 `kinekino-host/tests/windows_native_proposal_request.rs`로 옮겼다.
   - 남은 게이트 모듈과 그 원인:
     - `kinekino_process::infrastructure::windows`(Job Object 프로세스 패밀리)와 frame_capture `tools`/`process::owned`에 의존: clip_*, review_runtime, review_playback_sessions, timeline_evidence.
     - Windows 전용 `kinekino_vad_executor` 항목에 의존: vad_*, review_source.
     - mpv, local_host(named pipe), browser 계열, video_surface, window_*, webview_audio, 대화상자 picker.
     - Linux에서 비어 있는 `meari-native`에 의존: meari, clip_subtitle_*, card_*.
5. 이후 묶음(Win32 API 의존 모듈)은 모듈 군별 포트를 core에 정의하고, 구현을 OS별 어댑터 크레이트로 옮긴 뒤 같은 팩토리로 등록한다. 묶음마다 이 ADR에 추가한다.

## Consequences
- 묶음 A: R-cfg 6건 해소(allowlist 439 → 433).
- 묶음 B: allowlist 변화 0. 파일 단위 집계라 `infrastructure/mod.rs` 한 항목이 남는다. 게이트 해제 모듈 5개와 그 단위 테스트는 Linux에서도 컴파일·실행된다.
- Unix의 불변 저장소 writer 잠금은 권고 잠금(flock)이다. Windows의 배타 share mode와 달리, 잠금을 따르지 않는 외부 프로세스는 막지 못한다.
- 묶음 C: allowlist 변화 0. `infrastructure/mod.rs`의 남은 게이트 때문이다.
- 묶음 C: Linux에서 실행되는 player lib 테스트가 560개에서 655개로 늘었다.
- Unix `rename_no_replace`는 link+unlink 두 단계다. 둘 사이에 중단되면 staging 이름이 남을 수 있다. 기존 정책도 실패한 staging 파일은 검사용으로 남긴다.
- Windows에서 `has_native_desktop_window` = true인 경로는 컴파일 게이트 안 변경이며 Windows에서 검증하지 않았다.
