# 플레이어 창 조작: ⋮ 메뉴, Esc 우선순위, 대화상자 없음 안내, dev 의존성 최적화

## Context

[Meari 플레이어 창](20261031020000-player-window-meari-libmpv.adr.md) 이후 실제 데스크탑 확인에서 다음이 나왔다. 장식 없는 창을 옮기거나 크기를 바꿀 방법이 없었다. 파일 열기·회차·전체화면이 한 곳에 모여 있지 않았다. 파일 대화상자를 띄울 수 없는 데스크탑에서는 아무 반응이 없었다. debug 빌드의 전체화면에서는 포인터를 움직여도 컨트롤이 약 2초 늦게 나왔다. 측정해 보니 최적화하지 않은 의존성(Meari 렌더)의 프레임 하나가 약 1.1초 걸려 이벤트 루프를 막았고, 병합 전 main에서도 같았다. 전체화면에서 ⋮ 메뉴를 연 채 Esc를 누르면 메뉴와 전체화면이 함께 닫혔다.

## Decision

- 앱 제목 줄을 창 제목 줄로 쓴다(끌기 이동, 두 번 눌러 최대화). 가장자리 띠로 크기를 바꾼다.
- 전송 막대에 ⋮ 메뉴를 두고 파일 열기·회차 목록·전체화면을 모은다.
- Esc는 열린 레이어부터 닫는다. 메뉴가 열려 있으면 메뉴만 닫고, 그다음 Esc가 전체화면을 끝낸다.
- 400ms보다 빨리 돌아온 빈 대화상자 결과는 "대화상자 없음"으로 본다. 시작 화면은 상태 줄, 재생 중은 4초 하단 토스트로 안내한다.
- 작업 공간 `[profile.dev.package."*"]`에 `opt-level = 2`를 둔다. 의존성만 최적화해 자체 코드의 디버깅은 유지한다.

## Consequences

- 전체화면 프레임 시간이 약 1.1초에서 40~190ms로 줄어, 포인터 이동 후 0.1~0.19초 안에 컨트롤이 보인다(xdotool 측정).
- 의존성 첫 빌드가 길어진다(`-j 1`에서 약 20분).
- 렌더 비용 자체는 소프트웨어 래스터라 남아 있다. GPU 경로는 후속 과제다.
