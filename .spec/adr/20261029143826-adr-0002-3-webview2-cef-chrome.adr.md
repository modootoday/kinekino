# ADR 0002: 3엔진 브라우저 포트 (WebView2 + CEF + 시스템 Chrome), 능력표 기반 선택

## Context
- 사용자 결정(2026-10-29 KST): 메인 언어는 무조건 Rust. 브라우저 엔진은 `BrowserEngine` 포트 아래 WebView2 + CEF + 설치된 Chrome 세 어댑터로 지원한다. Windows는 구현만 하고 검증은 마지막에 한다.
- 근거: ADR 0001(adr:kinekino/20261029135636, 이 문서가 supersede), 박스 임베드 스파이크 S1/S2(`spike/embed` 3097585, 보고서 /workspace/kinekino-embed-spike-report.md, 리서치 /workspace/kinekino-chromium-embed-research.md).
- 관측(Linux/X11, 박스): S1 설치된 Chrome 156을 x11rb로 재부모화 → 임베드·리사이즈·포커스·마우스(32px 보정)·키 입력·H.264(MSE)·Widevine 통과. S2 공식 CEF 156 X11 자식 창 → 임베드·VP9·Widevine(VP9, CDM 자동 다운로드 후) 통과, H.264/AAC 불가(공식 빌드 proprietary_codecs off).
- ADR 0001의 "Chrome+CDP 기본, 임베드 불가" 결정은 S1/S2로 임베드가 가능해져 대체된다.

## Decision
1. **포트**: `kinekino-browser/src/engine/port/`의 `BrowserEngine`이 유일한 의존 표면이다. 모든 어댑터는 `capabilities()`로 능력표(`CapabilitySet`)를 선언한다. 선언한 능력은 동작해야 하고, 선언하지 않은 API 능력은 `EngineError::Unsupported`(또는 `audio()`/`frame_capture()`가 `None`)를 돌려준다.
2. **능력(Capability)**: 미디어 `H264`, `Aac`, `Vp9`, `Widevine` / API `Eval`, `ScriptInjection`, `RequestInterception`, `FrameCapture`, `AudioMute` / 창 `WindowEmbed`.
3. **엔진(EngineKind)과 선언 능력표(어댑터 구현 기준, 엔진 잠재력 아님)**

| 능력 | WebView2 (Windows) | CEF 공식 빌드 | 설치된 Chrome 임베드 | Chrome CDP (헤드리스/별도 창) |
|---|---|---|---|---|
| H264 / Aac | O | X (공식 빌드) | O (측정) | O (측정) |
| Vp9 | O | O (측정) | O | O |
| Widevine | O | O (VP9, 런타임 CDM 다운로드, L3 추정) | O (측정) | O (측정) |
| Eval | X (반환값 경로 미이관) | O (console 채널) | O (CDP) | O |
| ScriptInjection | X (빌드 시점 설정) | X (후속: render process OnContextCreated) | O (CDP) | O |
| RequestInterception | X (player 쪽에 잔류) | X (후속: ResourceRequestHandler) | O (CDP Fetch) | O |
| FrameCapture | X | X (windowed; 후속 OSR) | O (CDP) | O |
| AudioMute | X | O (`SetAudioMuted`) | O (JS 미디어 요소) | O (JS) |
| WindowEmbed | O (자식 HWND) | O (X11 부모 XID / HWND) | O (X11 재부모화, `--app`) | X |

4. **플랫폼 매트릭스 (공식 지원 = 기본 1 + 대체 1)**

| 플랫폼 | 기본 | 대체 | 비고 |
|---|---|---|---|
| Windows | WebView2 | CEF | 구현만, 검증 보류(가장 마지막) |
| Linux(X11) | CEF | 설치된 Chrome 임베드 | H.264 필요 사이트는 대체로 |
| 그 외(macOS·Wayland 네이티브) | 없음 | 없음 | 범위 밖 |

Chrome CDP 헤드리스 엔진은 GUI 매트릭스 밖의 CLI/검증 엔진이며, CDP는 설치된 Chrome 임베드 어댑터의 **제어 채널**로 재사용한다(창 제어는 x11rb, 페이지 제어는 CDP).
5. **선택 로직** (`engine/select/`): 앱은 요구 능력표를 넘기고, 선택기는 플랫폼의 기본 → 대체 순으로 "설치됨 && 요구 능력 포함"인 첫 엔진을 고른다. 없으면 부족한 능력 목록과 함께 오류. 설치 여부: CEF=`KINEKINO_CEF_DIR`의 `libcef` 존재 + `cef` feature, Chrome=`KINEKINO_CHROME_PATH`(기본 /usr/bin/google-chrome) 존재, WebView2=cfg(windows)+`webview2` feature.
6. **공통 계약 테스트** (`engine/contract/`): 로컬 fixture(외부 사이트 없음)로 내비게이션·이벤트, 선언된 능력의 동작, 미선언 능력의 `Unsupported`를 검사한다. 가짜 엔진은 항상, Chrome CDP는 Chrome이 있으면, 임베드·CEF는 DISPLAY가 필요해 `--ignored`/예제로 돈다.
7. **CEF 배포**: 바이너리는 저장소에 커밋하지 않는다. 빌드는 `CEF_PATH`, 실행은 `KINEKINO_CEF_DIR`(기본 없음)로 SDK를 가리킨다. Widevine CDM은 번들 금지, CEF component updater의 런타임 다운로드만 사용한다.
8. **비 Rust 범위**: 제품 코드는 전부 Rust. 비 Rust 바이너리 의존은 CEF(libcef, C/C++ BSD-3), 설치된 Google Chrome(외부 프로그램), WebView2 런타임(OS 제공), Widevine CDM(런타임 다운로드)로 한정한다.

## Consequences
- 지원 조합이 플랫폼당 2개로 고정되어 테스트 비용이 3배가 되지 않는다. 엔진 추가는 어댑터 + 능력표 + 계약 통과로 끝난다.
- Linux 기본 CEF는 H.264/AAC가 없으므로 H.264 필요 사이트는 능력표 요구(`H264`)로 자동으로 Chrome 임베드로 간다.
- WebView2·Windows CEF 코드는 cfg/feature 게이팅으로 Linux 빌드를 깨지 않지만 **Windows에서 컴파일·실행 검증하지 않았다**.

## 미결·미검증
- 한글 IME: 박스에 ibus/fcitx 없음 → CEF·Chrome 임베드 모두 미검증.
- Wayland: X11/XWayland만 대상. 네이티브 Wayland 임베드 미지원(OSR 후보).
- VMP: CEF는 VMP 서명이 없어 Widevine L3에 머물고 일부 서비스가 거부할 수 있음(미측정).
- CDM 라이선스: Google 독점, 재배포 금지 → 번들 금지, 런타임 다운로드. 약관 검토는 사용자/법무 결정.
- CEF 샌드박스: 현재 `no_sandbox`. chrome-sandbox setuid 배포는 후속.
- Windows: WebView2·CEF 어댑터 구현만, 컴파일·실행·검증 보류.
- CEF 미구현 능력(주입·가로채기·캡처)과 S2 리사이즈/입력 정량 측정은 후속.

## 구현 노트 (2026-10-29)
- 모듈: `crates/kinekino-browser/src/engine/` — `port/{capability,kind}.rs`(능력표), `select/`(플랫폼·역할별 선택, `KINEKINO_CEF_DIR`·`KINEKINO_CHROME_PATH` 가용성), `contract/`(공통 계약 스위트), `embed/x11.rs`(x11rb 리페어런트), `chromium/{cdp,chrome_embed,cef}/`, `webview2/`(cfg windows).
- CDP 관계: CDP는 설치 Chrome 임베드의 제어 채널이자 CLI/headless 엔진(`ChromeCdp`). `--app` 창은 `fetch_targets`→`get_page`로 기존 타깃에 붙고, 주입 스크립트를 위해 `Page.enable`을 명시 전송, 붙은 타깃에선 `Page.navigate`가 응답하지 않아 JS `location.href`+폴링으로 이동.
- chromiumoxide `arg()`는 `--`를 자동으로 붙인다(`"--app=…"`은 무시됨). `--app`은 `about:` URL을 받지 않아 `data:` URL로 연다.
- 데모: `cargo xtask demo-engine <chrome|cef> [--hold]`. 계약 결과 — Chrome 임베드: 10개 능력 전부 Pass. CEF(156.0.14): 선언 능력(vp9, widevine, eval, audio-mute, window-embed) Pass, 주입·가로채기·캡처는 NotDeclared.
