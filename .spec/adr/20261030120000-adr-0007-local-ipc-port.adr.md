# ADR 0007: 로컬 IPC 중앙 포트

## Context
- player `local_host`(서버·클라이언트·보안)와 mpv JSON IPC가 tokio `named_pipe`와 Win32 토큰 API에 직접 묶여 `cfg(windows)` 게이트 뒤에 있었다.
- 사용자 원칙: Cross-OS, 중앙 인터페이스 필수, OS별 분리. 기술 선택은 업계 표준과 리서치 근거.

## Decision
1. **포트**: `kinekino_core::platform::ipc` — `IpcTransport`(`OsPolicy::ipc()`), `IpcListener`, `IpcStream`(tokio `AsyncRead`/`AsyncWrite`). 객체 안전(dyn)으로 두어 도메인 크레이트가 OsPolicy만 거치게 한다.
2. **엔드포인트 ID는 OS 중립**: `EndpointId{product, pid, start, nonce}`, 정규 이름 `<product>.v1.<pid>.<start:016x>.<nonce:032x>`. 주소는 어댑터가 정한다.
   - Windows: `\\.\pipe\<name>`.
   - Unix: `$XDG_RUNTIME_DIR/<product>-ipc/<nonce>.sock`(sun_path 한도 104바이트 때문에 nonce만; pid·start는 커널 피어로 검증)(디렉터리 0700, 소유자 확인). `XDG_RUNTIME_DIR`이 없거나 소유자·모드가 맞지 않으면 실패한다(`/tmp` 폴백 없음 — 공유 디렉터리 경합 회피).
3. **피어 신원은 OS에서만**: Windows는 기존 방식(`GetNamedPipe*ProcessId`, `GetProcessTimes`, 토큰 SID·무결성·UAC, 메시지마다 클라이언트 가장). Unix는 `SO_PEERCRED`(uid·pid) + `/proc/<pid>/stat` 22번째 필드(starttime). Linux 외 Unix는 미검증으로 `process_start`가 `Unsupported`.
4. **`permits`는 어댑터 정책**: Windows는 같은 SID·같은 무결성·UAC 동일, Unix는 같은 uid이며 root가 아닌 쪽이 root 피어와 대화하지 않는다(특권 중개 방지).
5. **mpv**: 같은 포트의 `connect_address`(원시 주소)를 쓴다.
6. **선택**: `kinekino-platform::CurrentOs::ipc()`가 cfg로 어댑터를 고른다. 어댑터가 들어오기 전까지는 `UnsupportedIpc`.

## 능력표
| 능력 | Windows | Unix(Linux) |
| --- | --- | --- |
| local_only | 예(`reject_remote_clients`) | 예(AF_UNIX) |
| owner_only_acl | 예(SDDL `D:P(A;;GA;;;<sid>)`) | 예(0700 디렉터리 + 소켓 0600) |
| message_peer | PerMessage(가장 토큰) | ConnectionBound(`SO_PEERCRED`는 connect 시점 고정) |
| raw_client | 예 | 예 |

## 위협 모델 차이
- 같은 사용자의 다른 프로세스는 두 OS 모두 신뢰 경계 안이다(같은 principal). 경계는 다른 사용자·원격·특권 차이.
- Unix에는 무결성 수준이 없다. tier는 0으로 고정하고, Windows의 낮은 무결성 샌드박스 거부에 해당하는 보장은 없다(능력표에 기록).
- `SO_PEERCRED`는 connect 시점 신원이다. 연결 후 setuid로 바뀐 프로세스는 감지하지 못하며, fd 전달로 다른 프로세스가 소켓을 넘겨받을 수 있다. 같은 uid 안의 일이므로 허용 위험으로 둔다.
- PID 재사용은 두 OS 모두 start 스탬프 비교로 막는다.
- 소켓 파일 경로 경합은 0700 디렉터리 소유자 검사와 `bind` 실패(이미 존재) 시 중단으로 막는다. 이전 실행이 남긴 소켓은 이름에 pid·start·nonce가 있어 충돌하지 않는다.

## Consequences
- 보안 테스트: Unix 어댑터는 다른 uid 피어 거부, root 피어 거부, 0700 디렉터리 검사, 이름 형식 거부를 테스트한다.
- 실제 Windows 실행 검증은 이 환경에서 불가하다(Windows 타깃 clippy만). 보고에 명시한다.

## 후속: Windows 어댑터(P2-3)
- `kinekino-platform-windows::ipc::WindowsIpc`로 SDDL·`reject_remote_clients`·토큰 조회·가장 코드를 옮겼다. `permits`는 기존 `permits_peer`와 같은 규칙(정상 무결성 RID, UAC 유형 일관성, 전체 동일)이다.
- 수락 방식은 tokio 문서의 표준 패턴으로 바꿨다: `accept`가 연결되면 곧바로 다음 인스턴스를 만들고(최대 2) 연결된 인스턴스를 넘긴다. 이름은 항상 소유된다. 기존 구현은 세션이 끝난 뒤 다음 인스턴스를 만들었으므로, 세션 중 두 번째 클라이언트가 `ERROR_PIPE_BUSY` 대신 대기 인스턴스에 연결될 수 있다(서버가 한 번에 한 세션만 처리하는 것은 같다).
- 가장 복원 실패(`RevertToSelf`)는 `IpcFailure::fatal`로 알린다. 호스트는 이를 받으면 멈춘다.
- 스레드 가장 상태 검사는 포트의 `ensure_thread_identity`(Unix는 항상 Ok)다.
- 검증 한계: Windows 타깃 clippy만 통과했다. 실제 Windows에서 테스트를 실행하지 못했다.

## 후속: local_host 이전(P2-4)

- `local_host`는 `#[cfg(windows)]` 게이트를 벗고 `os_policy::ipc()` 포트만 사용한다. player의 `peer_token`, `domain::local_peer`(PeerSecurity/permits_peer)는 삭제했고 정책은 어댑터 `permits`가 단일 원천이다.
- 공개 엔드포인트 문자열의 `pipe:` 접두사는 레거시 공개 계약으로 유지한다. 실제 주소는 어댑터가 `EndpointId`에서 도출한다.
- `ERROR_PIPE_BUSY`(231)는 Windows 어댑터가 `io::ErrorKind::WouldBlock`으로 매핑하고 클라이언트는 그 kind로 재시도한다.
- Unix 어댑터는 `com.kinekino.player`처럼 점을 포함한 제품 id를 허용한다(선행 점, `/`, 빈 이름은 거부).
- 서버 pid 조회의 연결 해제 실패(233) 테스트는 Windows 의미론이므로 `cfg(windows)`로 남긴다. 나머지 local_host 테스트 29개는 Linux에서 실제 소켓으로 실행된다.
- peer_token 테스트는 platform-windows `ipc/token/tests.rs`로 이동했다(Windows clippy만 검증).

## 후속: mpv 이전(P2-5)

- mpv `--input-ipc-server` 주소는 `ipc().address(fresh_endpoint("source-mpv"|"source-review"))`로 만든다(Windows named pipe, Unix 소유자 전용 런타임 디렉터리 소켓). mpv 제어·캡처 연결은 `ipc().connect_address`를 쓴다. mpv 모듈 게이트 제거는 배치 3.
