# 이어보기 저장 형식

## Context

`kinekino-core::playback`에는 이미 `ResumeStore` 포트, `ResumePolicy`, `ResumingPlayback`과 JSON 어댑터 `FileResumeStore`가 있다. 지금 파일은 버전 없는 `{key:[pos,dur]}` 형식이고, 저장 위치와 키 규칙이 정해지지 않았으며, 손상 파일은 오류로 거절된다. 이 ADR은 로드맵 plan:kinekino/20261031153240의 M1-5(PL-7)로, 이어보기를 실제로 쓸 수 있게 하는 첫 조각인 저장 형식만 정한다. 이어보기 전체 계약(CAS·revision·SDK 표면)은 sot:kinekino/viewing-preferences-and-resume에 있고, 이 ADR은 그것을 구현하지 않는다. 열기 경로 연결(M1-6)과 환경설정 영속(M1-7)은 범위 밖이다.

## Decision

1. **위치.** `kinekino-core::playback`에 둔다. domain은 `resume.rs`(ResumePoint·ResumePolicy), application은 `store.rs`(ResumeStore 포트, 메모리 구현, 계약 검사), infrastructure는 `resume_file/`(`mod.rs` 저장소, `format.rs` 문서 형식·정리, `location.rs` 기본 경로)이다. `resume_key.rs`(키 정규화)는 domain이 아니라 경계 도우미다. 심볼릭 링크를 풀려고 파일 시스템을 읽으므로(canonicalize) 순수 정책이 아니며, 소스 문자열이 들어오는 경계에서 한 번만 부른다.
2. **저장 위치.** `KINEKINO_RESUME_FILE`이 있으면 그 경로를 쓴다. 없으면 `$XDG_STATE_HOME/kinekino/resume.json`, `$HOME/.local/state/kinekino/resume.json`, `%LOCALAPPDATA%\kinekino\resume.json` 순으로 찾는다. 경로 해석은 환경 조회 함수를 인자로 받는 순수 함수다.
3. **키.** 로컬 파일만 저장한다. 절대 경로나 로컬 `file://` URL(호스트가 없거나 `localhost`)은 `file:` 뒤에 정규화한 절대 경로를 붙여 키로 쓴다. 파일이 있으면 canonicalize로 심볼릭 링크를 풀고, 없으면 `.`·`..`를 문자열 규칙으로 정리한다. 상대 경로, 빈 문자열, `localhost` 외의 호스트가 있는 `file://` URL(네트워크 공유는 로컬이 아니다), `http(s)://` 같은 원격 URL, 그 밖의 스킴은 키를 만들지 않으며(None) 저장·조회도 하지 않는다. 키의 Debug 출력은 경로를 가린다.
4. **값(JSON v1).** `{"version":1,"entries":{"<key>":{"position_ms":u64,"duration_ms":u64,"updated_at_ms":u64}}}`. 위치와 길이는 초 단위 값이지만 밀리초 정수로 저장한다. 메모리 값은 기존 마이크로초 `ResumePoint`이고, 저장할 때 밀리초로 내린다. `updated_at_ms`는 Unix epoch 밀리초이며 저장소가 주입 가능한 시계로 기록한다. 알 수 없는 필드가 있으면 손상으로 취급한다.
5. **버전.** `version`은 필수다. 1이면 읽는다. 더 큰 버전이면 읽기는 빈 저장소처럼 동작하고, 쓰기는 Unsupported 오류로 거절해 새 형식 파일을 덮지 않는다.
6. **원자적 쓰기.** 같은 디렉터리의 프로세스별 임시 파일 `resume.json.<pid>.tmp`에 쓰고 fsync한 뒤 rename한다. 쓰기나 rename이 실패하면 그 임시 파일을 지운다. 상위 디렉터리가 없으면 만든다. 프로세스마다 임시 파일이 달라 서로의 임시 파일을 비우지 않으므로, 여러 프로세스가 동시에 쓰면 마지막 rename이 남는다(읽기-수정-쓰기 사이의 다른 프로세스 변경은 잃을 수 있다). 잠금은 범위 밖이다.
7. **손상 파일.** JSON 오류, 형식 불일치, 버전 필드 없음(예전 무버전 형식 포함)이면 빈 저장소로 시작한다. 첫 쓰기 전에 손상 파일을 `resume.json.corrupt`로 rename해 한 벌 보존하고(이전 보존본은 대체) 새 파일을 쓴다. 기존 시험 `malformed_file_is_an_error_not_silent_reset`의 "오류로 거절" 정책은 이 결정으로 대체한다.
8. **상한·정리.** 항목은 최대 1000개다. 쓸 때 `updated_at_ms`가 가장 오래된 항목부터 지우고, 180일 넘게 갱신되지 않은 항목도 지운다.
9. **끝 근처·처음 근처.** 기존 `ResumePolicy`를 유지한다. 위치가 10초 미만이거나, 남은 시간이 60초 이하이거나, 재생 비율이 95% 이상이거나, 길이를 모르면(0) 저장하지 않고 삭제한다. 복원할 때는 3초 되감고 새 길이로 다시 검증한다.
10. **개인정보.** 미디어 경로와 키는 로그나 오류 메시지에 넣지 않는다. 오류에는 저장소 파일 경로와 원인만 담는다. 사이트별 용어는 쓰지 않는다.

## Rationale

- 크레이트: 포트, 정책, 기존 어댑터가 이미 core에 있고 core는 contract 등급이라 domain 정책과 포트를 둔다. 어댑터는 표준 라이브러리 fs만 쓰고 OS 분기가 없어, 그대로 두면 소비자(platform-unix mpv 시험)가 깨지지 않는다. 별도 크레이트 분리는 후속 검토다.
- 저장 위치: 기존 `config_path`·`settings_file`과 같은 "명시 환경변수 → XDG → HOME → Windows" 순서다. 이어보기는 설정이 아니라 기계에 남는 이력이라 XDG Base Directory의 state 범주에 맞다. 순수 함수라서 테스트가 실제 홈을 건드리지 않는다.
- 원격 URL 미저장: 질의 문자열에 서명 URL, 토큰, 쿠키가 들어 있을 수 있고(SoT의 "signed URL 비영속"), 같은 항목도 URL이 매번 바뀌어 키로 불안정하다. 플러그인 재생 항목은 안정적인 항목 ID(플러그인 ID와 항목 ID)로 키를 만드는 후속 조각에서 다룬다.
- 밀리초 정수: 부동소수 왕복 오차가 없고 SoT의 정수 정책과 맞다.
- 새 버전 쓰기 거절: 구 버전 실행이 새 형식 데이터를 지우지 않게 한다.
- 손상 복구: 손상 파일 때문에 재생이 막히면 안 되고, 보존본이 남아 원인을 볼 수 있다.
- skill: 없음 (질의: "Persist media playback resume positions to a JSON file with atomic writes, versioning and corrupt-file recovery in Rust", "rust test-first regression test for a local file-backed key value store with atomic rename") — 상위 결과가 에이전트·ML·영상 생성 주제로 이 조각과 무관.
- skill(리뷰 반영): 없음 (질의: "rust test-first regression test for atomic file write with temporary file and file URL path key normalization", "Write files atomically with per-process temporary file names and clean up on failure; reject non-local file URL hosts") — 상위 결과가 사이트 점검·에이전트·ML 주제로 무관.

## Consequences

- 로컬 파일 재생 위치가 실행을 넘어 남고, 손상 파일이나 새 버전 파일이 재생을 막거나 데이터를 지우지 않는다.
- 무버전 파일은 한 번 `.corrupt`로 보존된 뒤 v1로 다시 시작한다. 예전 형식은 옮기지 않는다(실사용 경로가 없었다).
- 남은 일(리뷰 낮음 항목):
  - Windows 평문 UNC 경로(`\\server\share\…`)는 절대 경로로 보아 키가 생긴다. 네트워크 공유 제외는 `file://` URL에만 적용했고 평문 UNC는 범위 밖이다.
  - Windows canonicalize가 붙이는 `\\?\` 접두사 때문에 같은 파일이라도 파일이 있을 때와 없을 때 키가 다를 수 있다.
  - `file://` URL의 `%2F`·`%00` 디코딩 처리(경로 구분자·NUL로 풀리는 경우)를 정하지 않았다.
  - 상대 `XDG_STATE_HOME`을 거르지 않는다(명세상 절대 경로만 유효).
  - rename 뒤 상위 디렉터리 fsync가 없어 전원 차단 시 rename이 사라질 수 있다.
  - 시계가 epoch 이전이면 `updated_at_ms`가 0이 되어 다음 쓰기에서 정리될 수 있다.
  - 경계값 테스트 일부(상한 정확히 1000개, 밀리초 내림 경계, 같은 시각 항목 정렬)가 없다.
- 남은 일: 동시 쓰기 잠금, 플러그인 항목 키, 열기 경로 연결(M1-6), 환경설정 영속(M1-7), SoT의 CAS·revision·SDK 표면, 어댑터 크레이트 분리 검토.
