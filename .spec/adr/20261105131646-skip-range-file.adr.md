# 수동 구간은 항목 키로 로컬 파일에 남긴다

## Context

로드맵 plan:kinekino/20261031153240의 M1-9c(PL-8)다. ADR 20261105111300은 수동 구간을 지금 항목의 메모리에만 두고 파일에 남기지 않았다. 같은 파일을 다시 열면 구간을 다시 표시해야 한다. 이어보기 저장(ADR 20261103035240)과 같은 로컬 파일 키·원자적 JSON 정책을 쓸지, 회차(형제 파일) 사이에 구간을 복사할지가 남아 있었다.

## Decision

1. **키·위치.** 이어보기와 같은 `ResumeKey`(로컬 파일만). 별도 파일 `skip-ranges.json`을 resume.json과 같은 state 디렉터리에 둔다. `KINEKINO_SKIP_RANGES_FILE`이 있으면 그 경로를 쓰고, 없으면 `XDG_STATE_HOME/kinekino` → `HOME/.local/state/kinekino` → `LOCALAPPDATA/kinekino` 순이다.
2. **JSON v1.** `{"version":1,"entries":{"<key>":{"start_ms":u64,"end_ms":u64,"updated_at_ms":u64}}}`. 메모리의 `SkipRange`는 초(`f64`)이고 저장할 때 밀리초 정수로 내린다. 원자적 쓰기(프로세스별 tmp+rename), 손상→`.corrupt`, 새 버전 쓰기 거절, 상한 1000·180일 정리는 resume_file과 같다.
3. **회차 간 재사용.** 하지 않는다. 형제 파일이나 다음 회차에 구간을 복사하지 않는다. 같은 키를 다시 열 때만 복원한다. (회차마다 오프닝 위치가 다르다. 플러그인 시리즈 키는 범위 밖.)
4. **수명.** `MarkSkipEnd` 성공 시 put. `ClearSkip` 시 저장소에서 clear. 항목 전환 시 메모리는 forget(기존)하되 저장소 항목은 유지. open 완료 시(`resume_opened`와 같은 시점) 키로 get해 복원한 뒤 `skip_offer`를 갱신. eof는 skip을 지우지 않는다(이어보기 위치와 다르다). 저장소 오류는 재생을 막지 않고 resume처럼 코드만 한 번 warn.
5. **포트.** core에 `SkipRangeStore`(get/put/clear)와 `MemorySkipRangeStore`, `FileSkipRangeStore`. 기존 `SkipRange` 값 타입을 재사용한다. 플레이어는 `with_skip_store`로 연결하고, smoke가 아닐 때 watch가 `default_skip_ranges_file`로 파일 저장소를 붙인다.

## Rationale

- 같은 파일을 다시 볼 때 구간을 다시 표시하지 않으려면 항목 키 저장이 필요하다. 형제 파일로 복사하면 오프닝이 다른 회차에서 잘못된 건너뛰기가 난다.
- 이어보기와 키·원자 쓰기·손상 정책을 맞추면 구현·검사가 단순하고, 파일만 분리해 이어보기와 구간이 서로의 형식을 깨지 않는다.
- skill: 조회 결과 무관(persist skip ranges / atomic JSON file).

## Consequences

- 같은 로컬 파일을 다시 열면 확정한 구간과 `skip_offer`가 복원된다. 다른 파일에는 복원되지 않는다. `ClearSkip`은 저장도 지운다.
- ADR 20261105111300 Consequences의 “남은 일 M1-9c”는 이 ADR로 넘긴다. 메뉴 연결(M2-3)은 그대로다. 단축키 표는 adr:kinekino/20261105151827에서 확정했다.
- 남은 일: 플러그인 항목 키, 동시 쓰기 잠금, Windows UNC·canonicalize 접두사(이어보기 ADR과 같은 낮음 항목).
