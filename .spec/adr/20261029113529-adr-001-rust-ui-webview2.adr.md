# Rust UI와 Windows WebView2 선택

> 대체됨: [제품 UI는 Meari, WebView2는 웹 재생 엔진 어댑터로 한정](20261030050042-ui-meari-webview2.adr.md). 아래 WebView2 배포 판단은 엔진 어댑터에 대해 유지된다.

## 맥락

UI까지 Rust, Windows 우선, 광고 제거된 내부 웹 플레이어를 함께 제공해야 한다. 브라우저를 직접 만드는 대신 표준 엔진의 미디어·iframe 실행을 사용한다.

## 대안

| 대안 | 이점 | 비용/제약 |
|---|---|---|
| egui/eframe + Wry/WebView2 | Rust UI, Windows의 Chromium 계열 공유 런타임, 요청 이벤트 직접 연결 | 자식 HWND와 GPU 레이어·포커스 통합 필요 |
| Tauri + HTML/CSS 또는 Rust WASM UI | 웹 레이아웃과 생태계 | 주 UI가 웹뷰이며 Rust native UI 방향과 다름 |
| Rust + CEF 번들 | 엔진 버전 통제 | Chromium 바이너리·프로세스·보안 업데이트 배포 부담 |
| 순수 Rust 네이티브 플레이어만 | 웹 광고 영역 자체가 없음 | 미디어 리졸버 미검증 시 시청 불가 |

## 결정과 결과

Rust UI는 egui/eframe, 호환 플레이어는 Wry의 WebView2 child view로 시작한다. CEF를 번들하지 않는다. WebView2는 앱 안에 호스팅하지만 초기 배포는 Evergreen 공유 런타임을 전제로 하며 Chromium 전체가 실행 파일 안에 포함된다는 표현을 사용하지 않는다. 오프라인 독립 배포가 확정되면 Fixed Version의 설치 크기·업데이트 책임을 비교한다.

장점은 중복 엔진 배포를 줄이는 구조다. 실제 메모리 절감량은 미측정이다. 영상 재생 시 GPU/디코더 프로세스가 추가될 수 있다. 브라우저를 사용하지 않을 때 정리/휴면시키는 정책과 HWND 포커스·DPI·전체화면을 검증해야 한다.

재검토 조건: WebView2의 요청 가로채기 범위로 광고 차단/미디어 관측을 충족하지 못함, GPU/입력 통합 실패, 또는 macOS/Linux를 같은 우선순위로 지원해야 함.

근거: [Wry 문서](https://docs.rs/wry/0.57.0/wry/), [WebView2 배포 모델](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution), [egui 공식 자료](https://github.com/emilk/egui).
