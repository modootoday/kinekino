# ADR 0003: 크로스 OS 경계 — 크레이트 등급, 포트 규약, Registry, 경계 lint

## Context
- 사용자 지시: 메인 언어 Rust, Linux 완전 동작이 현재 목표, Windows는 컴파일 게이트 안에 구현만 하고 검증은 마지막. 계획 plan:kinekino/20261029151512의 P0(크로스 OS 기반)을 확정한다.
- 관측(2026-10-30 KST, `arch/cross-os-foundation`): 어댑터 크레이트 밖의 OS `cfg` 술어 344회 / 106파일(`cargo xtask lint-structure` 집계, `cfg`·`cfg!`·`cfg_attr` 포함, `#[cfg(test)]`·feature 제외). 계획서의 335회와 집계 방식이 달라 수치가 다르다. 대부분 kinekino-player.
- 기존 브라우저 포트(ADR 0002, adr:kinekino/20261029143826)는 능력표 선택을 이미 갖고 있었지만 다른 포트와 공유하는 규약이 없었다.

## Decision
1. **크레이트 등급** (`xtask/src/structure/boundary/mod.rs`의 `CLASSES`가 단일 원천):
   - adapter: `kinekino-platform`, `kinekino-platform-unix`, `kinekino-platform-windows`, `kinekino-browser`
   - contract: `kinekino-core`, `kinekino-media-contracts`
   - composition: `kinekino-app`
   - bin: `kinekino-cli`
   - 나머지는 domain/application. 목록에 없는 크레이트는 위반이다.
2. **진입 경로**: `main → kinekino_app::entry(Args, Env, legacy)`, 그리고 `bootstrap(&Args, &Env) -> App`. composition root에는 `cfg`가 없다. `kinekino platform <capabilities|config>`는 app이 처리하고, 나머지 명령은 기존 SDK runner(legacy)로 그대로 넘긴다.
3. **설정 계층**: 기본값 → 설정 파일 → `KINEKINO_*` env → CLI 플래그 순서로 적용하고, 키마다 출처(`default|file|env|cli`)를 기록한다.
   - 파일 경로: `KINEKINO_CONFIG`, 없으면 `$XDG_CONFIG_HOME|$HOME/.config/kinekino/config.json`, 없으면 `%APPDATA%/kinekino/config.json`.
   - 파일 스키마는 `deny_unknown_fields`라서 비밀값 키가 들어가면 거부된다.
   - 비밀값은 `CredentialStore` 포트로만 다룬다.
4. **포트 규약** (`kinekino-core::port`):
   - 어댑터는 `kind()`와 `capabilities()`를 제공한다(`Adapter`, `AdapterKind`, `CapabilityTable`).
   - 미지원 호출은 `ErrorCode::Unsupported`를 돌려준다.
   - 공통 오류 코드는 `ErrorCode{Unsupported, Unavailable, InvalidInput, Cancelled, Timeout, Quota, Auth, Io, Internal}`이다. 여기에 `retryable`을 더한 `PortError` JSON 형태는 `{"code","retryable","message"}`이고, 포트 오류는 `ToPortError`로 매핑한다.
   - 이벤트는 `drain_events()`로 꺼낸다(`EventSource`).
   - 포트별 Config는 serde + 기본값이며 비밀 필드를 두지 않는다.
5. **Registry** (`Registry<P, K, C, Cfg>`):
   - `register(Registration{kind, declared, rules, probe, factory})` → `select(platform, required, Policy)` → `build(selection, &cfg)` 순서로 쓴다.
   - 플랫폼 규칙은 `(OsId, Option<DisplayServer>, Role{Default, Fallback, Explicit})`이다. `Explicit`은 정책(`Prefer`/`Only`)으로만 선택된다.
   - 후보마다 판정을 남긴다: `NotOnPlatform`, `ExplicitOnly`, `ExcludedByPolicy`, `NotAvailable(이유)`, `Missing(능력)`. `explain().to_json()`이 이 판정을 `kinekino platform capabilities`에 노출한다.
6. **브라우저 정렬**:
   - `kinekino-browser::engine::registry`가 ADR 0002 플랫폼 매트릭스로부터 등록을 생성한다. 기존 `select()`와 같은 결과를 내는지 전수 테스트로 확인했다(설치 조합 16 × 플랫폼 6 × 요구 능력 5).
   - `ChromeCdp`는 `Explicit`이다.
   - `EngineError`는 `Launch→Unavailable`, `Call→Internal`, `Unsupported→Unsupported`로 매핑한다.
   - 어댑터별 factory는 각자의 cfg/feature 게이트 안(`registry/factory.rs`)에 있다.
7. **세션 포트** (`kinekino-platform::session`):
   - `target()`: Unix는 `DISPLAY`/`WAYLAND_DISPLAY`로 X11/Wayland를 판별한다(Wayland 우선).
   - `SessionCredentialStore`: Unix는 프로세스 수명 동안만 유지되는 메모리 저장소다. Windows는 모든 호출이 `Unavailable`인 자리표시이고 미검증이다.
8. **경계 lint 5종** (`cargo xtask lint-structure`, 허용 목록 `xtask/structure-allowlist.txt`):
   - R-cfg `r-cfg <file>`: 어댑터가 아닌 크레이트의 OS cfg.
   - R-dep `r-dep <crate> -> <dep> (이유)`: domain/contract가 adapter/composition에 의존하는 경우, bin이 composition 외 크레이트에 의존하는 경우, 그리고 미분류 크레이트.
   - R-ver `r-ver <crate> <dep>`: `workspace = true`가 아닌 의존.
   - R-entry `r-entry <file>`: bin 진입이 15줄 초과이거나, cfg가 있거나, `main`이 `kinekino_app::` 단일 호출이 아닌 경우. xtask는 제외.
   - R-port `r-port <file> <Trait>`: 포트형 이름(`*Port|Engine|Store|Sink|Host|Provider|Backend|Transport|Client|Api|Gateway`)의 trait이 contract 크레이트와 `port/`·`ports.rs` 밖에 정의된 경우.
   - 기존 부채는 허용 목록에 기준선으로 고정하고 신규 위반 0을 게이트로 둔다.

## Consequences
- 신규 크레이트와 어댑터는 `CLASSES`에 등급을 추가해야 lint를 통과한다. 새 OS cfg는 adapter 크레이트에만 둘 수 있다.
- 기준선(2026-10-30 KST): r-cfg 106, r-dep 8, r-ver 43, r-entry 6, r-port 41. 기존 구조 위반 298건은 그대로다. 수치는 허용 목록 축소로만 줄인다(P1 이후).
- 한계:
  - R-cfg는 파일 단위 키라서, 이미 허용된 파일 안에서 cfg가 늘어나는 것은 잡지 못한다. 총계 출력으로 추적한다.
  - R-port는 이름 휴리스틱이다.
  - kinekino-cli `main.rs`는 `#[cfg(windows)] mod` 선언 때문에 R-entry 위반으로 남는다. host 모듈을 adapter로 옮기는 것이 후속 과제다.
- Windows 경로(`platform-windows::session`, webview2 factory)는 컴파일 게이트 안에만 있고 Linux에서 빌드·검증하지 않았다.
