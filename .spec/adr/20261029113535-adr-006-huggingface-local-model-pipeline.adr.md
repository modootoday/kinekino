# Hugging Face 모델 카탈로그와 작업별 로컬 추론

## 배경과 결정

사용자가 HF 기반 모델과 노트북에서 동작 가능한 경량성을 지정했다. 모델 카탈로그/버전/아티팩트 유통은 HF Hub를 기준으로 하고 모델별 로컬 실행을 기본으로 한다. 오디오 인식·텍스트 교정/요약·OCR·분리/추적·깊이 추정을 각각 별도 포트로 둔다. 단일 sLM이 모든 모달리티를 처리한다고 가정하지 않는다.

## 선택 비교

| 선택 | 장점 | 비용/선택 이유 |
|---|---|---|
| 항상 클라우드 추론 | 로컬 메모리 부담 작음 | 네트워크·요금·미디어 전송. 기본 경로로 선택하지 않음 |
| 하나의 대형 멀티모달 모델 상시 탑재 | 공통 인터페이스 | 노트북 RAM/VRAM·속도·시간 정렬 품질 부담 |
| 작업별 소형 모델 필요 시 로드 | 노트북 자원 예산과 교체 용이 | 여러 런타임/포맷·전처리 검증 필요. 선택 |
| 모든 추론을 순수 Rust로 새 구현 | 언어 통일 | 모델 지원/품질 검증 비용. 코어/UI는 Rust, 엔진은 검증된 FFI/worker를 허용 |

HF main/latest를 실행 시 무조건 추종하지 않는다. 검증한 commit·파일 해시·토크나이저·양자화·변환 계보·라이선스·런타임 버전을 고정한다. 파일은 필요 시 설치하고 실패/취소/오프라인을 지원한다. 모델 패키지는 데이터이며 저장소의 임의 코드를 자동 실행하지 않는다.

노트북 기본은 CPU로도 완료 가능한 오프라인 작업, 1개 무거운 작업, 필요 시 모델 해제다. GPU/NPU는 선택 가속으로 두고 제조사 이름만으로 호환을 확정하지 않는다. 사용자 후속 확인에 따라 목표 노트북은 현 데스크톱과 동급이며 현 호스트를 주 실측 기준으로 삼는다. 내장 GPU/8~16GB는 선택 확장 목표다. 배터리·발열에 따른 차이는 별도 미검증으로 남긴다.

## 결과와 재검토

모델별 계보·평가·배포 조합이 늘지만 기능의 교체/경량화가 가능하다. ASR 원문과 교정안, 사용자 검토와 생성 초안을 분리한다. OCR/ASR·요약·마스크/깊이 결과에 원본 시간·모델 revision을 유지한다. 현 후보 선정은 조사 단계이며 성능 수치를 확정하지 않았다.

설계 예산과 실제 호스트 관측은 [AI 정본](../../sots/player/application/analysis/sot-013-local-ai-projection-assets.md)을 따른다. 노트북 메모리/품질 게이트를 못 맞추면 더 작은 모델·입력 축소·긴 작업의 분할·기능별 선택 설치를 먼저 검토한다. 기본 기능을 실행하기 위해 WSL/VM·별도 서버 설치가 필요해지는 경우 다시 결정한다. 현재 DPI·VM 보류 지시는 유지한다.
