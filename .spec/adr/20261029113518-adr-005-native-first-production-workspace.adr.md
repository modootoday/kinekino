# 네이티브 우선 단일 창과 독립 제작 작업

## 배경

사용자가 현재 웹 중심 화면을 네이티브 중심으로 바꾸는 방향을 확정하고 저장·변환·숏폼·카드뉴스·투영 에셋까지 설계를 확장했다. 재생 UI에 모든 편집 기능을 추가하면 조작이 복잡해지고 UI 스레드·세션·프로세스 책임이 섞인다.

## 비교

| 선택 | 이점 | 비용/한계 |
|---|---|---|
| 웹 메인+추가 버튼 | 현 구조 변경이 작음 | 사용자가 확정한 네이티브 우선 방향과 불일치, 캡처/정확 편집 능력 불명확 |
| 단일 창 네이티브+접이식 제작 패널 | 익숙한 재생 유지, 맥락과 위치 보존 | HWND/WebView와 편집 프리뷰 합성·포커스 설계 필요 |
| 별도 대형 편집 앱/창 | 전문 편집 UI 공간 | 창·모델·미디어 수명 중복, 첫 버전 범위 과대 |

## 결정

네이티브 기본 영상·컨트롤을 중심에 두고 웹은 탐색/소스 확인/명시적 호환 복구로 제공한다. 회차 열기에서는 검증된 소스만 mpv로 연결한다. 네이티브 실패 시 웹 자동 전환·광고 차단 해제 대신 이유/재시도/웹 재생을 표시한다. 정상 웹 제스처 요구는 화면에 드러낸다.

제작은 단일 창의 접이식 패널/편집 화면이며 다운로드·ASR·인코딩은 application 작업 큐의 독립 작업이다. 재생 세션에서 미디어 ID/시간/트랙을 스냅샷으로 받아 진행 중 회차 전환이 이미 시작한 산출물의 입력을 바꾸지 못하게 한다. 완료 작업만 캐시하고 부분 실패는 항목별 처리한다.

저장/리먹스/정확 컷·합성은 유스케이스를 분리한다. 공통 프로젝트 모델과 검증된 입력으로 수동·추천·일괄 제작을 처리한다. 프로젝트는 실행 코드가 아니라 선언적 데이터이며 외부 게시 기능은 별도다.

## 결과와 재검토

UI는 단순해지지만 프리뷰/최종 결과 일치, 자원 스케줄링, 영속 프로젝트/복구가 추가된다. 첫 단계는 네이티브 우선+기초 저장이며 AI와 고급 투영은 뒤의 독립 게이트다. HWND 위에 egui 오버레이를 합성할 수 있다고 전제하지 않는다. 편집 프리뷰는 별도 소유 렌더 영역/texture 또는 일시정지 프레임을 사용하고 libmpv texture 통합은 필요성과 측정 근거가 생길 때 별도 ADR로 정한다.

관측·목표 차이는 [UX 정본](../../sots/player/presentation/viewing/sot-011-native-first-studio-ux.md), 기능 계약은 [제작 정본](../../sots/player/application/production/sot-012-media-production.md), 단계는 [계획](../../plans/player/plan-003-native-studio-expansion.md)을 따른다. 현재 구현이 이 결정을 충족한다고 표시하지 않는다.
