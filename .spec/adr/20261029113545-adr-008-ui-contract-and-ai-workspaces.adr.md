# UI 요소 계약과 AI 제작 작업 공간

2026-10-18 사용자 승인: “UI/UX 설계 제안은 만족스럽습니다. 승인합니다.” 기능/정보 구조와 계약을 승인했다. ImageGen 이미지 간 불일치는 채택하지 않으며 폰트·간격·아이콘·밀도·상태별 디테일은 실제 공통 Rust 컴포넌트 구현 후 판단한다. 그림을 pixel-perfect 구현 사양으로 간주하지 않는다. Pages는 갱신하지 않는다.

## 배경

사용자는 PotPlayer 기반 네이티브 기본 UI, 모든 개발 Rust, 단일책임·모듈화·계층 구조를 지정했다. 병합 이미지는 읽기 어렵고 단순 목업만으로 기능과 상태를 구현할 수 없으므로 탭별 시각화와 완전한 설계 정본을 요구했다.

## 제안

[UI 정본](../../sots/player/presentation/sot-020-ui-contract.md)을 공통 프레임과 13개 책임별 화면 계약으로 분리한다. 요소 ID, 입력 검증, 상태, 저장 데이터, 인수 기준을 문서에 명시하고 Pages에 독립 이미지와 함께 배포한다. 이미지의 임의 글자·치수·기본값은 계약보다 우선하지 않는다. 사용자 검토 답변은 Pages와 정본의 결정 상태에 함께 반영한다.

시청은 필요한 네이티브 조작과 구간 스킵만 유지하고, 제작은 공통 프레임 안에서 작업별 편집기·검사기를 교체한다. ASR/OCR/텍스트 교정/오디오·영상 구간/분할·추적/깊이 추정을 별도 모델 기능으로 취급한다. 준비되지 않은 모델이나 저장 형식은 명시적 NeedsInput으로 처리한다.

## 비교

큰 통합 이미지 한 장은 비교하기 쉽지만 세부 판독과 변경 추적이 어렵다. 이미지 단독은 제작 속도가 빠르지만 상태·검증·데이터 계약을 전달하지 못한다. 탭마다 독립 제품을 만드는 방식은 공통 자원·작업 큐·원본 참조를 중복시킨다. 공통 shell과 책임별 계약은 이를 공유하며 탭별 로직을 분리한다.

## 영향

presentation에 OS·COM·모델 로딩·프로세스 정책을 넣지 않는다. 모델 선택과 실측은 별도 게이트다. 대기열·미리보기·출력은 revision으로 연결하여 오래된 결과가 현재 편집을 덮어쓰지 않게 한다. 설계 승인은 기능 구현·실제 렌더·접근성·모델 품질 검증 완료를 뜻하지 않는다.
