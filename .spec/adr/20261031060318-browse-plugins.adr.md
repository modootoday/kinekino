# 작품 탐색을 소스 플러그인에 연결: Catalog 포트와 PluginCatalog

## Context

시작 화면의 `작품 탐색` 버튼은 안내 문구만 보였다. 소스 플러그인 인프라([ADR 0011](20261030200000-adr-0011-media-source-plugin.adr.md))는 `SourceProvider`·`ProcessSource`·`plugins list`까지 있지만 플레이어 창과 연결되지 않았다. 플레이어 UI 크레이트는 플러그인 호스트를 알면 안 되고(포트 규약, ADR 0003), 특정 사이트 지식은 공개 저장소에 들어가지 않는다.

## Decision

- `kinekino-player-ui`에 `Catalog` 포트(`sources()`, `browse(at, page)`)를 둔다. 타입은 `kinekino_core::source`만 쓴다. `Controller::with_catalog`로 주입하고, 없으면 탐색은 "설치된 소스 플러그인이 없습니다" 안내를 시작 화면 상태 줄에 보인다.
- 탐색 화면은 시작 화면 자리에 뜨는 목록이다. 첫 단계는 설치된 소스(manifest id), 소스를 고르면 그 루트(빈 item id)를, 항목을 고르면 그 항목을 `browse`한다. 한 화면 `BROWSE_ROWS`(12)줄 고정 슬롯이라 목록이 바뀌어도 문서를 다시 마운트하지 않는다. `더 보기`는 `next_page`, 뒤로 버튼과 창 모드 Esc는 한 단계 뒤로 간다. 소스가 거절하면 목록을 유지하고 이유만 보인다.
- 루트 항목 규약: `SourceRef { provider, id: "" }`는 소스의 첫 목록이다. 플러그인은 빈 id를 자신의 기본 목록으로 해석한다.
- `kinekino-app`의 `PluginCatalog`가 어댑터다. 발견된 플러그인 중 `browse`를 선언한 것만 싣고, 호출마다 `ProcessSource` 왕복 한 번이다. `watch`가 `Env`로 플러그인 폴더를 찾아 주입한다.
- 검증은 합성 플러그인(`fake-source-plugin`, `com.example.fixture`)만 쓴다. 실제 소스 플러그인과 관찰 기록은 저장소 밖(`.spec.local`)에 둔다.
- 스타일은 회차 패널 목록 구성요소(`aw-catalog-browser`, `aw-episode-row`)를 그대로 쓰고, 폭은 `--aw-episode-panel`의 두 배로만 정한다(새 값 없음).

## Consequences

- 플레이어 UI는 플러그인 프로세스·manifest를 모른다. 다른 어댑터(캐시, 원격)를 같은 포트로 바꿔 끼울 수 있다.
- 호출은 UI 스레드에서 동기로 돈다. 느린 플러그인은 그동안 창을 멈춘다. 비동기화는 [남은 일](../plan/20261031060318-browse-plugins-next.plan.md)에 있다.
- 시리즈·회차 목록·스트림 해석·재생 연결은 아직 없다. 탐색은 목록 단계까지다.
