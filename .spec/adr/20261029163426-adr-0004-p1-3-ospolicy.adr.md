# ADR 0004: P1 3단계 — OsPolicy 포트 역전과 진입점 이전

## Context
- P1 3단계(plan:kinekino/20261029151512). domain 크레이트 `kinekino-player`·`kinekino-process`가 어댑터 `kinekino-platform`의 자유 함수(`fs::{apply_share_mode, apply_open_flags, open_reserved_read, is_reparse_point, is_sharing_violation, file_identity}`, `process::hide_console_window`, `io::close_original`)를 15곳에서 직접 불러 R-dep 위반 2건이 allowlist에 있었다.
- 블로커: app을 거치지 않는 진입점(bin `owned-process-test-child`, `source-sdk-fixture-worker`, `media-source-worker`, 그리고 조사 중 확인한 `player`)과 단위·통합 테스트에는 구현체가 등록되지 않는다. core에는 플랫폼 `cfg`를 둘 수 없다. 사용자 승인(2026-10-30 KST): 권고안 (a) — bin을 어댑터/app 쪽으로 옮기고 각 진입점에서 install.

## Decision
1. **포트**: `kinekino_core::platform::OsPolicy`(Send+Sync 트레이트, 위 8개 연산). 프로세스 전역 슬롯 `install(&'static dyn OsPolicy)`(첫 등록 우선, 이후 무시)·`is_installed()`·`os()`(미등록이면 진입점 누락을 알리는 panic).
2. **구현체/팩토리**: `kinekino_platform::CurrentOs`가 빌드 OS 어댑터에 위임하고 `kinekino_platform::install()`이 등록한다(멱등).
3. **호출부**: 각 domain 크레이트의 `infrastructure::os_policy` 모듈만 `os()`를 부른다. 기존 함수 이름을 그대로 노출해 호출부 변경을 import 경로로 한정했다. `#[cfg(test)]`에서는 이 모듈이 `CurrentOs`를 명시 주입한다.
4. **의존성**: player·process는 `kinekino-platform`을 dev-dependency로만 가진다(R-dep은 normal 의존만 검사). process는 `kinekino-core`를 새로 의존한다.
5. **진입점 이전**: 네 bin 모두 `kinekino-app`의 thin entry(`src/bin/*.rs`, 본문 `kinekino_app::…()` 한 줄)로 옮겼다. app 함수는 `kinekino_platform::install()` 후 `kinekino-host`(adapter, `cfg` 허용)의 본문 모듈을 부른다: `kinekino_host::player_gui::main`, `kinekino_host::fixtures::{owned_process_test_child, source_sdk_fixture_worker, media_source_worker}::main`. `kinekino_app::entry()`(CLI)도 install한다.
6. **features**: app·host에 `native-proposal-window`, `test-support`, `source-adapter-test-support`, `worker-ipc`를 추가해 원래 크레이트 feature로 전달한다. bin의 `required-features`는 같은 이름을 유지한다.
7. **테스트**: player·process 통합 테스트는 각 `#[test]` 첫 줄(또는 공용 `Fixture::new`)에서 `kinekino_platform::install()`을 명시 호출한다. 다른 패키지 bin은 `CARGO_BIN_EXE_*`로 못 찾으므로 `<profile>/<bin>[.exe]`를 찾고 env(`OWNED_PROCESS_TEST_CHILD`, `PLAYER_EXE`)로 덮어쓸 수 있게 했다.

## Consequences
- allowlist 449 → 439(R-dep 2, R-entry 4, R-cfg 4 해소). 신규 위반 0.
- 검증(Linux, 2026-10-30 KST): fmt, clippy `-D warnings` 0(workspace 기본 + app 세 fixture feature), 테스트 951 통과, lint-structure 신규 0, spec-check 0.
- **미검증**: Windows 빌드·실행(`player.exe`, 세 fixture, `windows_family`·`native_product_launch` 테스트의 bin 경로 해석)은 컴파일 게이트 안 변경만 했고 실검증하지 않았다. `native-proposal-window` feature 빌드도 이 박스에서 돌리지 않았다. Windows 테스트 전에 `cargo build -p kinekino-app --features <feature> --bin <bin>`이 필요하다.
- `os()` 미등록 panic은 새 진입점이 install을 빠뜨리면 첫 호출에서 드러난다.
