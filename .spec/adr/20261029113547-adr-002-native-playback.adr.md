# 네이티브 재생 엔진과 미디어 검증 게이트

## 맥락

OBS-06~09: frame-host는 중개 페이지이며 실제 video는 별도 iframe 안에 있고 소스는 blob이다. 네이티브 컨트롤을 우선하되 아직 관측하지 않은 HLS API를 가정해서 구현할 수 없다.

## 대안 및 결정

| 대안 | 이점 | 비용 |
|---|---|---|
| mpv 별도 프로세스 + 로컬 IPC | FFI 없이 네이티브 재생·명령 시험, UI 장애 분리 | 창 분리, 바이너리 배포 및 IPC 수명 관리 |
| libmpv 임베드 | 단일 창과 세밀한 렌더링 통합 | FFI/GPU 수명·빌드·라이선스 조합 검증 |
| GStreamer | 파이프라인 통제 | Windows 플러그인 배포와 플랫폼 연동 |
| 브라우저만 | 현재 표본의 재생 구조와 가까움 | 네이티브 컨트롤 우선 요구를 충족하기 어려움 |

초기 어댑터는 mpv 프로세스와 Windows named pipe JSON IPC로 한다. 셸을 거치지 않으며 사용자가 직접 배치한 신뢰된 실행 파일만 실행한다. 현재 프로세스/IPC를 유지하면서 HWND 영상 영역 임베드를 적용했다. `--wid`로 앱 자식 창에 출력한다. libmpv FFI 도입은 현재 필요하지 않으며 GPU 텍스처 합성 등 요구가 생기면 재검토한다.

HTTPS 미디어 요청과 정상 수신된 HLS 응답을 메모리에만 저장하고 네이티브 재생 버튼을 활성화한다. 관측한 media.example.test의 master.txt는 본문의 #EXTM3U·#EXT-X-로 확인한다. 확인된 HLS는 lavf/hls로 지정하여 일반 M3U 조각 재생을 방지한다. blob URL·플레이어 HTML을 파일 URL로 추측하지 않는다. DRM/접근 제한을 해제하는 구현은 포함하지 않는다.

## 결과와 재검토

Tokio 비동기 named pipe에서 명령 응답과 재생 속성을 관찰한다. 시간·영상 크기 및 웹 영상과 일치하는 전체 길이를 확인하기 전 NativePlaying으로 확정하지 않는다. 정상 HLS 재생을 확인한 뒤 웹 영상을 pause한다. Referer를 전달하며 쿠키 복사·토큰 만료 처리는 아직 구현하지 않았다. 후보가 없거나 네이티브가 실패하면 광고 차단된 웹 모드를 유지한다. 실제 검증 상태는 [검증 정본](../../sots/verification/playback/sot-005-playback-validation.md)을 따른다.

세 카테고리 표본에서 HLS 응답 감지와 30초 이상 mpv 재생을 재현하여 이 접근의 초기 유효성을 확인했다. 전체 콘텐츠나 만료/인증 처리가 검증된 것은 아니다. 단일 창 출력·컨트롤·전체화면의 실제 관측은 [통합 UI 검증](../../sots/verification/presentation/sot-006-integrated-ui-validation.md)을 따른다. 장시간·다중 DPI 안정성은 후속이다. 배포 시 mpv 및 코덱 빌드의 라이선스·NOTICE를 실제 산출물 기준으로 확인한다.
