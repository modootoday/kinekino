# 제품 UI는 Meari, WebView2는 웹 재생 엔진 어댑터로 한정

## Context

[ADR-001](20261029113529-adr-001-rust-ui-webview2.adr.md)은 제품 UI를 egui/eframe으로, 호환 웹 플레이어를 Wry의 WebView2 child view로 정했다. 사용자 방침은 kinekino의 모든 UI를 Meari로 만드는 것이다. 설정 창은 이미 Meari로 옮겼다([설정 창 ADR](20261030040215-settings-window-meari.adr.md)). ADR-001의 재검토 조건 중 "macOS/Linux를 같은 우선순위로 지원"도 충족됐다.

## Decision

- 제품 UI(플레이어 셸, 스튜디오, 설정, 대화상자)는 Meari(`meari`, `meari-native`)로 그리며 모든 OS에서 같은 코드를 쓴다. egui/eframe을 새 UI에 쓰지 않는다.
- WebView2(Wry, webview2-com)는 웹 재생 엔진, 즉 광고 차단과 미디어 관측이 붙은 호환 플레이어와 플러그인 브라우저에만 쓴다. 이 엔진은 `kinekino-browser`의 BrowserEngine 포트 뒤에 있는 어댑터이며 제품 UI 렌더러가 아니다.
- ADR-001의 WebView2 배포 판단(Evergreen 공유 런타임, CEF 미번들)은 엔진 어댑터에 대해 그대로 유지한다.

## Consequences

- `kinekino-player`의 `presentation/`(eframe·egui_extras·egui_taffy)는 이관 대상이다. 이관 계획은 plan에 기록한다.
- `kinekino-player`에 직접 있는 wry·webview2-com 사용처(`infrastructure/browser_provider`, `webview_audio`, `local_file_picker`)는 엔진 어댑터 용도이며 제거 대상이 아니다. 다만 `kinekino-browser`로 모으는 것이 경계 규칙에 맞는다.
- 이관이 끝날 때까지 플레이어 GUI는 eframe을 쓰며, 이것은 이 ADR과의 알려진 편차다.
