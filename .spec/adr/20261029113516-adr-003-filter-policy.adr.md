# 네트워크 필터와 cosmetic 필터 분리

## 맥락과 결정

광고 제거는 핵심 요구이며 웹 모드도 예외가 아니다. DOM 숨김만 하면 광고 코드·추적 요청이 실행되고, 네트워크 차단만 하면 빈 슬롯과 남은 홍보 영역이 보인다. 따라서 Rust 요청 차단, 호스트 범위의 CSS 숨김, 팝업 차단을 분리한다.

네트워크 엔진은 ABP 문법을 지원하는 adblock-rust를 선택한다. 초기 규칙은 조사 기반의 작은 자체 목록으로 배포하고 로컬 추가·예외를 지원한다. 대규모 외부 목록·원격 갱신은 라이선스·무결성·회귀 검증 이후 도입한다. CSS는 원본 플레이어 iframe을 지우지 않는 사이트 전용 규칙으로 시작한다.

실제 외부 iframe 검증에서 종전 WebView2 필터 등록 API의 범위 제한을 확인하여 ICoreWebView2_22의 요청 출처 종류 ALL 등록으로 변경했다. 이 인터페이스를 제공하는 런타임이 필요하며 실패 시 제한된 구 API로 조용히 대체하지 않는다. [검증 근거](../../sots/verification/playback/sot-005-playback-validation.md)를 따른다.

## 대안과 비용

도메인 문자열만 직접 매칭하면 가볍지만 예외·리소스 종류·서드파티 규칙이 늘면서 직접 필터 언어를 만들게 된다. 확장 프로그램 설치는 사용자 환경과 엔진 정책에 의존한다. 모든 외부 도메인을 막으면 미디어 CDN까지 차단할 수 있다. 선택한 방식은 별도 매칭 라이브러리의 비용과 사이트 전용 셀렉터 유지보수를 수용한다.

초기 목록은 전체 광고를 포괄하지 않는다. 미디어 자체 광고·워터마크는 제거 범위가 아니다. 실제 차단율/메모리/CPU 수치는 측정 후 기록한다. 재검토 조건은 오탐으로 재생 실패, 엔진 콜백 처리 지연, 목록 라이선스 부적합 또는 도메인 구조 변경이다.
