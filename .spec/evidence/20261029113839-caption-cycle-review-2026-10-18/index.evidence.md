# 캡션 최대화·복원·최소화·키보드 실제 검토

2026-10-18. 기준 native-player-start-v2.png 전체와 캡션(1404,0,182,46)4× 파생물 caption-start-r97-4x.png를 확인했다. 최소화 가는 수평선, 최대화 사각, 닫기 대각선과 기본 외곽선 없는 이어진 영역이 기준이다. 공용42×32 hit 영역과16 viewBox 안의 실제 약10~12 glyph 계약을 재확인했다. 이 기록은 이전 복원 아이콘/최소화 미검증 항목을 아래 범위에서 보완한다.

## 실행 식별과 범위

`runtime/review-runs/ui-caption-cycle-20261018-r97/player.exe`(PID115496), 일반 실행(ui-demo 없음). 기존 가상 모니터 안의3500,100에서1180×760으로 시작했다. VM·DPI·모니터 구성은 변경하지 않았다. 실제 영상은 열지 않았다.

최대화/복원 직후 capture는 Windows 애니메이션 중 이전 크기의 잔상/배경을 포함했다. 추가 입력 없이 완료 상태를 재관측한 뒤 다음 조작을 했다. 이를 앱의 안정된 배치로 판정하지 않는다. 최대화 작업 영역의 높이2112와 모니터 전체2160은 작업 표시줄 영역 차이이며 DPI 변경을 수행한 것이 아니다.

## 판정·남은 범위

일반 시작 화면의 마우스 최대화/복원/최소화, 키보드 최소화/닫기, focus 표시와 복귀 후 빈 회차 패널 보존을 실제 확인했다. 새 결함은 발견되지 않아 Rust 코드를 변경하거나 검사를 재실행하지 않았다. 검토용 프로세스는 직접 종료했다.

760/980/제작 화면의 동일 cycle, 긴 실제 미디어 제목, 재생/전체화면과 minimize 조합, pressed 지속 상태, 모든 hover 상태의 정밀 색 비교, 키보드 최대화/복원, OS 스크린리더의 실제 이름 판독은 미검증이다. 캡션 전체 상태/제품 전체 시각 인수 완료로 확대하지 않는다.
