# 음성·자막·음악 검증

2026-10-18, [공통 조건](README.md). 실제 Sintel 107~132초의 25초 영어 대화, 30~50초 음악, 한국어 FLEURS 12.48초를 사용했다.

## ASR와 양자화

Candle whisper tiny FP32/Q8을 동일 입력으로 교대로 각각 3회 실행했다. 모두 실행 성공이며 영어 인식 결과도 같았다. 잘못 인식한 `dark past → turk blast` 등은 양쪽에 남았다.

| 모델 | 3회 중앙 실행시간, 로드 포함 | 최대 표본 private bytes |
| --- | ---: | ---: |
| tiny FP32 | 3.6753431초 | 307,232,768 |
| tiny Q8 | 9.1921633초 | 262,946,816 |

이번 CPU 조건에서 Q8은 느렸고 메모리 표본 최대는 낮았다. 최초 단발 실행을 반복 비교 결과와 섞지 않는다.

한국어 FLEURS 한 문장에 대해 구두점·공백을 제거하고 Unicode 영숫자를 소문자화한 CER은 tiny 두 변형 모두 11/53=20.75%, base의 타임스탬프 비활성 텍스트는 5/53=9.43%였다. base도 연도 2011을 2021로 인식했다. 이 한 표본으로 언어 전체 품질을 판단하지 않는다.

base 타임스탬프 활성 실행은 12.48초 입력에 13.5~15.5초 구간을 출력했다. 비활성 실행의 0~30초 출력도 정렬 자막으로 쓰지 않는다. 검증 도구에 원본 시간 범위 검사를 추가했다. 텍스트 CER이 낮아도 정렬·화자 자막 자동 게시 승인은 아니다. 강제 정렬 및 수기 정답 구간 비교가 남아 있다.

일본어 FLEURS row API는 서버의 Parquet 크기 한도로 500을 반환했다. 이후 공식 고정 revision의 dev archive(179,387,192 bytes)를 Rust로 내려받고 LFS SHA256을 검증했다. 서로 다른 transcript ID 1516/1634/1578의 16.74/12.12/9.00초 float32 WAV를 원본 보존 후 PCM16으로 변환했다. 세 파일은 모두 MALE 메타데이터이며 서로 다른 화자임을 보장하지 않는다. 초기 입력 검사는 float32를 거절했고 실제 포맷 확인 후 변환 경로를 수정했다.

tiny Q8/base FP32 각각 3개 입력의 최초 6회 실행은 프로세스 성공이었지만 ID1516 tiny에서 반복 문구가 생겨 정규화 CER이 672.13%였다. base는 37.70%, ID1634 tiny/base는 11.63/9.30%, ID1578은 40/20%였다. 오류율은 삽입 오류 때문에 100%를 넘을 수 있다.

디코더가 원본 16.74초가 아닌 패딩된 mel의 45초를 전체 음성 길이로 취급해 30~45초 무음까지 별도 디코딩하는 문제를 확인했다. 연구용 Candle 예제를 원본 PCM 길이로 반복 범위를 제한하도록 수정하고 `-bounded` 별도 6회 실행을 완료했다. 기존 실행과 해시는 유지한다. 패딩 encoder 입력 자체를 제거하거나 출력 문자열만 임의 삭제하는 방식은 쓰지 않는다. 일본어 OCR은 이 음성 평가와 구별한다.

| transcript ID | 수정 후 tiny Q8 CER | 수정 후 base FP32 CER |
| --- | ---: | ---: |
| 1516 | 57.38% | 36.07% |
| 1634 | 11.63% | 9.30% |
| 1578 | 40.00% | 20.00% |

모두 프로세스 성공이며 1516의 30~45초 반복 출력은 사라졌다. 실측 실행 파일 SHA256은 `e980948855b7a552f85a6f15690486060c9e5a07cd3d5fe59e3c915d9175720a`다. 남은 실제 발화 오인식은 크며 읽기 음성 3개만으로 자동 자막 품질을 승인하지 않는다. 패딩으로 생긴 추가 구간 수정과 모델 자체 정확도 개선을 구별한다. 개발 빌드와 병행한 실행이므로 속도 순위로 쓰지 않는다. 타임스탬프 비활성 출력은 여전히 정렬 자막이 아니다.

## 화자와 전처리

추가 Qwen0.6B Rust CPU 실추론의 한국어1개·일본어3개·영어 영화 대화 결과와 프로토콜 구분자 노출 문제는 [별도 검증](qwen-asr.md)에 기록했다. 한국어 CER5.66%, 일본어24.59/0/12%는 선두 프로토콜 구분자만 분리한 발화 값이며 raw 오류율도 보존했다. 정렬·화자 품질 통과나 양자화 채택은 아니다.

pyannote segmentation FP32 및 INT8, WeSpeaker embedding을 Rust/ORT에서 실행했다. FP32의 단순 cosine 군집은 5개, INT8은 4개 군집을 만들었다. 실제 화자 수 정답에 대한 DER/JER을 계산하지 않았으므로 이 차이를 개선으로 해석하지 않는다. 짧은 구간은 unknown으로 남겼다. 실제 community-1의 VBx 전체 파이프라인과 같지 않다.

위 군집5/4는 초기 Sintel 입력의 관측이다. 이후 AMI human reference 대조·local-anchor/PCM배율 실험과 [60~120초 시간 분리 검증](diarization-temporal-holdout.md)을 수행했다. AMI의 실제 DER/JER·원본DER대조·소수화자 누락은 별도 정본을 따르며 초기 Sintel의 정답 부재를 AMI 현재 평가 부재로 해석하지 않는다.

순수 Rust kaldi-fbank와 native knf의 동일 Povey 조건 2,498×80 특징 비교에서 최대 오차 0.0000629425로 설정 허용치 0.001을 통과했다. 실제 embedding 입력은 모델 설정에 맞는 Hamming이며 이 Povey 비교를 Hamming 전체 검증으로 표현하지 않는다. 시간 경계는 모델 프레임을 균등 투영한 근사치다.

## 음악·스킵

후속 [독립 Sprite Fright ASR·음악 관측](animation-asr-music.md)은 실제4개 클립과 전체 프레임 점수를 추가했다. 대화 중에도 Music 평균 점수가 높았고 자막 공백에서 ASR 문장이 나왔다. 새 결과를 자동 skip 또는 자동 자막 승인으로 사용하지 않는다.

Silero VAD 25초 입력 실행 성공. YAMNet은 20초 실제 영화 음악에서 Music과 Speech 점수를 출력했지만 점수를 스킵 확률로 보정하지 않았다. rusty-chromaprint는 동일 음악 앞에 무음 2초를 추가한 양성 대조에서 약 1.981초 이동을 찾았고 다른 대화 클립에서는 일치가 없었다.

이는 구성한 양성/음성 대조다. 서로 다른 실제 회차의 OP/ED 자동 탐지·오탐률 검증은 남았다. 수동 마커, 자동 제안, 자동 스킵은 각각 별도 승인과 되돌리기 상태를 유지한다.
