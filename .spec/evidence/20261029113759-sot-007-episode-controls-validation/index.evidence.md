# 회차 패널·전환·전체화면 자동숨김

## 실제 사이트 조사와 계약

Codex 내장 브라우저에서 방영중→어떤 암부의 소녀공서→2화로 이동해 조사했다. `/c/` 작품과 `/e/` 회차 페이지에 `.wr-subject a[href^="/e/"]` 회차 목록이 있고, 최신 회차부터 내려오는 순서였다. 2화의 `.ep-nav`에는 1화 이전 링크가 있으며 마지막 회차 이후 링크는 없었다. 회차의 정상 재생 진입점은 `button.watch-now`의 “바로 보기”다.

URL 숫자를 더하거나 중개 URL을 추측하지 않는다. 로드된 DOM의 회차 목록을 역순으로 가져와 오래된 회차부터 표시한다. 목록 순서가 바뀌거나 선택자가 바뀌는 사이트 변경은 호환성 재검증 대상이다.

## 계층별 구현

| 계층 | 책임 |
|---|---|
| domain/episodes.rs | 회차/페이지 값 객체, HTTPS source.example.test의 /c/·/e/ 경로·자격정보·query/fragment·개수·문자열 크기 검증 |
| application/episode_queue.rs | 중복 제거, 현재 회차, 목록 경계, 이전/다음 대상, 다른 작품/목록 이동 시 폐기, 오래된 페이지 스냅샷 거절 |
| application/control_visibility.rs | 단조 시간 기반 3초 비활동 숨김 정책, 입력·고정 상태에서 재표시 |
| infrastructure/browser + assets/episode-observer.js | DOM 관측과 제한된 IPC 수신, source URL과 실제 페이지 일치 검사, 정상 “바로 보기” 버튼 실행 |
| infrastructure/window_activity.rs | 활성 앱 창 안의 포인터 이동 관측. Windows API는 이 어댑터에만 둔다. 좌표는 저장하거나 외부로 전송하지 않는다. |
| presentation/episode_panel.rs | 우측 스크롤 목록·현재 선택·닫기·이전/다음 버튼·사용자 선택 처리 |
| presentation/chrome.rs | 입력과 재생 상태를 표시 정책에 전달하고 상하단/회차 패널 표시 여부 적용 |

회차 메시지의 본문 상한은 512,000바이트, 목록 상한 2,000개, 제목은 항목별 512바이트다. 기존 재생 메시지는 4,096바이트 상한을 유지한다. 등록되지 않은 외부 URL이나 임의 스크립트 명령을 IPC에서 실행하지 않는다.

## 사용자 동작

- 우측 회차 패널은 기본 열림. “회차 목록” 또는 P로 토글하고 패널의 “닫기”로 닫는다. 현재 회차는 선택 색상으로 표시한다.
- 작품 페이지에서 회차 선택 시 해당 `/e/` 페이지로 이동하고 관측이 일치한 뒤 정상 “바로 보기”를 한 번 실행한다. frame-host 이동 후에도 목록과 선택을 유지한다.
- 이전/다음화는 관측한 목록에 있는 이웃만 제공하며 경계에서 비활성화한다. 첫 항목에서 마지막으로 순환하지 않는다. 현재 항목은 실제 사이트 기준이며 재생 완료 자동 다음화는 이번 범위가 아니다.
- 전환 전에 mpv를 종료하고 미디어/시간 상태를 초기화한다. 네이티브 모드에서 선택했다면 새 소스·웹 길이 관측 후 mpv에 재연결한다. 기존 재생/일시정지 의도를 유지하고 새 회차는 0초에서 시작한다. 카탈로그에서 처음 선택할 때는 브라우저가 허용하면 재생을 시도한다.
- 브라우저 자동 재생 정책 또는 소스 오류가 있으면 원본 Play를 누를 수 있다. 직접 frame-host URL로 시작한 경우 작품 목록을 역추정하지 않고 작품/회차 페이지를 먼저 열라는 안내를 표시한다.
- 전체화면에서 재생 중 3초간 입력이 없으면 상하단 앱 컨트롤을 제거하고 중앙 영역을 확장한다. 마우스 이동·키 입력으로 재표시한다. 일시정지·연결 중·회차 패널 열림·주소 편집·진행바 드래그 상태는 표시를 유지한다.
- 자동숨김은 앱 컨트롤 대상이다. 웹사이트 자체 플레이어 스킨·뉴스 영역·커서는 별도 제거하지 않는다. 앱 컨트롤은 자식 WebView/mpv와 겹쳐 그리지 않고 별도 레이아웃 공간을 차지한다.

## 실제 앱 검증

광고 요청 차단을 계속 켜고 Windows 실제 앱을 Computer Use로 조작했다. [기계 판독 기록](../../../evidence/playback/episode-controls-2026-10-18.json)에는 원문 미디어 주소·헤더·본문을 넣지 않았다. 현재 표본은 “어떤 암부의 소녀공서 (2)” 작품의 1·2화다.

| 조작 | 관측 결과 |
|---|---|
| 작품 로드 | Rust 패널에 1·2화 두 항목, 현재 회차 없음 |
| 패널에서 1화 선택 | 현재 index=0, 정상 /e/→frame-host 이동, 웹 영상 진행. 첫 화 이전 버튼 비활성 |
| 1화 mpv 전환 | 앱 내부 영상·전체 길이 약 1420.002초 확인, 오류 없음 |
| 다음화 클릭 | index=1, 이전 mpv 종료 후 2화 정상 중개 링크로 이동, 네이티브 자동 재연결 및 51.139156초까지 진행. 마지막 다음화 버튼 비활성 |
| 이전화 클릭 | index=0으로 복귀, 네이티브 재연결 및 10.8489초까지 진행 |
| 네이티브 전체화면 | 패널 닫고 입력 없이 대기 후 상하단 앱 컨트롤 숨김, 영상 확장. P 입력으로 패널·컨트롤 재표시 및 열린 패널 동안 유지 |
| 웹 모드 전체화면 | 웹 복귀 후 재생 유지, 패널 닫고 대기 시 앱 컨트롤 숨김. Escape로 창 모드 및 컨트롤 복귀. 마지막 웹 시간 87.229786초 |
| 종료 | Alt+F4 정상 종료, 소유 mpv 잔존 없음 |

검증 실행의 누적 요청 차단 카운트 최대 12, 알려진 광고 영역 노출 최대 0, 관측 네이티브 오류 0이다. 사이트가 회차에 연결한 콘텐츠 자체의 저작물/회차 정합성을 전체 재생으로 확인한 것은 아니다. 1화 초반의 표시 제목이 다른 시리즈 제목처럼 보이는 프레임도 있어 제공 사이트의 소스 매핑 검토가 별도로 필요하다.

## 검증과 한계

`cargo fmt --check`, `cargo test` 10건, `cargo clippy --all-targets -- -D warnings`, `cargo build` 통과. 회귀 시험은 오래된 목록 거절·경계/페이지 전환, 외부 링크/초과 목록 거절, 비활동/입력/고정 상태 정책을 포함한다. 마지막 소스 변경은 카테고리 이동 시 대기 전환 취소와 입력 검증 시험 보강이며 실제 전환 실행 이후 빌드/테스트로 확인했다. 최종 바이너리의 20초 기동 시험도 정상 종료했고 WebView2 155.0.4283.60, page_finished=true, 요청 36건·차단 2건을 관측했다.

실제 마우스 이동에 의한 전체화면 복원은 코드에 연결했으나 이번 Computer Use에서 전체화면 좌표 입력이 창 bounds 오류로 거절되어 독립 검증하지 못했다. 키보드 복원과 웹/네이티브 숨김은 실제 확인했다.

다른 작품·종영·단일 극장판의 목록 DOM, 매우 긴 회차 목록, 정렬 변경, 빠른 연타/뒤로가기, 다중 DPI·모니터, 브라우저 자동 재생 거부 복구, 장시간 반복 전환은 후속이다. 늦게 도착하는 미디어 응답의 세대 식별도 남아 있다. 목록 스냅샷의 출처 일치 검사만으로 모든 미디어 콜백 경합을 해결했다고 주장하지 않는다.

후속: 마우스 복원과 전환 경합 수정의 최신 상태는 [전환 안정성 정본](../playback/sot-008-transition-reliability.md)을 따른다. 이 문서의 미검증 표시는 당시 관측 범위다.
