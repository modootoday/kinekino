# 단일 창 UI 구현·실행 검증

## 구현 계약

PotPlayer 공식 이미지에서 관측한 영상 중심 배치와 하단 진행선·재생 조작을 참고했다. 로고·스킨은 복제하지 않는다. Rust egui 셸은 중성 어두운 배경과 금색 선택 상태를 사용한다. 상단은 범주·주소·광고 차단 상태, 중앙은 웹 또는 네이티브 영상, 하단은 전체 폭 진행바·재생/일시정지·-10/+30초·현재/전체 시간·웹/mpv·볼륨·전체화면·상태다.

- `infrastructure/video_surface.rs`가 앱의 자식 HWND를 소유한다. mpv는 `--wid`로 이 자식에 출력하며 별도 최상위 영상 창을 만들지 않는다. UI는 Win32 API를 직접 호출하지 않는다.
- `infrastructure/mpv`는 프로세스와 비동기 IPC만 담당한다. 기존 HLS 검증·프로토콜 제한·Referer 전달·로그 비노출 정책을 유지한다. mpv OSC와 자체 입력은 끄고 Rust 컨트롤이 명령을 보낸다.
- `presentation/transport.rs`는 컨트롤 렌더링과 사용자 입력을 분리한다. 진행바는 드래그 중 임시 위치를 유지하고 놓을 때 한 번 `absolute+exact` 탐색을 전송한다.
- `browser.control`과 `assets/media-control.js`는 허용된 iframe에 제한된 재생·일시정지·시간·볼륨 명령을 전달한다. 임의 스크립트를 페이지 메시지에서 실행하지 않는다.
- 웹→mpv: 현재 웹 위치와 앱 볼륨으로 시작한다. 준비 중 mpv는 음소거하며 웹 재생을 유지한다. 기존 전체 길이·영상·시간 검증이 성공하면 웹을 정지하고 숨기며 mpv의 일시정지 상태를 원래 웹 상태에 맞추고 음소거를 해제한다.
- mpv→웹: 마지막 관측 위치·일시정지·앱 볼륨을 웹에 전달하고 mpv를 종료한다. 브라우저 자동 재생 정책에 걸리면 사용자가 원본 Play를 누를 수 있다. 실패 시에도 웹으로 복귀한다. 인증·토큰 만료 해결을 보장하는 기능은 아니다.
- 전체화면은 mpv 속성이 아니라 eframe 앱 창 자체에 적용한다. 영상 영역과 WebView bounds가 새 중앙 영역에 맞춰 갱신된다. 자동 숨김은 아직 없다.
- 네이티브 영상 자식은 렌더 전용이며 포커스를 Rust 부모로 돌린다. 단축키는 위젯보다 먼저 처리하고 주소 입력 포커스일 때는 가로채지 않는다. 구현된 키는 Space, 좌/우 ±5초, Escape 전체화면 해제다. 웹 내부 포커스의 키는 원본 사이트가 처리할 수 있다.
- 종료·범주 이동 시 mpv를 먼저 정리하고 영상 HWND를 해제한다. mpv 프로세스는 필드 선언 순서상 영상 호스트보다 먼저 Drop된다.

공식 근거: [mpv --wid](https://mpv.io/manual/master/#options-wid)는 Windows HWND를 부모로 삼고 그 크기에 영상을 맞추는 방식을 명시한다. 기존 [PotPlayer 조사](../../player/presentation/viewing/sot-004-player-ux.md)를 디자인 근거로 사용했다.

## 실제 검증 관측

Windows 실제 빌드와 WebView2, 기존 작업 폴더 mpv를 사용했다. 광고 차단 체크는 계속 켠 상태였다. Computer Use로 실제 창을 조작하고 JSON IPC 및 웹 상태와 함께 확인했다. [기계 판독 요약](../../../evidence/playback/integrated-ui-2026-10-18.json)은 서명 URL·헤더·본문을 포함하지 않는다.

## 검증 중 수정한 문제

1. 별도 mpv 창: 전용 자식 HWND와 `--wid`로 같은 창에 영상 출력.
2. 전환 시 처음부터 재생: 웹 위치를 `--start`로 전달하고 역전환 시 웹 currentTime 복원.
3. 두 엔진 동시 소리 가능성: 네이티브는 준비 중 mute, 검증 후 웹 pause와 네이티브 unmute.
4. 진행바 드래그 값이 매 프레임 관측값으로 덮이는 문제: 임시 scrub 위치를 유지하고 release에서 탐색.
5. 네이티브 자식 창 포커스 및 egui 버튼의 Space 소비: 렌더 전용 자식/부모 포커스와 UI 렌더 전 단축키 처리를 적용. 주소 텍스트 입력은 제외. 최종 실행에서 Space와 Escape 재현 통과.
6. 웹 상태 설명과 네이티브 모드 혼동: 별도 고정 WEB/MPV 상태 배지를 추가.

## 검증 한계·남은 작업

이번 실행은 위 표본과 조작의 관측이다. 세 표본 전체를 최종 바이너리로 다시 장시간 시험한 결과로 표현하지 않는다. 종전 세 카테고리 30초 이상 엔진 재생 검증은 [이전 기록](../playback/sot-005-playback-validation.md)을 따른다.

- 100/150/200% DPI·다중 모니터·최소 창 크기·다양한 GPU 조합 전체 회귀는 미검증이다. 실제 기본 창과 전체화면/복귀만 확인했다.
- 수백 회 반복 전환·장시간 재생·디코더 실패 주입·자동 재생 거부 복구·인증 만료는 별도 시험이 필요하다.
- 물리 스피커 청취는 수행하지 않았다. 오디오 채널과 볼륨 속성만 확인했다.
- 회차 패널·이전/다음화·정지·음소거·속도·자막/화질 선택·완전한 목표 키맵·전체화면 자동 숨김·Rust 카탈로그·이어보기는 후속 범위다.
- WebView 전체 페이지는 호환 모드에서 유지된다. 네이티브 모드는 영상만 표시한다. 웹 모드까지 원본 페이지의 모든 비영상 영역을 제거한 전용 스킨은 후속이다.

검증 명령: `cargo fmt --check`, `cargo test`(7건), `cargo clippy --all-targets -- -D warnings`, `cargo build`. 최종 결과는 모두 통과했다.
