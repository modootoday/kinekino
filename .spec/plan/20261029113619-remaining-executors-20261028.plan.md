## 다음 구현 배정

첫 구현은 모델/네트워크 없이 기존 renderer를 재사용하는 전체 카드 제작 경로다. review PNG를 export_cards 별칭으로 연결하지 않는다. CardDocument는 proposal의 원 raw/accepted target을 수정하지 않는 편집 revision이며 카드 순서·역할·front/back·인용/요약 구별·cue 근거·프레임 identity·canvas/template pin·게시문/alt 초안·프로젝트를 함께 보존한다. 플랫폼 규격을 임의 최신값으로 만들지 않고 명시 preset을 사용한다. glyph/overflow 미측정은 자동 품질 승인으로 바꾸지 않는다.

1. domain의 CardDocument와 편집 revision/undo 규칙을 먼저 고정한다. add/duplicate/delete/reorder/text/frame/canvas 변경을 동일한 정책으로 처리하고 잘못된 참조·중복 ID·stale revision·한도를 거절한다. 기존 ProposalPayload의 카드 내용/근거를 재사용하며 별도 AI 원본 저장소를 만들지 않는다.
2. application은 고정 document/asset/template에서 준비된 묶음 입력을 만들고 기존 JobService→PreparedJobInput→명시 executor를 사용한다. raw JSON/CLI가 임의 executable/filtergraph/프로세스 권한을 공급하지 않는다. 미구현 renderer 기능은 Unsupported/NeedsInput으로 명시한다.
3. infrastructure는 원 Card renderer와 공통 자산을 소비해 각 PNG와 텍스트/프로젝트/manifest를 검증한다. staging을 완료물로 노출하지 않고 새 출력에 no-overwrite 발행한다. 취소 시 원 owned worker·임시 산출물을 보유한 채 정리 판정하며 receipt 실패를 성공으로 덮지 않는다.
4. 공통 typed SDK·schema·capabilities·CLI·jobs 등록을 함께 연결하고 TI 범주별 실제 증거를 남긴다. 일부 구현만으로 supported 또는 전체 CLI 인수를 선언하지 않는다. 정상 묶음/충돌·취소·실패 후 재조회·성공 항목 보존/실패만 재시도·원본 불변을 실제 확인한다.
