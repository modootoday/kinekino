# Cached VAD 제품 SDK/CLI 첫 수직기능

status: active — source-only 제안, 구현/operation 등록/제품 지원 미완료.

P0의 exact module·공개 타입 후보와 검토 기록/실행 admission 분리는 [profile admission 상세](vad-profile-admission-contract-2026-10-21.md)를 따른다. 공통 jobs API 변경은 SDK와 별도 조율한다.

2026-10-21 후속 중앙 배정으로 P0 원 exact10을 `runtime/development/media-vad-p0-r1/packages/media-vad` overlay에 구현했다. 원 계획의 추가 artifact/runtime/admission 모듈 책임은 profile.rs와 ports/analyze.rs에 배치해10경로를 유지했다. before신규부재10·source10 SHA `B79C4C47616BB4432A2C079452D36C0FF6EEA04F88E418354B4AEAB98674D880`·직접fmt0·HANDOFF는 `runtime/coordination/media-vad-p0-r1/`에 있다. 회귀9 작성/실행0, Cargo0이며 제품 지원/등록0이다. 초기 ‘구현 없음’ 표현은 source 후보 작성으로 갱신하며 compile/SDK 인수와 구별한다.

## Outcome

기존 jobs host에서 명시 등록한 VAD operation을 공통 Rust SDK와 player-cli로 제출·조회·취소하고 immutable 결과를 얻는다. GUI는 범위 밖이다. private spike 정상1/취소1을 제품 지원으로 승격하지 않는다. [기존 gate](cached-vad-first-gate-2026-10-21.md)의 후속 제품화이며 실험 gate를 대체하지 않는다.

## Phases

1. **P0 계약 source 후보.** 신규 `packages/media-vad/`의 Cargo.toml, src/lib.rs, domain/{mod,profile,input,result}.rs, application/{mod,ports,analyze}.rs, tests/contract.rs를 제안한다. domain에는 model profile ID·불변 revision/weight SHA/bytes·FP32·입력 mono16k PCM16/range·chunk score/result만 둔다. application에는 ModelArtifactReader, AudioArtifactReader, VadEngine, AttemptEvidenceSink 포트를 두고 task 정책·pin 검증·partial 비성공을 담당한다. 외부 path/argv/ORT 타입은 공개 domain에 없다. 완료 조건은 SDK와 DTO/error/identity/diagnostics 합의 및 source 목록 pin이며 컴파일 완료가 아니다.
2. **P1 명시 infrastructure 후보.** 같은 package의 infrastructure/{mod,job_executor,artifact_reader,output_publication,attempt_evidence}.rs와 별도 `packages/vad-ort-adapter/`의 src/{lib,session,wav,process_protocol}.rs 및 src/bin/vad-worker.rs를 제안한다. ORT adapter만 ort/hound/외부 runtime을 의존하고 원 owned-process supervisor로 worker를 소유한다. 자동 download/copy feature를 제품 기본값에 넣지 않는다. 설치된 엔진/profile manifest를 검증하며 D:/runtime·C:/cache 절대경로 및 private tool import0이다. CPU EP/intra2/inter1은 명시 profile 옵션이고 runtime 실측과 구별한다. ORT 정적/동적 및 DirectML 링크 전략은 배포 closure 확인 전 확정하지 않는다. 완료 조건은 공개 필수 소스·테스트·Cargo dependency/license 목록과 runtime 제외 경계의 PM 인수다.
3. **P2 jobs 접합 후보.** 기존 JobExecutor에 VAD adapter를 구현하며 proposed operation은 `audio.vad`다. source blob에는 안전한 immutable binary descriptor만 저장한다. execution identity는 SDK가 기존 원 job/attempt/request SHA에서 전달한다. staging→원 cleanup→reserve_publication→no-overwrite write→begin_verification→hash/bytes 재확인→VerifiedJobOutput 순서다. 부분·취소·stale 결과는 성공 output0이고 diagnostic artifact는 별도다. SDK 소유 후보는 media-jobs ports/worker의 최소 context 및 diagnostic 계약, root infrastructure/jobs와 browser_provider_jobs의 실제 registry wiring, root Cargo/lock이다. schema/help 문자열만 추가하지 않는다. 완료 조건은 fixture normal/cancel/race/stale/profile mismatch/recovery/cleanup failure 보존과 공개 API 인수다.
4. **P3 중앙 실행 gate.** 새 배정 뒤 Cargo fmt/test/clippy와 실제 동일 SDK/CLI submit/get/watch/cancel·실제 결과 hash/pin·원 process cleanup을 검증한다. 고정 모델/input만 사용하고 download0을 유지한다. registry capability가 operation을 실제 열거하고 actual CLI normal/cancel 근거가 생기기 전 지원=false다. GUI 기능/시각 인수는 이 단계의 대체 증거가 아니다.

## Rollback

P0/P1은 별도 신규 source 후보로 준비하고 공통 registry에 연결하지 않는다. 실패 후보는 원 pins와 원인을 보존한다. P2는 AI 등록/조립만 되돌려 기존 subtitle/provider operation을 유지하며 immutable 기존 output을 삭제하지 않는다. P3 실패는 원 receipt/raw/cleanup을 보존하고 capability를 미지원으로 유지한다. 이미 공개된 파일·실행 artifact는 덮어쓰지 않는다. 공유 index는 PM만 변경한다.
