# JOB 선택 작업 상세 읽기 소비자

후속 자동 gate에서 PM 배정 아래 최소 compile/fixture 수리를 포함한 최종23-r5를 검증했다. JOB6 모두 및 선택 전체138이 동일 최종 BIN에서 통과했다. 아래 source-only 상태·핀은 작성 당시 이력이다. [실제 검증 정본](../../../sots/verification/presentation/union22-sdk-connection-2026-10-23.md)에 최종 입력·수리·근거를 구분했다. root 채택/기본 JOB route 연결/시각 인수 완료를 의미하지 않는다.

## 계약과 범위

[공통 작업 조회 계약](../../../sots/player/presentation/shared/job-inspection.md)과 [SDK/CLI 실제 검증](../../../sots/verification/application/jobs-2026-10-19.md)을 근거로 기존 ApplicationClient::get_job, GetJob, JobRecord를 소비한다. 기존 async_sdk_port::SdkPort, TypedAsyncSdkPlugin, AsyncSdkPump를 재사용하며 새 worker나 작업 정책은 만들지 않는다. 읽기 전용 실제 JobService와 기본 Unsupported 모두 보존한다.

MountedJobDetails::mount는 소유한 ExecutionAttachment, 고정된 GetJob, RequestContext, 공통 DocumentOptions/CSS/VerifiedAssets를 받는다. 선택 ID는 host가 고정하고 renderer에서 임의로 바꿀 수 없다. 실제 Meari 모듈 파서와 NativeDocumentHandle을 사용하는 opt-in 패널이다. 기본 StudioApplication 라우트에는 아직 연결하지 않았다.

기존 공통 Button/InformationNotice 및 aw-* 토큰을 사용한다. 신규 폰트·아이콘·제품 자산은 추가하지 않는다. JOB-05a의 선택 상세 및 JOB-05b 오류/결과 표시에 해당하는 데이터 소비 후보이며 전체 JOB 화면이나 단계 stepper 완성을 의미하지 않는다. 목록·watch·작업 취소·작업 재시도·폴더 열기·단계 이력은 연결하지 않는다. 실제 공급되지 않는 진행률·ETA는 —로 표시한다.

## 상태와 수명

미조회, 로딩, 결과, 오류, 이전 결과 보존을 구별한다. SDK JobRecord::validate를 재사용하고 선택 ID와 이전 revision보다 오래된 결과를 UI에서 거절한다. revision/attempt/state/operation/source SHA·크기/parameters/output 경로·SHA·크기/failure·remediation은 실제 DTO에서만 얻는다.

동시에 한 조회만 허용한다. callback batch가 끝난 뒤 poll과 props/callback 교체를 원자적으로 수행한다. ACK/consumer 실패는 원 terminal과 pending을 보존하고 명시적인 결과 인수 재시도만 허용한다. 이것은 jobs.retry가 아니다. close는 먼저 열린 document의 버튼을 비활성화하고 binding을 회수한다. 부모 document가 이미 닫히는 중이면 DOM 갱신 없이 조회 drain을 진행한다. query 취소는 jobs.cancel과 구별한다. 원 owner/attachment를 보존하고 pending drain 뒤 해제하며 부모 worker/window 종료를 주장하지 않는다.
