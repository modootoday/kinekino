# AI 단계 재개와 하드웨어 예산

사용자의 2026-10-21 AI보류해제·현재하드웨어배분 지시를 따른다. [순간 관측](../../../sots/verification/runtime/host-resource-allocation-2026-10-21.md)은 i9-9900KF 8C16T/RAM63.93가용27.27GiB/RTX2070S8GiB가용5747MiB/C가용17.65·D190.60GiB다. 품질승인·GPU호환검증과 구별한다.

## 배분

| 작업 | 초기 예산/동시성 |
|---|---|
| SDK/UI/Meari/AI의 소스·문서·입출력 작업 | 담당별 병렬, 공유소스 lease·원핀 유지 |
| Rust build/link/대형시험 | 기존단일 owner·conservative2/2논리CPU/BelowNormal/-j1 유지 |
| 첫 AI 실측 | 단일worker·CPU2thread·BelowNormal·RAM4GiB 이내 목표, 짧은 입력 한 건 |
| GPU AI | 현재제품GPU실측 전이므로 첫짧은독립gate부터. 초기VRAM2GiB 이내 목표·batch1·model1·실재생/다른GPU AI와동시0 |
| 사용자 앱·OS·재생 여유 | 가용RAM16GiB와가용VRAM3GiB를 다음작업진입 기준으로 확보 |
| 모델/새AI캐시 | 기존pin캐시 우선·새경로D:한정·신규다운로드1개씩·C:신규모델/coldAI target0 |

RAM/VRAM 값은 실행 진입·관측 예산이며 아직 모든 외부엔진에 강제 한도가 구현됐다는 뜻이 아니다. 실제 어댑터의 affinity/threads·owned Job·peak 수집·협력취소 지원을 확인하고 적용한 설정/실패를 증거에 남긴다. GPU사용률의 강제 percentage 제한을 약속하지 않는다.

완료 peak 조회를 위한 query-only Job 핸들도 Job 수명에 영향을 준다. 독립 probe가 원 owner보다 오래 살아 마지막 핸들 close를 지연시키면 기존 KILL_ON_JOB_CLOSE 정리가 달라질 수 있다. 첫 VAD 어댑터는 probe를 원 owner 수명에 결속하거나 모든 실패·Incomplete·panic 경로에서 probe가 먼저 닫히는 타입 구조를 검증한다. 제어 권한 부재를 수명 영향 부재로 취급하지 않는다. Complete의 원 child exit/familyEmpty 확인과 메모리 조회 성공은 별개 증거다.

현재 CPU-only 모델경로와 기존runner first_two를 그대로 두면서 검증 없이 다른core mask를 적용하지 않는다. 첫CPU추론은 무거운빌드/link와 교대로 중앙슬롯에서 실행한다. GPU경로가 짧은실측으로확인되고 각peak/반응성/가용기준을 만족하면 CPU빌드+GPU AI의 제한병행을 별도배정한다. 코드병렬과 compute병렬을 구별한다.

새 단계 진입 전 가용RAM<16GiB/VRAM<3GiB/C:<12GiB 또는 사용자반응성저하가관측되면 신규AI/다운로드 admission을 대기시키고 소스구현을계속한다. 실행중원owner/오류/종료는협력취소·기존정리계약을따르며 사용자앱·ChatGPT·Terminal·WSL/VM을종료하지않는다. 기존C:sharedcache는활성검증중이므로이동/삭제하지않는다. 전역환경변수/보안제외변경0이다.

## 단계

1. 미디어·검증 담당이 기존23역할/모델실험과 HF revision/license/precision·기존Rust실행명령/실행파일·입출력계약을 한정경로에서 재확인한다. 전체모델재다운로드/전수재실측0. 실제AI가제품에연결됐다고표시하지않는다.
2. 기존저메모리 ASR/VAD 또는 embedding/소형텍스트경로 중 입력30초/한건·텍스트512–1024token/출력256token 이하 등 작은 재현gate를 제안한다. 수치는실측profile이며 제품의최종기능한도가아니다. 품질미달모델을실행가능만으로채택하지않는다.
3. PM이 pin·실행파일·자원제어·입력·원ownedprocess/취소·출력검증을 인수한 작업부터 단일worker로 실측한다. 처음부터23개·대형alignment/3D를동시에실행하지않는다. 과거ForcedAligner7435804672B peak는이번4GiB예산밖이므로그경로를그대로시작하지않는다.
4. ASR/화자분리·음악/OPED·시각/asset은필요한제품IO를병렬구현하고 실추론은예산내에서단계배정한다. GPU모델1개/배치1을기본으로peak와회수확인후다음모델로간다.
5. 사람의결과비교·수정·명시채택/품질승인은 제품연결뒤에진행한다. 기존23실험·품질승인0을새제품승인으로바꾸지않는다.

AI전체보류는해제됐다. 단일worker·작업별중앙배정은계속유지하며 Pages/VM/DPI/새장시간시험/수동GUI검토보류는이번지시로해제하지않는다.
