## 일정 판단

실행 파일은 이미 생성됐으나 실제 제품 완료 날짜는 현재 확정할 수 없다. 이전 12시간 검토 빌드 목표를 전체 제품 납기로 승계하지 않는다. CLI 신규5명령의 실제 연결과 기능별 인수 분모를 고정한 뒤, 남은 구현 규모와 실제 처리 시간을 근거로 검토 빌드 일정을 갱신한다. 전체 제품 날짜는 CLI 인수와 GUI/AI 검토 준비 상태를 함께 보아 산정한다. 사용자 품질 승인 전 개발자가 승인 완료를 대리하지 않는다.

## 중앙 PM 다음 실행 순서

1. F1: 기존 ReviewStore가 반환한 ReviewSession을 출판까지 보유하는 CaseResolver를 연결한다. package/item/source_request SHA의 정확한 membership을 검증하고 원 요청 JSON 내부 임의 경로를 열지 않는다.
2. 기존 미디어 custody의 식별·보유 계약을 조사해 MediaResolver를 연결한다. 별도 registry를 임의로 만들지 않으며 decode/PTS 근거 없이 Verified를 반환하지 않는다.
3. 프로세스 경계 복구·경합을 검증하고 SDK/DTO/schema/capability와 신규 CLI5명령을 함께 연결한다.
4. 전체 기능의 CLI 인수표를 명령×host×성공/오류/취소/저장으로 고정한다. 미지원·미구현·미검증을 구분하고 최신 입력에서 통합 회귀와 정상 bins를 다시 확인한다.
5. 공통 SDK 기능 인수 뒤 GUI 결과 비교/수정/판정/이력과 승인 시안 비교를 수행한다. 기존 수동 GUI·추론·다운로드 보류를 이 문서로 해제하지 않는다.

현재 실제 다음 연결점: application/model_review의 ReviewStore::open은 전체 package/assets를 검증하고 ReviewSession으로 원 파일 guard를 유지한다. review_source::CaseLease는 그 세션을 소유할 수 있으므로 기존 custody 보장을 재사용한다. 이 연결 설계 확인은 구현/시험 완료가 아니다.
