# 도구 기능 승격과 담당별 인수 계획

상태: 2026-10-19 **리서치 후속·미실행**. 실제 인벤토리는 tools 직계24개, packages4개다. [조사 정본](../../sots/architecture/tools-package-promotion-research-2026-10-19.md)의 전체 분류와 근거를 따른다. 서브에이전트는 이 문서까지만 작성하며 실제 구현·검사는 desktop 담당이 수행한다. [중앙 조율](../player/session-coordination.md)의 API/SDK/UI 우선·신규 AI 실측 후순위와 공유 파일 lease/검사 슬롯을 지킨다.

PM이 이 표와 정본을 각 담당 세션에 전달한다. 조사 서브에이전트가 desktop 세션을 직접 메시징하거나 공유 Cargo/source를 변경하지 않는다.

## 순서와 검증 게이트

1. **현재 제품 검사 완료**: media-contracts/publication/subtitles 체크포인트와 SDK projects/UI 실제 검증을 먼저 보호한다. 조사 후보를 전부 루트 workspace members에 등록하지 않는다.
2. **첫 재사용 kernel 선정**: AI 연구는 실제 2개 path 소비자가 있는 diarization metrics를 우선 제안하고 SDK는 boundary evidence·review artifact 정본 결합을 검토한다. 실제 제품 구현을 막는 분리를 먼저 강제하지 않는다. 한 단계의 이동표·public API·owner·license·dependency DAG를 ADR로 제안한다.
3. **pure contract를 private package로 분리**: source/build manifest와 기존 lock/bin/fixture raw를 고정한다. CLI는 parse→library usecase→명시 출력 adapter만 담당한다. 고정 모델/cohort/path를 generic default로 몰래 바꾸지 않는다. package name/version과 wire/artifact schema version을 분리한다.
4. **기존 소비자 보호**: DER/JER reference와 model-spike/jer-function path dependency, boundary CLI/examples, review export/제품 SDK를 모두 대조한다. 기존 import compatibility가 필요하면 명시 re-export를 유지한다. handler가 SDK를 역참조해 crate 순환을 만들지 않게 한다.
5. **각 변경 freeze에서 검사**: Rust fmt/test/clippy all-targets-Dwarnings, wrapper actual CLI와 파일/nooverwrite/실패 원문, typed 반환·JSON오류·artifact hash 비교를 보존한다. float/grid 변경은 허용 tolerance와 원본 IEEE 값으로 검증한다. 최초 실패를 삭제하지 않는다. 검사 자원은 PM 슬롯에서 배정한다.
6. **선택 제품 연결**: library 승격과 기능 지원 추가를 별도로 승인·구현한다. ApplicationClient 공통 usecase, GUI/CLI discovery·schema·unsupported, job/cancel/deadline/source revision·재시작을 동일 의미로 연결한다. 사용자 직접 조작 가능한 UI에서 저장·오류·명시채택을 확인한다.
7. **모델 adapter 후속**: Qwen/ORT/Candle/embedding은 frozen revision·정밀도·variant·license·runtime artifact와 bounded port 계약을 검증한 후 검토한다. 실제 추론/성능/품질 검토는 제품 준비 이후이며 이번 리서치로 예약하지 않는다.

## 승격하지 않고 보존할 대상

- forced-aligner baseline/repair/observation/segmentation/encoder/head reference는 서로 다른 실험 역할이다. 공통 TensorRecord를 추출해도 대조군·결과·producer source·컴파일 evidence를 병합하거나 기존 source를 덮어쓰지 않는다.
- validation의 driver/VM cleanup/DPI·관리자 시스템 조작은 일반 product library와 격리한다. read-only resource sample을 재사용해도 사용자 앱 종료·전체 시스템 최적화를 끌어오지 않는다.
- spec-maintenance의 repository 경로 mapping/링크 예외, engine-lab의 source patch/build profile, tokenizer의 특정 token-ID/fixed model audit는 tools 책임이다.
- model-review-bundle historical viewer DTO와 현역 제품 review DTO를 새 독립 정본 둘로 만들지 않는다. 과거 artifact reader와 새 writer는 명시 schema adapter로 연결한다.
- native-ui-workbench는 초기 catalog scaffold이며 실제 Meari와 중복 여부 결정 전 별도 runtime package로 승격하지 않는다.

## 호환·배포·복구

24개 manifest의 license 필드가 없다는 사실을 해결하지 않은 채 외부 publish하지 않는다. native DLL·CPython/Perl oracle·ONNX runtime·dictionary·HF model license는 package Rust license와 별개다. 모든 원본 notice와 source/runtime/model pin을 보존한다. 새 core는 engine/GUI/OS 자료형을 숨기고 typed 최소 오류를 노출하며, 도구-specific raw failure는 진단 artifact로 남긴다.

이동 전후 파일 대응표와 source/bin/lock/artifact SHA를 보존한다. re-export와 CLI 명령은 검증 전 제거하지 않는다. 실패 시 담당 단계만 복구하며 다른 담당 변경/원시 evidence를 reset·삭제하지 않는다. Git commit/push·.gitignore 공개범위 변경·대량 workspace 평탄화는 이 계획에 포함하지 않는다.

완료 기준은 폴더 존재가 아니라 재사용 소비자·thin CLI·공개 계약·실제 검증·정본의 일치다. 이번 조사에서 해당 인수 gate는 실행하지 않았고 현재 도구의 품질이나 배포 완료를 새로 인증하지 않았다.

관측 갱신: SDK가 model-review-bundle와 visual-review의 별도 workspace 선언을 추가한 상태를 09:29 재확인했다. 해당 수정은 기존 root 추출 검사 오류의 복구이며 이 도구 승격 계획의 실행이 아니다. 이후 담당은 초기 manifest 사본 대신 현재 source를 다시 확인한다.
