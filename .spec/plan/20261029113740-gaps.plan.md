# 설계 공백·미연결·미검증 분리

2026-10-26 초기 조사. [추적표](requirements.md)의 G ID는 이 문서를 가리킨다. **계약 공백**은 구현자가 임의 정책을 결정해야 하는 상태, **미연결**은 기존 기능의 필요한 host/consumer 연결 미완료, **실행 미검증**은 시험/설정 존재와 별개다. 아래 항목 전체를 새 결함이나 전체 기능 부재로 단정하지 않는다.

후속 산출물: G03의 [host/명령/context](../../../sots/player/application/api/host-support-boundaries.md), G04~G05의 [실행/저장](../../../sots/player/application/execution-storage-boundaries.md), G07의 [association/draft](../../../sots/player/application/api/review-source-draft-contract.md)를 작성했다. contract 기준선 단계이며 모든 기능의 closure나 제품 검증 완료를 뜻하지 않는다. 아래 조사 질문은 이 문서와 개별 기능 인수표를 대조하며 닫는다.

추가: G06/G08/G09는 [task 통합](../../../sots/player/application/production/task-integration-contract.md), G10~G12/G14는 [UI/Meari 인수](../../../sots/player/presentation/shared/product-integration-acceptance.md), G13/G15는 [배포·신뢰](../../../sots/player/architecture/release-and-trust-boundaries.md), 전체 의존성은 [실행 순서](implementation-order.md)로 구체화했다. 표의 실제 구현/검증 미완료는 유지하며 계약 closure는 별도 감사에서 판정한다. 문서 자동 링크 검사는 offline tool 의존성 부재로 미실행이다.

최종 대조 기준: 이어보기/설정은 [VP 계약](../../../sots/player/application/viewing-preferences-and-resume.md)에 구체화했다. 후속 문서 링크 검증은 private std-only Rust 도구의 명시 문서 범위로 진행했다. 기존 spec-maintenance 실패는 보존하며 scoped 검사와 기존 링크의 수동 heading 대조 결과는 [완료 감사](completion-audit.md)에 기록한다. 아래 공백 표의 구현·실행 질문은 이행 항목으로 유지하고, 설계상 해결 여부는 별도 감사가 판정한다.

## 다음 작업 순서와 종료 산출물

1. **정본 충돌 최소 정정(G02)**: 직접 확인한 identity/bin·production partial 구현을 고친다. 최신 우선 기록은 현재 인계/호스트로 연결하고 원 감사·receipt는 수정하지 않는다.
2. **노출/수명/저장 기준선(G03~G05)**: 기존 SDK/API/CLI 및 owned execution의 정확한 caller/조건을 기능별 정본에 연결한다. 현재 이름만 있는 operation은 Unsupported/미확인으로 분리한다.
3. **Media와 제작 계약(G06~G09)**: 기존 소유 구현을 재사용하는 caller 조사 뒤 durable association/draft 차이, operation별 입력/출력/취소/복구·PTS·model admission을 확정한다.
4. **UI/Meari 통합 경계(G10~G12/G15)**: 기존 승인 화면과 상태별 typed contract·Router/plugin 표를 정밀 대조한다. 제품 정책을 compiler/router/plugin 본체나 TSX에 복제하지 않는다.
5. **추적 closure와 설계 판정(G13/G14/G16)**: 구현 순서·의존성·각 인수 gate·잔여 사용자 결정·보류를 보고한다. 필요하면 최소 Rust 자동 검사를 별도 배정하며 source375 제품 gate와 구분한다.

단계1~5 설계 산출물이 실제로 작성·대조된 후 goal 완료를 검토한다. 현재 goal은 active, 이번 산출물은 단계0 초기 추적/공백이다. 코드 구현·전체190·정상 bins·GUI·사용자 품질 검토의 미완료는 최종 보고에도 유지한다. 불명확한 외부 상태를 가정해 닫지 않는다. 실제 근거가 부족해도 읽기/문서 작업을 계속하며 자원 대기를 설계 전체 차단으로 쓰지 않는다.
