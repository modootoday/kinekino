# 담당 세션 목표 상태와 작업 지속

2026-10-21 후속 사용자 요청에 따른 중앙 PM의 능동 모니터링·역할 재배분·완성 속도 운영 목표는 [PM 운영 목표](pm-operating-goal.md)로 보강했다. 기존 goal active 및 전체 범위는 유지한다. 제공 도구의 본문 편집 기능 부재를 재확인했으므로 시스템 objective 변경 성공으로 표시하지 않는다.

2026-10-21 사용자 요청으로 PM이 공식 문서와 현재 도구 계약을 조사했다. [OpenAI Goals 안내](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)는 사용자 `/goal resume`·`/goal clear`를 설명하고 재개·삭제 전이는 사용자 또는 시스템이 제어한다고 명시한다. 특정 Desktop blocked 상태가 영구 복구 불가능하다는 근거는 확인하지 못했다.

현재 에이전트 도구는 get/create/update이며 resume/clear는 없다. create는 미완료 목표가 있으면 실패한다. 기존 blocked를 완료로 위장해 새 목표를 만들거나 같은 생성 요청을 반복하지 않는다. UI 표시와 서버 상태의 불일치는 실제 오류로 기록하고, 복구됐다고 추정하지 않는다. 서버 저장소·앱 DB를 직접 수정하지 않는다.

목표 저장 문제와 구현 가능 여부를 분리한다. 담당은 get_goal로 상태를 한 번 확인해 PM에 보고하고, PM의 명시 작업 메시지를 받아 허가된 구현·검증 준비·인계까지 수행한다. heavy 슬롯 대기나 다른 담당 리뷰 대기는 전체 목표 blocked의 근거가 아니다. 자동 continuation 복구는 실제 active 상태로 확인하기 전 주장하지 않는다. 사용자 재개가 필요한 경우 해당 세션·원 상태·정확 오류와 사용자 제어 방법을 구체적으로 제시한다.

이번 조사 직전 SDK와 Meari는 idle, UI와 Media는 active였다. PM 목표는 get_goal에서 active였다. PM은 네 담당 모두에게 조사 결과와 역할별 구체 작업을 전송해 SDK 진단1/validation9, UI 원 검증61, AI 자원 source13, Meari 실제 V2b 통합 읽기 검토를 배정했다. 메시지 전달 성공은 자동 목표 재개 성공과 구별한다.

## 담당이 반환한 원 상태

| 담당 | get_goal 관측 | 현재 작업과의 구별 |
|---|---|---|
| 중앙 PM | active | 전체 조율 목표 유지 |
| SDK | blocked, tokens7091396/time58721s | 이전 create 오류는 미완료 목표 존재. 명시 진단1/validation9 작업은 재개했고 목표 복구로 표시하지 않음 |
| 미디어·AI | blocked, updatedAt1792481417, tokens1982873/time12873s | 저장 objective에 과거 model-review 연결·추론보류 문구가 남음. 최신 사용자 AI 재개와 source13 배정이 현재 작업 기준이며 오래된 목표로 새 지시를 취소하지 않음 |
| UI | blocked, updatedAt1792470757, tokens2073712/time14595s | 명시 V2b strict/fmt와 후속 시험은 계속 진행, 목표 전이 시도0 |
| Meari | blocked, 기존 Q01~Q09 원 objective 반환·조회 오류0 | 명시 V2b 통합 읽기 검토와 문서 인계 완료, 목표 상태 변경0 |

`get_goal` 조회 성공과 목표가 active인 것은 다르다. SDK·AI의 blocked 상태는 이번 조사에서 복구하지 못했으며 현재 메시지로 실행 중인 작업과 분리해 추적한다.

## 사용자 active 전환 뒤 재확인

사용자가 모든 목표를 직접 active로 전환했다. 담당별 재조회는 SDK updatedAt1792540087, Meari 원 Q01~Q09, AI updatedAt1792540098, UI updatedAt1792540106 모두 active를 확인했다. 위 blocked 표는 이전 관측이다. 자동 목표가 복구됐다고 추정한 것이 아니라 각 담당 get_goal 응답에 근거한다.

다만 제공 도구의 update_goal은 상태 세 종류만 받고 objective 편집 인자가 없다. create_goal은 기존 미완료 목표에 중복 사용할 수 없다. 목표 본문 갱신 성공은 주장하지 않으며 원 전체 objective를 보존한다. 담당은 현재 역할과 최신 사용자 지시를 반영한 목표 제안문·현재 계획을 기록하고 active 목표로 구현/검증을 계속한다. AI의 과거 전면보류 문구는 최신 사용자 단일worker 단계 재개 지시를 대체하지 않는다.
