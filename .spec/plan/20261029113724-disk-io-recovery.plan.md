## Before heavy work resumes

in application/execution_admission.rs returns after affinity selection without
the Resources snapshot intervals used by build4. Its Job limits only affinity
and priority class; neither profile has a disk rate limit. Existing per-command
manual RAM/GPU/free-space checks do not imply runtime I/O control. No code change
or test execution was performed to make this observation.

I/O priority versus Job I/O rate control, inheritance/privilege/support limits,
bounded counters, runtime cancellation and original owner retention. The agent

implementation. Findings must be reviewed before assigning any Rust change or
resource validation; research alone is not a working throttle.

Rust design, not an implemented or verified resource controller.
