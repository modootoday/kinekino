# 중앙 PM 운영 목표

2026-10-21 사용자 요청으로 갱신했다. 시스템 goal은 실제 조회에서 active이며 전체 제품 목표를 유지한다. 현재 도구는 objective 본문 편집을 지원하지 않으므로 이 문서를 실행 목표의 정본으로 사용한다. 목표를 가짜 완료하거나 중복 생성하지 않는다.

## 목표

중앙 PM은 사용자와 직접 소통하며 담당 세션의 구현·검증·인계를 능동적으로 관리해 실제 제품 완성까지의 시간을 줄인다. 업무를 나눠 주는 데 그치지 않고 가장 가까운 제품 연결의 병목을 확인하고 담당·우선순위·소비자 계약을 갱신한다. 보고량·시험 개수·active 표시를 제품 완성률로 환산하지 않는다.

공통 Rust SDK/API/CLI를 기능 정본으로 유지하고 GUI는 동일한 application 유스케이스와 domain 정책을 소비한다. 우선 실제 시청 경로와 선택→수정→명시 채택→저장→재열기 연결을 완성한다. 자막·화자 분리·다운로드·스냅샷·카드·숏폼·OP/ED·경량 AI·2D/3D 에셋 등 승인한 전체 범위는 유지한다. 모델 품질의 사용자 검토는 해당 결과를 제품에서 확인할 수 있는 단계에 준비한다.

## 담당과 다음 인수

| 담당 | 현재 집중 작업 | 독립 후속 | 인수 조건 |
|---|---|---|---|
| SDK·CLI | capture-origin 호환과 동일 writer 경계의 guarded mutation 계약·최소 구현 | 실제 CLI에서 명시 편집·채택·재시도의 권한 검증 준비 | 과거 capture 보존, 출처·기대 상태·CAS 검사와 재호출에서도 guard 우회 없음 |
| 플레이어 UI | IPC negative 시험의 실패 시 원 host·종료 소유 보존 | 검증된 SDK·Meari 계약으로 명시 사용자 진입 연결 | capture 차단을 유지하고 원 소유권·실제 입력·저장/재열기를 입증. 시각 검증과 구분 |
| Meari | 동결 record·RadioGroup49의 타입·계약 검증 | 실제 UI의 typed 선택 소비 지원 | 고정 build-source·실제 콜백·게시와 영향 회귀. Web 타입검사와 브라우저 실행 구분 |
| 미디어·AI | 부모 trusted payload producer 인계 | default/no-ORT worker의 CPU 계약 시험 준비 | 기존 프로토콜과 원 scope/lease 재사용, 실제 입력·출력·종료 증거로 단계 전진 |
| 중앙 PM | 현재 gate 종료→최소 수리 인수→채택/커밋→다음 슬롯 배정 | 통합 경로의 다음 소비자·실제 미완료 항목 갱신 | 고정 입력과 원 실행 증거 확인, 책임별 커밋, 정본·계획 반영 |

이 표는 역할과 인수 조건이다. 무거운 작업의 현재 실행 권한은 실행 배정 문서만 소유한다. 후보를 준비했다는 이유로 실행 중 gate의 범위를 늘리지 않는다.

## 모니터링과 재배분

1. 담당마다 현재 업무 하나와 충돌 없는 후속 하나를 유지한다. 담당은 자기 책임 안에서 구현을 계속하고 PM은 공유 파일·우선순위·자원·인수를 관리한다. 연구 서브에이전트는 읽기 조사만 맡는다.
2. 시작·첫 실패·계약 변경·인계·종료 사건과 예정 체크포인트에서 확인한다. 같은 상태의 반복 조회, 중복 감사, 작은 보고마다 회신하는 비용을 줄인다. 진행 중 목표 갱신을 이유로 작업을 재시작하지 않는다.
3. 실패하면 원 오류를 보존하고 소유 담당에게 최소 수리를 배정한다. 대기자는 독립 후속을 진행한다. 소비자는 필요한 정확한 타입·호출·오류 계약을 제공자와 직접 조율하고 PM에는 우선순위 충돌만 올린다.
4. 검증 범위는 변경과 직접 영향에 맞춘다. 이미 통과한 불변 입력의 전체 시험을 반복하지 않는다. 공유 빌드 입력 경로와 캐시를 안정화하고 성능 개선은 실제 측정 전 확정하지 않는다.
5. 완료한 범위는 원 source·BIN·receipt·종료/EOF·보호 대조와 함께 명시 반환한다. PM은 중요한 위험과 주장만 독립 대조하고 책임별 채택·Git 커밋·.spec 갱신 뒤 즉시 다음 실행을 배정한다.
6. 사용자에게는 주요 제품 인수 시점의 전체 표, 남은 사용 동작, 다음 병목과 필요한 결정만 묶어 보고한다. 단순 대기나 담당 리뷰를 사용자 승인 문제로 올리지 않는다.

## 자원과 완료 경계

무거운 빌드·실측·추론은 단일 슬롯으로 관리하고 가벼운 구현·읽기 검토는 병렬 진행한다. 명시 반환 전에 다른 무거운 작업을 겹치지 않는다. 원 handle 관측 timeout을 종료로 추정하지 않는다. 사용자 ChatGPT/Terminal과 실행 중 앱을 종료하지 않는다. Pages·VM·DPI·새 장시간 시험·수동 GUI 시각 검토의 보류를 유지한다.

Rust 통일·단일책임·모듈화·계층 구조·공개표면 최소화를 유지한다. 관측 사실·설계·미검증, 실행 성공·제품 지원·사용자 품질 승인을 구분한다. 전체 제품 완료 기준이 충족되기 전 시스템 goal을 완료하지 않는다.
