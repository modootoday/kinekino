# SDK 원격 새 빌드 인계 — 2026-10-25

대상은 build-host Windows 11의 `C:/workspaces/com.kinekino.player`다. 사용자 최신 결정에 따라 기존 빌드 캐시는 전송하지 않고 대상에서 새로 빌드한다. 현재 PC의 C→D 보호26 검증은 로컬 정리 안전용이며 원격 전송의 선행 조건이 아니다. cloudflared 전송과 대상 수신 준비는 PM이 조정한다. 현재 PC WARP 설정은 변경하지 않는다.

## 전송 책임 경계

`runtime/build-cache`, 각 Cargo target, incremental은 제외한다. canonical Git 소스와 submodule 상태, uncommitted WIP, `.spec`, private `runtime/development` 소스 및 필요한 `runtime/verification`의 로그·manifest·역사 verifier는 별도 보존한다. `target/debug/mpv.exe`는 target 디렉터리 전체 제외에 묻히지 않도록 필수 외부 실행 파일로 분리한다. 실제 표본 actual9·미디어·모델과 라이선스·revision 증거도 캐시로 분류하지 않는다. 파일 전송 범위와 비밀정보 경계의 최종 manifest는 PM 소유다.

## 대상 재현 순서

대상 root에서 `CARGO_TARGET_DIR=C:/workspaces/com.kinekino.player/runtime/build-cache/native`, `TMP`와 `TEMP`는 같은 root의 `runtime/build-cache/tmp`로 지정한다. 대상 PC는 C 설치 root를 사용하므로 원본 PC의 D 절대 경로를 복제하지 않는다. 원본과 대상의 정책 구분은 PM의 최신 지시를 따른다. Cargo jobs1 및 resource-runner conservative2/BelowNormal을 적용한다.

1. root `cargo fmt --check`; Meari manifest `source/packages/meari/Cargo.toml`의 fmt 확인.
2. root `cargo check --locked --offline -j1 -p kinekino-player -p blitz-paint -p meari-native --all-targets --features kinekino-player/native-proposal-window` 및 같은 범위 `cargo clippy ... -- -D warnings`.
3. Meari manifest에서 `-p meari -p meari-native --all-targets --features meari-native/window` check와 strict clippy.
4. 각 Cargo no-run의 JSON producer를 고정하고 직접 산출물의 실제 `--list`를 exact190 계획과 대조한다. Product145 → Core18 → Native26 → OS1 순서로 한 그룹 안에 Cargo writer를 두지 않고 원시험을 실행한다. ignored OS1은 원 exact 이름과 ignored 플래그를 사용한다.
5. 같은 source pin으로 `player`/`player-cli` 정상 bin을 빌드하고 provenance를 기록한다. 새 정상 bin 준비 전 역사 경로의 성공을 현재 파일에 이전하지 않는다.
6. 한 stage의 원파일을 finally에서 복원하고 streams/writers/index/WIP 및 보호 메타데이터를 반환한다. 실패는 첫 실패와 미실행 나머지를 구분한다.

위 명령은 실행 계획이다. 대상에서 실행한 근거는 아직 없으며 offline 의존성이 준비됐다는 주장도 하지 않는다. 의존성 확보는 중앙에서 별도 배정한다. 실제 R4는 Product29 통과 뒤 30번째 technical-step UI assertion 실패였고 source375는 그 UI 버튼 수정 후 아직 미빌드 상태다. 전체190 통과·OS 성공·GUI 시각 인수·사용자 AI 품질 승인은 미완료다.
