## 해결되지 않은 관측·결함

- 회차 전환 첫 actual은 seek10초 뒤 pausedfalse/errorfalse이나 시간 고정·Cache0으로 실패했다. 같은 바이너리/조건의 r2 성공은 원인 해결이나 신뢰성 보장이 아니다. 첫 실패·PNG·정리 근거를 보존한다.
- 사용자 커서 결함의 standalone native 범위는 실제 통과했다. embedded 제품 영상 영역·fullscreen·transport overlay·키보드/접근성 입력의 커서 정책은 별도 미검증이다.
- 무음은 CLI의 명시 volume0과 legacy GUI 초기 mute handoff를 구별한다. GUI volume80인데 mute가 남을 수 있는 경계가 있다. 초기 mute의 Web/native 중복 소리 방지 의도를 보존하면서 공통 요청/관측·실패/기한 계약을 수리한다. [소스 감사](../../sots/verification/application/native-audio-handoff-audit-2026-10-19.md), [수리 계획](native-pointer-and-audio.md).
- 실제 청취·자막 양성 트랙·정확 PTS/색상·전체 사이트/회차·전체 제품 시각 일치는 위 성공으로 입증하지 않는다.

## 다음 인수 순서

1. 완료 인수: Meari Native host port 집중14·전체229/10ignored·최종 strict/fmt와 제한 OS 수직 검증. 물리 입력·스크린리더·suspend·제품 창 통합은 별도 잔여다.
2. 완료 인수: 고정 Meari 입력과 SDK를 사용한 UI panel/factory 신규9·전체36, lint 최소수리 뒤 영향9/strict/fmt. 현재 NativeHost window bridge는 새 미검증 입력으로 구별한다.
3. 사용자 무음 결함 수리인 SDK audio 공통 유스케이스·typed mute 요청/nullable 관측·Web 정지/전환을 다음 단일책임 checkpoint로 등록하고 CLI/실제 검증한다. 제품 host·패키지 분리와 섞지 않으며 문서만으로 결함을 종결하지 않는다.
4. root 제품 등록·동일 SDK/registry·실제 window/event loop 연결과 fresh CLI/project/provenance를 통합한다. eframe Glow와 Meari 자체 winit/GL 공유는 검증 없이 가정하지 않는다.
5. 제품 연결 뒤 AI 조사 담당과 원 candidate·수정 output·결정/조건의 결합을 확인하고 사람 품질 검토를 준비한다.

Meari는 root workspace에서 제외되고 현재 root SDK가 직접 소비하지 않는다. 따라서 SDK 등록 입력을 고정한 채 독립 패키지 소스 작업은 가능하지만 추가 build/browser/실제 실행은 단일 슬롯을 따른다. UI 신규 미등록 adapter와 제품 root 등록 여부도 구별한다.

## 기능별 인계

- 제품 parent consumer의 빌드 진단: 같은 serde_core1.0.229의 식별 충돌 E0277을 PM이 원로그에서 읽었다. SDK는 동일 lock source/checksum·서로 다른 Meari fingerprint·공유 unhashed libmeari.rlib extern 재사용을 관측했다. 산출물 충돌 가능성은 아직 단독 인과 확정 전이다. 기존 캐시를 지우거나 공개 타입을 우회하지 않고 consumer 전용 D runtime/build-cache/sdk-product-parent-consumer에 동일 입력을 격리해 진단하도록 배정했다. 단일2CPU/BelowNormal/j1·offline/locked와 디스크 전후 기록을 유지한다. 성공 시에도 공유 target 결함 해결로 표시하지 않는다.

- 제품 parent 등록의 첫 resolve76ms/101과 fmt metadata 실패: root 직접 path 의존과 player-ui-plugins 자체 workspace가 중복됐다. PM이 두 manifest를 읽고 제품 전용 plugin의 독립 workspace 제거·루트 members/default-members 편입을 승인했다. Meari 독립 workspace와 도구 workspace는 유지하며 기존 plugin lock은 삭제하지 않고 루트 lock의 정본 전환을 문서화한다. 수리·실행 성공은 아직 미인수다.

- UI bridge 읽기 검토: Meari가 registry pending 한도와 text 합산 bytes의 일시 포화가 Rejected로 소비될 수 있는 P2 후보 두 건을 보고했고 PM이 실제 registry/queue 분기를 읽었다. 실행 재현 전이다. UI에 기존 r1 보존·단건 영구 초과/합산 일시 포화 구별·최소 수리/회귀 준비를 배정했다. registry Busy는 request ID 고갈도 포함하므로 일괄 Capacity 또는 오류 문자열 분기로 처리하지 않는다. 공개 typed 구분이 필요하면 Meari와 별도 조율하며 추가 cargo/GUI는 아직 없다.

- [NativeWindowHost bridge 준비](presentation/native-window-bridge-gate.md): 동일 factory owners 이전·admission/drain/동기 receipt·typed close 준비본을 `runtime/coordination/ui-native-window-bridge-prepared-r1`에 고정했다. PM이 선언 목록의 최종7개를 읽었다(기존6개에 closed panel 재개방 거부 추가). owned4 및 regression/assembly/manifest pins를 분리 보존하며 컴파일/실행 전이다. SDK 반환 뒤 고정 입력으로 선택·전체 회귀·strict/fmt를 실행한다. 정상 Immediate UI callback과 기술 parent Pending 시험을 구별한다.
