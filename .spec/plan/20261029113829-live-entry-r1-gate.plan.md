# Live entry R1 독립 실행 계획

계획이며 실행 권한이 아니다. 현재 SDK 제품 CLI r2가 유일 heavy다. UI R2는 private 작성만 병행한다. 실제 배정은 execution-leases.md에서 별도로 한다.

## 입력과 선행 조건

R1 source9 SHA5479218AD0639821E23130827E0D6A11C34AAE02C559B414182F4B5A2881C607 및 before9 원본을 보존한다. task3/scoped9는 root f4f678a에 채택됐지만 R1은 미채택·미실행이다. 배정 시점 새 root의 기존7 preimage/신규2 부재와 raw9를 재확인한다. SDK 제품13의 인수/채택 여부는 새 기준에서 구별한다. private R2와 자동 합성하지 않는다.

## 검증

기존 S/T/runner 및 직전 반환 보호 기준을 사용한다. 변경 입력만 명시 동기화하며 unchanged bytes의 mtime, fixed BIN, 원 alias와 과거 미귀속2를 보존한다. fresh RAM16GiB/VRAM3GiB/C12GiB/writer0, CPU2/BelowNormal/offline/locked/j1/thread1이다. fmt/해당 feature all-target strict, Cargo JSON의 실제 lib BIN·feature·fresh·SHA/bytes/producer, 실제 list/ignored list를 기록한다.

작성 시험은 live_entry::tests의 일반1과 ignored7이다. 실제 등록 후 일반1, 원 LocalHost/SDK를 쓰는 ignored7을 정확 이름으로 각각 실행한다. 같은 원 SDK inspect/ACK/release·원 route owner/close, 중복/foreign/unknown·Jobs 양방향 배타·원 실패 carrier를 확인한다. callback suffix 시험과 inspection 양성은 mount/편집/프레임 관측 양성이 아니다. 기존 Card/Jobs/close의 실제 영향 범위를 소스와 목록에서 정하고 중복 전체 library 실행을 기본 추가하지 않는다. 수리 시 원 오류와 BIN/receipt를 보존하고 exact delta를 별도 제안한다.

## 반환과 한계

S 복원과 채택 baseline/직전 고정본·alias/index/canonical 보호를 대조하고 원 세션 terminal/EOF 및 process/handle/writer/cleanup을 확인한다. 새 source/BIN/실제 결과와 SOT를 연결해 명시 반환한다. CLI 기능을 GUI로 재시험하지 않고 창/수동시각/DPI/VM/모델 실행0이다. Inspected 상태는 편집 활성·명시 채택·Some checked frame·실제 Viewer 사용자 경로 완료를 뜻하지 않는다. trusted Rust caller가 원 create/import 결과를 보유하는 provenance 계약과 capture-derived 입력 금지를 후속 R2/R3가 유지해야 한다.

기존 독립 검토의 modoo.today code-change-review-verification 본문·verdict 참조 적용을 이어받아 작성/등록/실행/실제 입증 경계를 분리했다. 새 코드·실행0.
