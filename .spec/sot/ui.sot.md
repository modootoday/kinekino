# UI와 제작 기능 설계 정본

2026-10-26 [제품 UI·Meari 통합 인수](shared/product-integration-acceptance.md)는 기존 승인된 화면/요소를 VIEW3·Studio20 route와 SDK/CLI·Router/plugin·상태·인수 단계에 연결한다. 현재 routes 선언은 runtime 등록/지원 증거가 아니다. 기존 공통 시안과 요소 기준은 유지하고 수동 GUI 보류는 해제하지 않는다.

전체 선택 시안 재검토에 따른 [화면 구성 정본](shared/screen-composition.md)을 필수 구현 기준으로 적용한다. 아래 기능·요소 계약만으로 화면을 임의 구성하지 않는다. [재검토 근거](../../verification/presentation/design-reference-review-2026-10-18.md)는 관측과 미검증 범위를 구분한다. 2026-10-18 이후 작업 순서는 전체 시안 검토 → 화면별 구성/상태 문서 → SDK 계약 → 컴포넌트 구현 → 요소별 확대 비교다.

2026-10-18 사용자 승인으로 이 문서와 presentation 하위 탭 계약을 UI 구현 기준으로 채택한다. 생성 이미지의 불일치한 디테일은 복제하지 않고 공통 Rust 컴포넌트의 실제 렌더를 보고 판단한다. D1~D11을 포함한 제안 방향은 승인됐으나 실제 치수·밀도·상호작용·접근성의 인수는 구현 후 진행한다. Pages는 동결하고 로컬 문서만 갱신한다. 현재13개 화면·197개 요소 계약이며 새 화자 탭 이미지는 미제작이다. 설계 승인과 기능 구현·모델 품질 검증은 별개다.

## 공통 프레임

시청 기본 1180×760, 최소 760×480 논리 단위. 제목줄 32, 시청 하단 56. 제작 진입 시 가용 작업영역 안에서 1440×900을 제안하고 최소 1180×760을 목표로 한다. 작업영역이 작으면 창을 화면 밖으로 키우지 않는다.

제작 프레임은 왼쪽 탐색 180, 간격 12, 오른쪽 검사기 300, 하단 큐 40, 나머지 가운데 편집기로 구성한다. 너비 1280 미만에서 오른쪽 설정은 “설정” 버튼의 서랍으로 옮기고, 1180 미만 작업영역에서는 왼쪽 탐색을 48 아이콘 레일로 줄여 중앙을 확보한다. 툴팁과 현재 탭 제목을 유지한다. 세 영역을 동시에 강제로 축소하지 않는다. 980 미만이면 단일 작업 편집기 + 설정 서랍 방식으로 재배치한다. 스크롤은 목록·검사기 안에서 제공하고 창 버튼과 주요 저장/취소는 화면 안에 유지한다. 가상 디스플레이를 포함한 실제 검증은 구현 후 별도다.

상단의 시청으로 돌아가기, 현재 작업명, 프로젝트 수정 상태, 모델 관리 진입은 공통이다. 왼쪽 탭 이동은 작업 실행을 뜻하지 않는다. 탭별 초안과 마지막 선택을 보존하며, 실행 중 작업은 하단 큐에서 계속 보인다. 탭을 바꿔도 백그라운드 작업을 몰래 취소하지 않는다.

| 공통 ID | 요소 | 계약 |
|---|---|---|
| SH-01 | 시청으로 돌아가기 | 편집 초안 보존, 원래 재생 위치/일시정지 의도 유지 |
| SH-02 | 탭 탐색 | 선택/hover/focus 구별, 툴팁, 스크롤 가능 |
| SH-03 | 소스 선택 | 로컬 파일 또는 정상 세션 MediaId. 임의 셸/스크립트 입력 없음 |
| SH-04 | 시간 구간 | 시작 포함·끝 제외 [in,out), 정수 마이크로초 저장, 화면은 ms까지 |
| SH-05 | 되돌리기/다시 실행 | 현재 문서 수정 단위, 작업 실행/파일 삭제를 역으로 실행하지 않음 |
| SH-06 | 미리보기 | 결과가 아닌 샘플 표시, 원본과 비교, 생성 중임을 표시 |

| SH-10 | 모델 상태 | 미설치·다운로드·검증·준비·실행·실패 구별 |

## 입력과 편집 공통 규칙

세부 기본값·범위·컴포넌트 크기·아이콘은 [필드 규칙](shared/field-rules.md)을 따른다.

화면 간 차이를 판단할 때 [일관성 기준](shared/consistency.md)을 우선한다. 디자인 자산의 기준 경로는 [.spec/artifacts/design](../../../artifacts/design/README.md)이다.

숫자 입력은 finite만 허용한다. 시간은 0≤in<out≤duration. duration 미상에서는 끝까지 처리하는 작업을 사전 검증에서 보류한다. 프레임 번호는 실제 PTS와 timebase가 확인될 때만 사용하며 VFR을 고정 FPS로 환산해 사실처럼 표시하지 않는다. 회전·픽셀 종횡비·색공간을 원본 좌표 변환에 포함한다.

슬라이더와 숫자 필드를 함께 제공하고 적용 전 미리보기한다. 잘못된 입력은 필드 아래 원인을 표시하고 적용/작업 추가를 비활성한다. 키 입력 중 임시로 비어 있는 값은 편집 상태로 허용하되 저장 가능한 값으로 취급하지 않는다. 단위·최솟값·최댓값·기본값을 각 검사기에 표시한다.

텍스트의 최대 길이는 서버/모델/형식 제한과 편집기 성능 검증 뒤 명시한다. 한글 조합 중 단축키를 가로채지 않으며 텍스트 오버플로를 자동으로 삭제하지 않는다. 색·아이콘만으로 오류나 선택을 구별하지 않는다.

## 상태와 작업 수명

명령과 화면 상태의 연결, 닫기/초안 복구는 [상태 전이 계약](../application/jobs/state-transitions.md)을 따른다.

편집 초안은 Draft→Preflight→Queued→Running→Verifying→Completed. NeedsInput·Failed·Cancelled로 분기한다. 모델 준비와 미디어 다운로드는 의존 작업으로 보이고 하나의 가짜 진행률로 합치지 않는다. 작업 단계/bytes/처리 구간이 실제로 알려졌을 때만 퍼센트나 ETA를 표시한다.

취소는 요청 중→취소 완료로 응답하고 소유 워커만 중단한다. 일시정지는 재개 가능한 전송/체크포인트가 있을 때만 제공한다. 인코딩·추론에 단순 프로세스 정지를 적용해 재개 가능하다고 속이지 않는다. 실패 재시도는 같은 입력 revision과 설정을 재사용하고 출력 중복을 막는다.

실행 중 편집은 별도 Draft revision으로 저장하며 현재 작업 입력을 바꾸지 않는다. 작업 결과가 오래된 revision이면 “이전 초안의 결과”로 표시하고 현재 편집을 덮어쓰지 않는다. 앱 재실행 시 진행 중 작업은 복구 확인 상태가 되고 자동 중복 실행하지 않는다.

## 접근성과 상호작용

아이콘 18~20, 클릭 영역 32 이상, 주요 재생/확인 40 이상. 키보드 focus2, 일반 글자 contrast4.5:1, 주요 비텍스트3:1을 목표로 한다. disabled는 기능 불가의 이유를 툴팁/설명으로 제공한다. 실제 egui 접근성 트리와 스크린리더 검증을 인수 게이트에 포함한다.

Tab 순서는 탐색→소스→중앙 편집→설정→실행→큐. 목록 Up/Down·Enter·Home/End, 다중 선택 Shift/Ctrl, 드래그 순서 변경에는 위/아래 버튼도 제공한다. Esc는 팝오버→패널→전체화면 순서이며 초안을 버리지 않는다. Ctrl+Z/Y는 입력 필드의 편집을 우선한다. 공통 키맵은 설정에서 충돌 검사 후 변경할 수 있는 후속 계약이다.

## 저장 데이터와 민감정보

ProjectDocument(schema_version, project_id, revision, media_refs, edits, model_refs, outputs)를 로컬 저장한다. media_ref는 논리 식별자·로컬 파일 참조·fingerprint이며 서명 URL/쿠키/HF 토큰을 프로젝트에 저장하지 않는다. OS 경로는 infrastructure 저장 포트를 통해 처리한다. 외부 미디어 변경·없음·모델 revision 불일치는 재연결 요청으로 처리한다.

원본·AI 초안·사용자 수정·출력 결과를 구별하고 source PTS와 revision 연결을 유지한다. 결과 생성이 외부 게시를 뜻하지 않는다. 자동 내보내기/덮어쓰기/업로드는 묵시적으로 수행하지 않는다.

## Rust 책임 경계

GUI는 [공통 SDK](../application/api/sdk-contract.md)의 명령/조회/이벤트를 사용하고 [CLI](cli/automation-contract.md)와 정책을 공유한다. UI에만 있는 중복 제작·재생 정책을 만들지 않는다. 현재 GUI는 기존 프로토타입이며 새 SDK·CLI 구현 완료를 뜻하지 않는다. 제품명은 [제품 식별](../domain/product/identity.md)에서 주입한다.

| 계층 | 책임 |
|---|---|
| domain | MediaId, TimeRange, SegmentAnnotation, CueDocument, SubjectTrack, ClipDocument, CardDocument, MaskAsset, ProjectionSpec, ExportPreset, 검증 정책 |
| application | 탭별 유스케이스, 프로젝트 revision, 작업 상태, 모델 카탈로그 포트, 미리보기·내보내기 계약 |
| infrastructure | mpv/WebView2, HF 다운로드, 추론 엔진, 디코더/인코더, 파일 저장과 Windows 어댑터 |
| presentation | common shell, icons/tokens, 각 탭 view/viewmodel/inputs, 상태 표시와 사용자 입력 |
| main | 의존성 조립과 실행 |

탭별 presentation은 해당 유스케이스만 호출하고 모델 로딩·명령 생성·COM 처리를 직접 하지 않는다. 하나의 StudioApp에 모든 편집 정책을 넣지 않는다. 공통 IconId→라이브러리 자산/접근성 이름 매핑을 한 곳에서 관리한다. 새 개발·검증 코드는 Rust다.

## 설계 인수 게이트

1. 모든 시각 요소는 아래 탭 요소 ID와 연결되고 구현된 것만 활성화한다.
2. 기본·입력 필요·빈 상태·실행·실패·취소·완료 및 오래된 결과를 각 탭에서 검증한다.
3. 100/150/200%와 좁은 작업영역에서 텍스트, 포커스, 패널, 팝오버, 스크롤을 확인한다.
4. 모델/미디어 미가용, 디스크 부족, 경로 충돌, 취소, 앱 복구에서 원본 보존과 중복 방지를 확인한다.
5. 실제 모델 선정·엔진 호환·정확도·메모리·GPU/재생 경쟁은 별도 실측을 통과해야 기능 가용으로 승격한다.
6. Rust 변경 뒤 fmt/test/Clippy와 실제 UI 동작을 검사한다.

현재 완료는 계약 작성과 시안 자산 준비다. 새 UI 기능·모델 분석·AI 경쟁·저장 왕복 테스트가 완료됐다는 뜻이 아니다. 제품 구현은 사용자 디자인 검토 후 재개한다. [상세 스타일/AI 정책](review/sot-019-detailed-ui-ai-proposal.md), [기존 미디어 계약](../application/production/sot-012-media-production.md), [HF/투영 계약](../application/analysis/sot-013-local-ai-projection-assets.md)을 함께 적용한다.
