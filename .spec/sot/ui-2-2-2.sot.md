# 영속 작업 조회 UI 연결 계약

상태: 2026-10-19 설계. SDK jobs 등록과 typed 응답 인계 전이며 구현·실행 검증 완료가 아니다. [SDK jobs 계약](../../application/api/jobs.md)을 정본으로 사용한다. 수동 GUI 검증 보류와 SDK/API/CLI 우선 순서를 유지한다.

## 관측한 기존 연결

`studio/screens/system.rs`의 Job 화면은 WorkspaceSnapshot의 범용 table을 표시하며 빈 columns에는 progress Percent 열을 만든다. 선택 ID가 없으면 첫 행을 선택한다. `system_inspector.rs`도 선택 ID를 찾지 못하면 첫 행으로 대체한다. 현재 단계·시간·명령은 미연결이고 디자인 예시의 stepper만 별도로 표시한다. 이 구조를 실제 영속 jobs 조회·실행 지원으로 간주하지 않는다.

## 얇은 어댑터 경계

실제 목록은 ApplicationClient의 typed list/get 응답으로 연결한다. UI가 journal·source 파일을 읽거나 상태 전이·취소 경합·retry 정책을 계산하지 않는다. JobId는 project/proposal ID와 구분하고 선택·worker 응답의 식별자로 유지한다. 조회 실패 시 이전 결과와 오류를 함께 표시하고 실패한 조회를 빈 목록 성공으로 바꾸지 않는다.

새 조회·필터·선택마다 UI 요청 세대를 구분한다. 늦게 도착한 이전 요청 결과가 현재 선택 상세를 덮어쓰지 않게 한다. 목록 변경으로 선택 ID가 사라지면 미선택 상태를 표시하며 첫 행으로 암묵 이동하지 않는다. 상세의 표시 JobId·attempt·revision을 명시한다. 목록과 상세가 서로 다른 시점이면 이를 동일 snapshot으로 주장하지 않는다.

list의 cursor와 through_sequence는 SDK가 반환한 값을 그대로 유지한다. 다음 페이지에 이전 cursor를 재사용하며 새 필터/새 조회에서는 새 목록을 요청한다. UI가 cursor를 합성하거나 전체 목록을 한 번에 내려받지 않는다. 상태 필터는 SDK가 지원하는 입력만 활성화한다.

watch는 영속 event page를 비동기 worker에서 요청한다. UI thread 대기·무한 long poll·매 frame 요청을 만들지 않는다. 마지막으로 반영한 응답 cursor만 다음 요청에 사용한다. gap 응답은 재조회 필요로 표시하고 상세를 다시 요청한다. 오류를 정상 gap이나 완료로 바꾸지 않는다. 정확한 갱신 간격과 worker 수명은 typed 포트 인계 후 확정한다.

상태·실제 단계·결과 receipt·오류는 SDK 값을 표시한다. 단계명으로 퍼센트/ETA를 만들지 않는다. 첫 subtitle executor가 제공하지 않는 시간·진행률은 미제공으로 표시하며 Percent 기본 열에 가짜 값을 채우지 않는다. Cancelling은 취소 요청 중으로, Cancelled는 취소 확인으로 구별한다. 완료 여부와 출력의 유효성은 SDK receipt에 따른다.

## 명령 연결 전 인계 항목

- list/get/watch의 최종 Rust 타입·cursor·오류 구조 및 실제 capability ID와 지원 조건.
- cancel/retry의 expected revision 입력과 응답 상태. UI 중복 클릭 방지는 가능하지만 SDK의 원자 검증을 대체하지 않는다.
- operation별 결과 receipt와 source identity 표시 필드. 원문 blob은 목록 조회에서 자동 로드하지 않는다.
- host 수명과 read-only backend의 구분. 조회 지원만으로 submit/retry/전체 시작 버튼을 활성화하지 않는다.

최초 연결은 읽기 전용 list/get부터 진행한다. submit/cancel/retry는 각 typed 계약과 SDK 자동 검증이 준비된 뒤 별도 연결한다. 기존 공통 table·notice·inspector·토큰을 재사용하고 jobs 전용 정책 저장소나 별도 테마를 만들지 않는다.

검증은 SDK/CLI 기능 증거를 재사용한다. UI에는 오래된 응답 배제·선택 유실 처리 같은 어댑터 회귀만 최소 추가한다. 사용자 재개 전 GUI 실행·스크린샷·기능 클릭 검증은 수행하지 않는다.
