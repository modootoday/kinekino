# 기존9표본 수입의 정적 상태·오류 연결

2026-10-19 연구 세션의 읽기자료다. [고정 source와 추출 규칙](text-r3-source-mapping.md)을 제품 SDK/UI로 연결할 때 상태와 API 실패를 혼동하지 않도록 현재 Rust 계약을 정리한다. 새 정책·모델 실행·품질 판정을 추가하지 않는다. 실제9개 수입·수정·채택·재시작 검증은 SDK/UI 소유 세션의 실행 receipt가 근거다.

## source 연결

correction은 원래 ASR 문자열6개를 document source v2로 표현한다. source asset SHA, outer pointer `/messages/0/content`, `asr_request_after_no_think_lf_v1` 추출 규칙과 inner pointer `/0`부터 `/5`까지가 참조 정본이다. 배열 index를 subtitle cue ID로 바꾸지 않는다. 원문 bytes/SHA·pointer 순서·text는 검증 시 다시 대조한다.

cards/highlights는 source cue ID1..7과 text를 사용한다. 실제 request 원문에는 in_us/out_us가 있지만 수입 어댑터가 이를 검증한 뒤 제품 source cue의 start_us/end_us를None으로 둔다. 현재 입력의 시간null을0이나 생성 구간으로 채우지 않는다. 원문 보존과 생성 candidate의 시간 승인은 서로 다른 판단이다.

원문 근거: [추출 profile](../../../../../../src/domain/proposals/request_source.rs), [document v2 참조](../../../../../../src/domain/proposals/document_source.rs), [source 수입](../../../../../../src/application/proposals/source_import.rs).

## 상태와 API 실패

아래 exit는 표준 player-cli가 ApiError를 반환할 때의 공통 매핑이다. 별도 importer/example 프로그램 전체의 exit를 뜻하지 않으며 해당 프로그램의 실제 exit는 별도 receipt로 확인한다.

| 지점·조건 | 현재 계약 |
|---|---|
| source asset SHA/64KiB bound 불일치, message/profile/LF 경계·배열 오류 | source 수입의 invalid_argument, CLI exit2 |
| document source를 correction 외 task로 사용 | create에서 invalid_argument, exit2 |
| 생성 raw가 잘린 JSON·다른 typed schema·잘못된 참조·task 불일치 | create가 raw를 보존하고 needs_repair/draft=None/import_error를 저장. API 실패나 자동 복구로 바꾸지 않음 |
| needs_repair 상태에서 draft 없이 채택 | needs_input, exit3, remediation=edit_proposal_draft |
| 명시적 edit에 없는 source ref·잘못된 task·중복 참조·유효하지 않은 text | invalid_argument, exit2. 생성 raw의 불변성과 구별 |
| edit/accept expected_revision 누락·파싱 불가 | invalid_argument, exit2 |
| draft revision 또는 target_source_revision 불일치 | revision_conflict, exit5. 재조회 후 수정/채택 |
| 저장 adapter 미제공 | unsupported, exit3 |

이 표는 현재 함수 분기·오류 enum을 읽은 정적 연결이며 새 실제 오류 실행 결과가 아니다. 저장소 손상이나 IO 실패의 모든 경로까지 위 코드로 일반화하지 않는다. [application 유스케이스](../../../../../../src/application/proposals/mod.rs), [domain 검증](../../../../../../src/domain/proposals/validation.rs), [공통 API 오류/exit](../../../../../../src/application/api/errors.rs)가 구현 정본이다.

## 보존과 사용자 흐름

수입은 원문/generated raw를 보존하고 사람이 명시적으로 만든 draft를 별도 revision으로 저장한다. 채택 receipt는 source ID/revision/SHA와 draft/output revision을 결합하며 automatic_application_enabled=false다. 기존 proposal 재조회·명시적 수정·채택·새 프로세스 재조회 흐름을 GUI와 CLI가 같은 application 유스케이스로 사용해야 한다.

연구 결과의 JSON schema가 제품 typed proposal과 다르면 원본을 자동으로 product schema로 다시 써서 editable로 표시하지 않는다. 기술 검증용 edit/accept receipt와 실제 사용자의 내용·품질 승인을 구별한다. 추가 모델 실험과 사용자 모델 품질 검토는 API/SDK/UI 준비 뒤의 별도 마지막 단계다.

## 현행 접합 감사에서 남은 실제 연결

현재 create/edit/accept는 구현되어 있으며 `.spec/sots/verification/application/proposals-2026-10-19.md`의 실제9 CLI 원문/수정/채택/재조회 근거를 유지한다. 아래는 그 기능의 부재가 아니라 **모델 실행·후속 적용과 연결할 잔여**다. [현 jobs와 AI executor](ai-executor-current-jobs-integration.md), [모델 CLI 인계](model-engine-cli-contract-handoff.md)의 책임을 따른다.

| 종류 | 현행 source/제품 payload | 남은 연결 |
|---|---|---|
| 교정 | source_import.rs가 원문6문장을 DocumentSourceSnapshot으로 읽고 DocumentCorrection의 source_ref/text를 검증 | 과거 proposed/uncertain_words와 다르므로 명시 task adapter 필요. document pointer를 실제 ASR job/프로젝트 subtitle source에 연결하는 정책·검증 없이 cue/time을 발명하거나 채택 즉시 자막 파일에 적용하지 않음 |
| 카드 | 과거 headline/summary/cue_ids와 제품 cards[{front,back,source_refs}]가 다름 | 명시 매핑과 문장별 근거 의미 검토. accepted payload와 실제 카드 image/export/render는 별도. 기술fixture cue1/2복사를 사람 문구 승인으로 세지 않음 |
