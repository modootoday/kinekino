# 실제 텍스트9표본의 원문 매핑

2026-10-19. SDK 제안 수입용 읽기자료다. 새 추론·품질 판정·원문 자동 수정을 포함하지 않는다. 저장소는 `.spec/artifacts/quality-review/sdk-text-results-r3`, package SHA256은 `659b3cb6757259d8e770f6d3c96c4a77dafbab43c6ea540bcc7e0c58e4eb0197`이다. 각 asset의 bytes는 `objects/<sha256>`에 있다.

## 정본과 JSON 경로

package의 `/items/0..2`는 Gemma, `/items/3..5`는 Llama, `/items/6..8`는 Qwen이며 각 묶음은 correction/cards/highlights 순서다. `/items/i/source`와 `/items/i/baseline/assets/0`는 원래 HTTP request 전체의 pretty JSON asset이다. `/items/i/candidate/assets/0`는 원래 response choices[0].message.content의 UTF8 bytes다. 원본 manifest 연결은 각 candidate.condition.input_conditions.source_manifest_sha256과 exporter의 `pinned_text_sources.rs`에 있다.

| task | source asset SHA256 | bytes |
|---|---|---|
| correction | `b282db497133af492690d5d8726549cbafa7dd203517476e64e915c8101b2e27` | 1232 |
| cards | `47aecd7b66ef847c6e4a555650d3e39f57e9bfecf5cd00e64082e3da61d49cab` | 2129 |
| highlights | `658e5fbded1a1203472c937b8b7188c64915859446cb6c4e9b827d877b0d8093` | 5623 |

source의 `/messages/0/content`는 지시문과 입력 JSON을 담은 문자열이다. outer JSON decode 후 해당 task의 고정 지시문과 `/no_think\n` 경계를 확인하고 suffix 전체를 JSON decode한다. 첫 대괄호를 찾으면 지시문의 schema 배열 표기와 혼동할 수 있다. request의 실제 출력 schema는 `/response_format/json_schema/schema`다. 파싱 실패나 다른 구조를 임의 복구하지 않는다.

실제 Rust `serde_json` decode로 세 asset 모두 확인했다. outer decode1회 뒤 경계는 literal backslash+n이 아니라 실제 LF(U+000A)이며 정확히1개다. suffix는 추가 JSON-string-body decode 없이 직접 배열 parse1회에 성공했다. cards/highlights suffix의 첫 codepoint는 `[91,123,34,105,100,34,58,34,49,34,44,34,105,110]`이다. 추가 string-body decode는 trailing characters 오류다. 검사 코드는 `tools/spec-maintenance/src/application/text_source_inspection.rs`, 원문은 `.spec/evidence/verification/gemma-startup-pin-2026-10-19-r3/text-source-decode.log`다. cue7 text 내부 literal backslash+n은 이 경계와 구별한다.

correction suffix는 ASR draft 문자열6개의 배열이다. `/0`부터 `/5`까지가 문자열이며 cue ID·시간은 없다. 원문은 다음 순서다.

1. This blade has a turk blast.
2. You'd have shed much in a simple load.
3. You're a fool for traveling alone so completely unprepared.
4. You're lucky you're blood still flowing.
5. Thank you.
6. So, what brings you to the land or the gatekeepers?

cards/highlights suffix는7개 `{id,in_us,out_us,text}` object 배열이다. `/i/id`가 문자열 cue ID, `/i/text`가 원문이다. cue ID1..7은 이 칼날에는 어두운 과거가 있다. / 많은 무고한 피가 서려 있군. / 아무런 준비도 없이 혼자 다니다니, 바보같군. / 여태 살아있는 게 행운이네. / 감사합니다. / 그런데... / 문지기들의 땅에는\n무슨 일로 찾아왔나? 순서다. 마지막 문자열의 backslash와 n은 중첩 JSON decode 이후 원문 bytes대로 유지하고 임의 줄바꿈 정규화를 하지 않는다.

현재 원본 `runtime/ai-spike/assets/cues-ko.json` SHA256은 `dad7609aede6c4dd4eba6a0e868663c10b975f5e2dbb7c21151876caef482b23`다. 원본 document는 `/cues/i/id`·`/cues/i/text` 구조이며 exporter 입력 생성은 첫7개를 선택했다. 실제 수입은 현재 runtime 파일 대신 package에 고정된 request asset을 우선 대조한다.

## 시간과 schema의 한계

cards/highlights source에는 실제 in_us/out_us가 있다. ID1..7 순서로107250000..110500000,111800000..115800000,118000000..121450000,121750000..124800000,125250000..126300000,127500000..129000000,129400000..133800000이다. 원본에 시간이 없다고 설명하면 틀린다. 그러나 package 모든 item.range는 명시적 null이며 생성 출력 schema는 시간 값을 정의하지 않는다. 사용자·PM 지시에 따라 수입 proposal 시간은null을 유지하고 source cue 시간을 생성 candidate 시간으로 자동 승격하지 않는다. correction의 문자열 index를 원본 cue ID로 가장하지 않는다.

correction 출력 schema는 `{proposed:string,uncertain_words:string[]}`, cards는 `{headline,summary,cue_ids}`, highlights는 `{ranges:[{cue_ids,reason}]}`다. 이는 저장된 요청 schema 설명이며 기존 제품의 typed proposal과 자동으로 동형이 아니다. 새 cue/text/time을 발명하거나 잘린 JSON을 보수해 typed 유효로 표시하지 않는다. raw asset은 그대로 두고 불일치·불완전 결과는 needs_repair로 유지한다. 품질 판정은 [제품 통합 뒤 마지막 검토](model-quality-final-review-readiness.md)의 별도 단계다.
