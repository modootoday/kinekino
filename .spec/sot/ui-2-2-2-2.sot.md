## S2 문서 원문 참조 연결

### 검사기와 편집기의 동일 상태 투영

#### 다음 구현 단위: 같은 inspector의 설정/제안 검토 모드

SUB교정/CARD/CLIP추천의 공통 inspector 상단에 기존 segmented로 `작업 설정`/`제안 검토` 두 모드를 조합한다. 모드는 task별 presentation state로 유지하며 새로운 상위 workspace/tab을 만들지 않는다. 초기 작업 설정은 기존 시안의 inspector를 유지하고 제안 검토는 같은 너비/위치에서 실제 Proposals의 원문·편집buffer를 표시한다. 좁은 창의 기존 설정 진입은 같은모드/같은task state의 drawer를 연다. 모드전환은 inspect/save/accept를 자동실행하지 않고 dirtybuffer를 버리지 않는다.

본문 screens::show의 선행 proposals.show 호출을 제거한다. CARD 도구/thumbnail/canvas, SUB영상·비교표, CLIP preview/후보가 본문진입부터 유지돼야 한다. 제안 검토에서는 기존미연결 inspector를 동시에 렌더하지 않는다. 작업 설정에서 원문/제안 미연결 안내는 `영상 자막 행`/`카드 캔버스` 등 실제 미연결 대상을 명시하고 저장된 문서 제안까지 없다고 표현하지 않는다. 로드된 제안 identity/dirty/accepted 요약은 같은Proposals state에서 읽기전용으로 제공한다. 실제 미디어·캔버스·cuePTS가 연결되었다고 승격하지 않는다.

검토 body는 내부ScrollArea로 sourceidentity/provenance·원생성 펼침·작업별 구조화editor·명시수정버리기를 표시한다. footer는 body와 분리해 항상 접근 가능한 `수정본 저장`/`명시적 채택` 동작과 현재dirty/pending/error/receipt를 배치한다. 공용2열버튼과INSPECTOR_FOOTER토큰을 우선사용하고 상태문구길이를 실제300폭에서검토한다. 기존공용inspector::panel의기본소비자를바꾸지않고 state를명시인자로받는조합으로body/footer가같은State를차례로차용하도록한다. RefCell이나중복editorstate로Rust차용문제를우회하지않는다.

수정 파일 범위: studio/mod.rs(공통inspector진입·screens호출), screens/mod.rs(선행editor호출제거), studio/proposals/{mod,view,tests}.rs 및body/actions책임분리(task별모드·summary·본문/동작분리), components/inspector.rs(stateful조합), 필요한기존correction검사기안내. 실제호출부는studio/mod.rs로확인했으며legacy editor.rs는이변경대상이아니다. publicSDK/application/domain/Cargo/main은변경하지않는다. SDKprojects session47811고정완료뒤명시source교대부터구현하며이설계를현재구현완료로취급하지않는다.

새회귀는 단순renderer출력유무보다 작업canvas배치와task state보존을 검증한다. 같은창/같은task에서 제안조회전후 본문preview/toolbar상단이변하지않는지, 작업설정↔제안검토전환이dirtybuffer/receipt를바꾸지않는지, 서로다른task의모드/조회가혼합되지않는지확인한다. footer동작은latestexpected_revision·기존worker/CAS를그대로사용한다. 더긴상태/오류는본문에서읽되footer가화면밖으로밀리지않아야한다. DesignSample은실제제안저장소를샘플데이터로위장하지않으며기존reference조합을유지한다. 실제1440/760·문서SHA긴줄·cue7개·save/accept·키보드모드전환·drawer/Escape를새고정bin에서검토한다.

r167 재실행에서 실제 본문 source/draft/receipt가 복원돼도 기존 correction_inspector가 WorkspaceSnapshot만 읽어 연결 필요를 표시했다. 이를 고치기 위한 UI 전용 read projection은 Proposals의 기존 task State에서 차용한다. 별도 workspace table에 raw/편집 문자열을 저장하거나 두 번째 제안 저장소를 만들지 않는다. 공통 application DTO/SDK 정책 추가 없이 presentation이 비교 대상·표시 상태·선택된 source ref를 소유한다.

표시 projection은 현재 document의 proposal ID·source identity/revision·source kind·원문 참조·draft text·dirty/pending/error·명시 acceptance를 제공한다. 문서 ref는 실제 SDK assetSHA/outer/extraction/inner 전체를 유지하고 cue와 변환하지 않는다. selected edit/card/highlight는 안정 참조를 사용하며 항목 삭제 후 다른 항목에 이전 focus/선택을 덮어씌우지 않는다. 원문은 source에서, 수정문은 같은 task의 caller-owned draft buffer에서 읽는다. 표시 선택은 저장/채택 정책을 판단하지 않는다.

Inspector의 비교·상태·receipt는 이 projection을 사용하고 수정/저장/채택 동작은 동일 Proposals worker로 보낸다. 교정 본문 행 선택과 문서 문장 선택은 서로 다른 참조이므로 문서에 선택 자막 행 안내를 표시하지 않는다. 데이터가 없는 기존 workspace fields의 모델/미디어/PTS는 계속 미연결이며 제안이 있다는 이유로 가용 상태로 승격하지 않는다. 요청한 ID 입력과 현재 표시 중인 document ID도 구별해 조회 실패 시 기존 buffer가 어느 제안인지 명확히 표시한다.

넓은 화면은 canvas 옆의 보조 비교 영역, 좁은 화면은 명시 진입 drawer에서 같은 projection과 editor를 사용한다. 본문 맨 앞에 전체 편집기를 누적하는 구조는 이관 대상이다. 저장/채택/CAS/오류/receipt 영역을 editor 내부 고정 footer로 조합하고 원생성 raw·source provenance는 보조 펼침으로 유지한다. source/draft가 없는 단계와 malformed needs_repair·dirty·pending·saved·accepted를 별도 표시한다. 구현 후 기존3task 흐름·r164/r167 저장자료 읽기·narrow resize·focus/Escape·충돌 buffer 유지·원문 보존을 새 고정 EXE에서 재확인한다. 현재는 구현 전 계약이다.

SDK의 proposals.md sourceV2 계약을 따른다. Cue와 Document source는 공통 accessor로 식별하되 문서에 가짜 cue/time을 만들지 않는다. DocumentCorrection의 source_ref는 SDK document.text_reference가 제공한 asset SHA/outer pointer/extraction/inner pointer 전체를 선택한다. 화면은 문서 SHA·추출 위치·선택 원문을 읽기 전용으로 표시하고 사용자 수정문만 별도 multiline buffer로 편집한다. 문자열 위치로 새 참조를 조립하거나 UI에서 원본 JSON을 다시 추출/해석하지 않는다. 수동 복구의 빈 초안도 source 종류에 맞는 DocumentCorrection으로 준비한다. 원생성 bytes/parse 오류·저장/채택/CAS/receipt 경계는 r162와 같다. r162는 cue 합성 자료의 관측이며 S2 검증으로 소급하지 않는다.

현재 source enum accessor·문서 위치 선택/editor·빈 문서 초안 연결을 구현 중이다. SDK sourceV2 gate와 실제 자료 조회/편집/채택 전에는 동작/시각 완료로 판정하지 않는다.

원문 문장/자막 선택은 공용 input::select가 소유한다. 기존 입력과 동일한 직접 작성 ChevronDown SVG·전체 폭·labelled_by를 사용하고, 화면은 옵션과 선택 의미만 제공한다. 문서 pointer와 cue ID를 서로 변환하지 않는다. 수정문은 공용 multiline의 별도 접근성 label을 유지한다. 이 보완의 실제 표시는 S2 고정 실행본에서 확인해야 한다.

## r161 구현 체크포인트 — 실제 검증 전

`components/proposal_editor`는 domain typed draft를 caller-owned buffer로 편집하고 `input::multiline`이 label/focus/내부 스크롤을 공유한다. `studio/proposals`는 task별 독립 state와 단일 pending worker를 소유하며 typed inspect/edit/accept만 호출한다. SUB 교정·CARD·CLIP AI 본문 스크롤 안에 접이식 영역으로 연결했고 capability가 없으면 기본 접힘/미연결 사유를 표시한다. 제안 생성은 SDK/CLI 파이프라인이 담당하고 GUI는 명시 ID로 조회한다. 저장하지 않은 수정은 조회 전환/채택을 잠그며 명시적으로 버릴 수 있다. 다른 task 조회와 revision conflict는 기존 buffer를 유지한다. malformed 초안의 편집을 버려도 빈 task별 구조화 editor를 유지한다.

이 시점은 source freeze이며 Rust 최종 gate는 SDK 세션이 공유 target에서 수행 중이다. 실제 player의 입력/저장/채택 검증은 아직 하지 않았다. 기존 sample 검사기 readonly와 disabled actions는 이 실제 제안 영역을 대신하지 않는다. 정확한 실행 근거를 후속 기록으로 추가한다.

[r161 중간 실제 관측](../../../verification/presentation/proposal-ui-cycle-2026-10-19.md)에서 교정 malformed 수동복구와 카드 수정/save2/accept3·receipt를 확인했다. 재시작 receipt 복원 계약 누락을 SDK에 전달했다. 원생성 import 오류는 현재 수정본 저장 상태와 별개라는 label을 추가한다. 최종 SHA 재검토 및 하이라이트/충돌/재시작/좁은 편집은 미완료다.

후속 typed inspect는 application::proposals::StoredProposal(document,acceptance)를 반환한다. UI 전용 Inspected 결과로 문서와 receipt를 함께 복원하며 revision 숫자로 채택을 추정하지 않는다. 같은 revision3에서 acceptance Some/None을 각각 주는 회귀로 명시적 상태 사용을 검증한다. create/edit의 Document와 accept의 Receipt 반환 계약은 유지한다. SDK 최종 gate와 새 SHA 실제 재시작 인수 전에는 복원 완료로 판정하지 않는다.

## 계약과 책임

[SDK 제안 정본](../../application/api/proposals.md)을 소비한다. UI는 typed client 호출·비동기 상태·사용자 입력·표시를 소유한다. source snapshot/raw generated result는 읽기 전용이고 사용자의 편집 buffer와 저장된 draft를 분리한다. application 정책·직접 파일 저장·JSON 정책 파서를 presentation에 만들지 않는다. 정확한 Rust DTO는 SDK 구현 공유 후 연결한다.

## 공용 컴포넌트와 상태

공용 비교 프레임은 기존 text_comparison의 FIELD 면·THIN/BORDER·CONTROL radius·label/content 구조를 따른다. 편집 영역은 source-owned 공용 multiline editor로 조합하고 Pretendard/일본어 fallback·body13·전체 폭·최소 CONTROL 높이·내부 스크롤을 사용한다. 키보드 포커스와 선택은 별도 토큰으로 표시한다. 화면마다 editor 테두리/여백을 복제하지 않는다.

요청 중에는 대상 선택·수정·중복 저장/채택을 잠그고 세션 generation 및 proposal/revision으로 늦은 응답을 구분한다. expectedRevision을 최신 저장된 document에서 전달한다. revision_conflict는 기존 편집을 성공처럼 지우지 않고 재조회/재검토 사유를 표시한다. accept 성공은 receipt의 새 output_revision과 source/revision을 표시한다. ‘원본 저장 완료’나 ‘모델 승인’으로 표현하지 않는다.

needs_repair/import_error는 원생성결과와 오류를 그대로 표시하고 유효한 typed draft 수정을 안내한다. 유효한 저장 draft가 없으면 채택을 비활성화한다. backend unavailable과 확인된 빈 목록을 구분한다. capability를 근거로 실제 동작을 연결하며 예시 데이터를 실제 제안/채택 결과로 승격하지 않는다.

수동 복구도 raw JSON 편집을 필수로 요구하지 않는다. 교정은 원문 cue 선택+수정문, 카드는 front/back 필드+원문 근거 선택, 하이라이트는 title+원문 근거 선택이라는 작업별 입력을 제공한다. 원생성 raw는 읽기 전용 증거이며 사용자가 schema를 작성해야만 복구할 수 있는 UX로 만들지 않는다. 채택 receipt는 출력 문서 revision의 결과이며 실제 미디어 렌더링/파일 export 완료와 별도로 표시한다.

## 검증 계획

1440/760에서 한국어·일본어·긴 원문/제안 줄바꿈과 편집 focus·선택/내부 스크롤·drawer/Escape를 실제 검토한다. 정상 저장→채택 receipt, malformed→사용자 수정→저장→채택, stale revision, source revision mismatch, 중복 입력, 제안 전환 중 늦은 응답은 SDK 통합 검증과 UI 관측을 구분한다. 원문/원생성 bytes 불변·출력 revision 분리는 SDK 증거로 확인한다. 현재 문서는 설계이며 편집/채택 UI 구현·실제 검증은 미완료다.
