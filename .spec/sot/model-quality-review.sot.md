# 모델 결과 검토와 기능별 채택

2026-10-24 사용자 결정: **AI 품질은 실제 제품 GUI의 사용자 테스트 과정에서 사용자가 검증하고 승인한다.** 개발 담당의 SDK/CLI 기능 인수·자동 수치 검사·실측 및 테스트용 판정 저장은 선행 기술 근거이며 사용자 품질 승인이 아니다. 현재 사용자 승인 완료를 뜻하지 않으며, 준비된 GUI·원본/결과 표본·비교/재생·수정·명시적 판정·이력 확인을 제공한 뒤 사용자 테스트로 인수한다. 검토 준비 전에는 개발 미완료로 기록하며 지금 별도 모델 승인이나 수동 GUI 시험을 요구하지 않는다.

2026-10-19 사용자 정정 반영. 기존의 ‘제품 품질 승인 0개’는 품질 검증과 검토 준비가 미완료라는 뜻이다. 검토 가능한 입력·출력·기준·판정 기록 기능을 제공하지 않고 사용자 미승인을 차단 조건으로 삼지 않는다. 현재 구현·실측 현황은 [모델 상태](../../verification/ai/model-status.md)를 따른다.

## 역할과 상태

2026-10-19 사용자 결정: 자막 교정·카드 문구·하이라이트를 원문과 비교해 사람이 수정·채택하는 **제안 기능부터 제품에 연결**한다. 모든 모델 품질 개선을 끝낼 때까지 제품 연결을 보류하는 순서보다 이를 우선한다. 이 결정은 현재9개 결과의 품질 승인이나 자동 적용 허용이 아니다. 개발 담당은 알려진 실패를 먼저 표시하고 수정하며, 새 제안도 원문 보존·변경 비교·명시적 채택을 거친다. 구체적인 정책은 공통 application/domain에서 소유하고 GUI와 CLI가 공유한다.

공통 SDK 경계와 채택 이유는 [검토 경계 결정](../../../adrs/player/adr-model-result-review-boundary.md)에 둔다. 실제9개 텍스트 표본의 package/CLI/text-asset 검증은 [실측 정본](../../verification/ai/text-review-sdk-actual.md)에 기록하며, GUI 판정 화면의 실행 인수와 구분한다.

자동 검사·원본 대조·오류 수정·실제 결과 패키징은 개발 담당이 수행한다. 사용자는 준비된 결과에서 주관적 가독성·편집 적합성·허용 오차를 판단한다. 실행 완료, 수치 검증, 의미 품질 검증, 검토 준비 완료, 특정 기능 채택을 별도 상태로 기록한다. 검토 패키지가 없으면 ‘검토 준비 미완료’이며 ‘사용자 승인 대기’가 아니다.

## 제공해야 할 검토 패키지

각 표본은 원본 미디어와 고정 구간, 결과 자산, 모델/엔진 revision·정밀도·설정, 측정 자원, 자동 검사 결과, 알려진 오류를 연결한다. 동일 표본의 기준선과 후보를 나란히 비교할 수 있어야 한다. 모델명만 보여 주거나 보고서 수치만으로 승인받지 않는다. 현재 텍스트9개는 공통 SDK/CLI 조회와3자산 실제 텍스트 전달을 확인했다. 네이티브 MODEL의 일부 표본 표시·복제 저장소 판정 저장·재시작 이력·760 폭 표시는 [r153/r154 실행 검증](../../verification/presentation/model-review-cycle-2026-10-19.md)에서 확인했다. GUI에서9개 모두 읽기와 음성·영상 전체 패키지는 미완료다. 동작 검증용 판단 보류 기록은 사용자 품질 판정이 아니다.

| --- | --- | --- |

## 사용자에게 안내할 실제 검토 순서

아래 로컬 웹 주소와 r154 실행본 안내는 2026-10-19 당시의 제한된 검토·저장 시험 이력이다. 현재 제품의 GUI 사용자 테스트 입장이나 최종 품질 승인 경로로 그대로 안내하지 않는다. 최종 테스트에는 당시의 개발용 판정과 분리된 실제 제품 실행본·검토 저장소·실제 표본을 준비한다. CLI/API 판정 저장 계약은 공유하되 테스트/에이전트가 기록한 usable을 실제 사용자의 품질 승인으로 해석하지 않는다.

진행 순서: 사용자의 후속 지시에 따라 모델 검토는 제안 기능의 SDK·GUI/CLI 연결과 통합 검증 뒤 마지막에 진행한다. 준비·품질 점검은 AI 모델 조사 세션이 담당하고 root가 통합한다. 아래 절차는 준비된 자료를 최종 검토할 때 사용하며 지금 사용자 평가를 요구하거나 이를 제품 연결의 차단 조건으로 삼지 않는다.

읽기 전용 화면은 `http://127.0.0.1:9617/`이며 실행 중인 로컬 서버가 필요하다. Gemma270·Llama1B·Qwen0.6의 교정·카드·하이라이트 실제 텍스트 결과9개를 확인하는 범위다. 음성·화자·영상 품질 전체 검토 화면으로 안내하지 않는다. 이 화면에는 판정 저장 기능이 없다. 네이티브 MODEL은 아래의 제한된 범위에서 실제 비교·판정 저장을 검증했으며, 두 화면의 기능을 구별한다.

네이티브 실행 기준은 `runtime/review-runs/ui-model-review-20261019-r154/player.exe`와 명시적인 절대 `--review-root`다. 고정 실행본 SHA·실제 사용 저장소와 테스트 판정은 위 실행 검증 문서를 따른다. MODEL의 package SHA 입력에는 `659b3cb6757259d8e770f6d3c96c4a77dafbab43c6ea540bcc7e0c58e4eb0197`을 넣고 자료 열기를 실행한다. 이 SHA는 r3 텍스트 표본 패키지 식별자이며 모델 품질 합격 표시가 아니다. 사용자 검토에서는 UI 테스트 판정이 들어 있는 복제 저장소를 품질 평가 이력으로 사용하지 않는다. 실행 인수·저장소 준비는 개발 담당이 제공하며 사용자에게 구성 진단을 넘기지 않는다.

1. 같은 작업의 원문과 후보 결과를 대조한다. 원문은 사람 정답이 아니므로, 원문에 없는 내용·의미 변경·누락 여부를 직접 확인한다.
2. 교정은 의미 보존·잘림·반복, 카드는 사실성·읽기 쉬움, 하이라이트는 원문 근거·선정 적합성을 확인한다. 현재 텍스트 표본에는 검증된 영상 시각이 없으므로 장면 연결 정확도는 판단하지 않는다.
3. 모델/작업/표본을 지정해 ‘사용 가능 / 수정 필요 / 판단 보류’와 필수 메모를 남긴다. 네이티브 MODEL에서는 저장 응답 뒤 이력을 명시적으로 읽어 같은 판정 ID와 메모가 남았는지 확인한다. 대화로 의견을 전달한 경우 실제 SDK 저장 전에는 저장 완료로 표시하지 않는다. 예: `Qwen0.6 / 카드 / 표본 ID: 수정 필요 — 두 번째 카드에 원문에 없는 사실이 있음`.
4. 개발 담당이 오류를 수정하고 같은 표본과 추가 독립 표본으로 다시 검증한다. 결과와 변경점을 제공한 뒤 사용자에게 재검토 범위를 명시한다.

‘사용 가능’은 해당 조건의 표본 판정이다. 기능 출시나 자동 적용 승인은 별도로 기능·revision·정밀도·입력 조건·허용 오류·수동 확인 여부를 제시한 후 요청한다. 사용자가 수치 검사나 개발 결함 진단을 대신하도록 요구하지 않는다. 검토 자료·실행 방법이 준비되지 않은 기능은 개발 담당의 미완료 작업으로 기록한다.

## 판정과 승인 범위

표본별 판정은 ‘사용 가능 / 수정 필요 / 판단 보류’와 문제 구간·이유를 남긴다. ‘판단 보류’를 통과로 처리하지 않는다. 전체 검토 후에도 모델 자체에 포괄 승인을 붙이지 않고, 모델 revision·정밀도·입력 조건·기능·수동 확인/자동 적용 범위에 한정해 채택한다. 자동 스킵·자동 자막 교체·자동 제작 출력은 별도 기능 정책을 만족해야 한다.

GUI와 AI 친화 CLI는 같은 application 검토 유스케이스와 domain 판정 계약을 사용한다. 아직 실제 검증하지 않은 검토 버튼·명령·자동화 기능을 사용 가능하다고 안내하지 않는다. 현재 사용자에게 필수 승인 작업을 요구하지 않는다. 다음 개발 작업은9개 전체 읽기·키보드·복사·오류 경로의 잔여 검증과 음성·영상 검토 패키지 제공이다. [내용 감사](../../verification/ai/text-review-content-audit.md)에서 이미 확인한 잘림·반복·근거 오류는 개발 수정 대상으로 추적하며, 사용자에게 그대로 승인하도록 요청하지 않는다. Pages 재개·VM·DPI 변경은 이 계약에 포함하지 않는다.
