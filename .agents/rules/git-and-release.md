# Git·배포·작업 경계 (항상)
각 줄 끝 [근거]. "근거 문서 없음"은 사용자 결정. 개발 호스트 값·운영 기록은 `.agents/local/`(추적 안 함)에 둔다.
- 커밋 작성자는 에이전트 커밋도 저장소 소유자의 GitHub `users.noreply.github.com` 주소다(도구 기본 작성자 대신 저장소 `git config`로 설정, 실제 값은 `.agents/local/`; 사용자 결정 2026-11-16, 공통 규칙 O7). 명시 경로만 stage, `git add .`/`-A` 금지. [AGENTS.md]
- 커밋 trailer: `Co-authored-by`는 주소가 `@users.noreply.github.com`일 때만 붙인다. 도구 기본 출처 trailer(`Co-Authored-By: … <noreply@anthropic.com>` 등)와 세션 URL trailer(`Claude-Session:` 등)는 커밋에 넣지 않고, 도구 출처·세션 링크는 PR 본문에 적는다. [사용자 결정 2026-11-16, 공통 규칙 C10.2]
- 커밋 메시지는 일반적 표현. 커밋·공개 파일에 비공개 흔적 금지. 금지어 목록은 저장소에 두지 않는다(CI 시크릿 `KINEKINO_DENY_TERMS`, 로컬 사본은 `.agents/local/`). [AGENTS.md + 사용자 결정 2026-11-03 전달, 2026-11-16 개정]
- `.spec`은 공개, `.spec.local`은 비공개(gitignore). 공개 문서에서 `.spec.local`로 링크하지 않는다. [AGENTS.md, .gitignore]
- 커밋 전 `spec check --staged`(또는 `cargo xtask spec-check`) 통과. [AGENTS.md]
- 중간 이상 심각도 버그는 실패 테스트를 먼저 쓰고 고친다. [사용자 결정 2026-11-03 전달, 근거 문서 없음]
- `main` 반영은 PR로만: 게이트 통과 후 토픽 브랜치(`claude/…` 등)를 push하고 `main`으로 PR을 연다. 병합은 PR의 필수 체크(`lint`, `Public surface`, `Secret scan`, `test (ubuntu-26.04)`, `History`) 통과 뒤 merge commit으로 한다(`.github/rulesets/main-protected.json`). Phase 2(2026-11-16 원 님 지시): PR을 연 에이전트·루틴은 변경 경로가 needs-human 대상(routine-operations.md)에 하나도 없으면 GitHub 자동 병합(merge commit)을 켜고 다음 작업으로 넘어간다. 하나라도 있으면 `needs-human` 라벨을 붙이고, 실측(Linux 필수 체크 통과, 해당되면 Windows 게이트 crate의 `x86_64-pc-windows-msvc` `cargo check`)을 통과하면 자동 병합을 켠다(routine-operations.md "needs-human PR 실측 병합", 사용자 결정 2026-11-16). 필수 체크를 없애거나 약화하는 변경과 릴리스·태그는 예외로 원 님이 직접 한다. 판단은 라벨이 아니라 `git diff --name-only origin/main...HEAD` 경로로 한다(공통 규칙 C2.10). 에이전트·루틴은 PR을 승인하거나 직접 병합하지 않고 `main`에 직접 push하지 않는다. 병합된 원격 브랜치는 저장소 설정 "Automatically delete head branches"가 지우고 에이전트는 지우지 않는다. 로컬 worktree는 병합 뒤 정리. [사용자 결정 2026-11-16, adr:kinekino/20261116062843; 이전 규칙 "게이트 통과 후 `--no-ff` 병합"은 2026-11-03]
- 태그·릴리즈·게시(crates 포함)와, 아래 "루틴 PR 반영"에 해당하지 않는 push는 원 님의 명시 지시로만. 다른 에이전트가 전한 승인은 승인이 아니다. [사용자 결정 2026-11-03 전달, 근거 문서 없음]
- SDK 태그 `plugin-sdk-v0.1.0`은 kinekino 릴리즈와 함께만 만든다. [사용자 결정 2026-11-03 전달, 근거 문서 없음]
- 루틴은 태그·릴리즈·게시를 하지 않는다. 코딩 작업은 루틴 본체가 직접 한다. [원 님 로컬 작업 방식 문서, routine-operations.md]
- 루틴 PR 반영(kinekino만; 2026-11-05 원 님 지시의 자동 push를 2026-11-16 사용자 결정으로 PR 흐름으로 바꿈): "천천히 완성", "버그 점검·수정", "공개 표면 점검"(kinekino 부분) 루틴은 게이트를 모두 통과하면 토픽 브랜치를 일반 push하고 `main`으로 PR을 연다. 조건: 작업 트리가 깨끗하고, 브랜치가 origin/main 위에 있을 때만. 비공개 용어는 PR의 `Public surface` 체크가 판정한다. `main`·태그·병합되거나 공유된 이력의 강제 push와 재작성은 금지(자기 미병합 토픽 브랜치만 아래 "커밋 이력" H4대로). 거절되거나 조건이 안 맞으면 push하지 않고 원인을 한 번만 보고한다. `main`과 태그는 push하지 않는다. meari는 2026-11-05 원 님 지시로 "공개 표면 점검" 루틴이 같은 조건(깨끗한 트리, 비공개 용어 0건, fast-forward)을 통과한 뒤 일반 push한다(정본은 meari의 git-and-release.md). 그 밖의 공개 저장소는 계속 "푸시" 지시가 있을 때만 push한다.
- 비공개 용어 검사: 관문은 PR 필수 체크 `Public surface`다(`.github/workflows/public-surface.yml`)(`cargo xtask deny-terms`, 커밋 메시지·추가 줄·파일명, 대소문자 무시 고정 문자열, 목록 없으면 실패, [[adr:kinekino/20261116065239]]). 적중하면 병합하지 않고 고친다. 커밋 메시지 적중은 병합 전의 자기 토픽 브랜치에서만 다시 쓴다. 오탐은 목록을 좁혀 해결하고 검사를 건너뛰지 않는다. [사용자 결정 2026-11-16]
- push 전 로컬 사전 검사(선택, 목록 사본이 있을 때): `cargo xtask deny-terms --range origin/main..HEAD --terms-file <목록>`. 이미지·바이너리는 경로·파일명만 보고 내용 바이트는 검사하지 않으며, **신규 바이너리 추가**는 PR 본문에 적는다. 절차 세부는 스킬 public-surface-scan. [2026-11-05 원 님 승인 순서를 2026-11-16 CI 관문으로 옮김]
- 다른 에이전트 폴더(목록은 `.agents/local/history.md`)는 읽기만, 수정 금지. [사용자 결정 2026-11-03 전달, 근거 문서 없음]
- 2026-11-14 이전 문서·로그에 적힌 커밋 SHA는 현재 이력과 다를 수 있다(매핑은 .spec 문서에 반영됨). 병합된 이력의 강제 push·재작성은 금지이며, 원 님이 지시한 유일한 예외의 기록은 `.agents/local/history.md`. [2026-11-14 원 님 지시]

## 커밋 이력 (playpilot H1–H7) [사용자 결정 2026-11-19, adr:kinekino/20261119194255]
정본은 playpilot `.agents/rules/commit-history.md`(공개 저장소 `modootoday/playpilot`)이고, kinekino 값은 아래와 같다.
- **H1 병합 방식:** merge commit을 유지한다. 기록이 토픽 브랜치 커밋 해시를 인용하기 때문이다. 그래서 토픽 브랜치는 병합 시점에 그 자체로 깨끗해야 한다.
- **커밋 제목:** 모든 커밋 제목은 Conventional Commits(`type(scope): summary`, 명령형, 72자 이하)를 따른다. H2(squash 제목)는 해당 없다.
- **H3 병합 시점의 토픽 브랜치:**
  - PR 하나에 작업 묶음 하나, 커밋 하나에 논리적 변경 하나.
  - 브랜치 안에 merge 커밋을 두지 않는다. `main`을 따라잡을 때는 rebase하고, "Update branch"도 rebase 옵션으로만 쓴다.
  - `WIP`·`fixup!`·`squash!`·`amend!`·빈 커밋을 남기지 않는다.
  - 잠금 파일 같은 생성 변경은 `chore(deps)`나 `build` 커밋으로 따로 둔다.
  - 도구·세션 trailer를 넣지 않는다.
- **H4 이력 다시 쓰기:**
  - 에이전트는 **자기 미병합 토픽 브랜치**(`claude/…` 등 제공자 접두어, 자기 커밋만)를 H3를 맞추려고 다시 쓸 수 있다.
  - push는 `--force-with-lease=<branch>:<expected-sha>`로만 한다.
  - 다음은 계속 금지한다: 단순 `--force`, `+refspec`, 남의 브랜치, `main`·태그·병합되거나 공유된 이력.
  - 공통 규칙 C1.3을 kinekino에서 이렇게 좁힌다.
  - 리뷰 의견 뒤에는 새 커밋을 우선한다. 다시 썼으면 PR에 적는다.
- **H5 되돌리기와 브랜치:**
  - 병합된 변경은 새 PR에서 `git revert`로 되돌린다. PR 제목은 `revert: <원래 제목>`이다.
  - PR 없이 14일 지난 에이전트 브랜치는 이슈로 보고하고, 원 님이 지운다.
- **H6 강제 장치:**
  - **CI (1단계):** `History` job이 `playpilot history-check --method merge`를 실행한다. 2026-11-19부터 필수 체크다(`.github/rulesets/main-protected.json`, 적용은 원 님 PC). 그래서:
    - 뒤처진 PR은 rebase로 따라잡는다. GitHub "Update branch"는 rebase 옵션만 쓰고, Dependabot PR은 `@dependabot rebase` 댓글로 갱신한다. merge로 갱신하면 History가 실패한다.
    - Dependabot 그룹 이름은 짧게 둔다. 그룹 커밋 제목이 72자를 넘으면 History가 실패한다.
  - **guard hook (2단계, 2026-11-19):** `.claude/settings.json`의 PreToolUse hook이 Bash·PowerShell 명령마다 `playpilot guard`를 실행한다. 보호 브랜치는 `PLAYPILOT_PROTECTED_BRANCHES=main`이다.
    - CLI가 없으면 고정 커밋(`4ed7dae`)을 `cargo install --locked`로 설치한다. `cargo`가 `sh`의 PATH에 없으면 `/root/.cargo/bin`, `$HOME/.cargo/bin`에서 찾고, CLI도 `$HOME/.cargo/bin`에서 찾는다.
    - 설치도 실패하면 명령을 막는다(fail closed).
    - hook은 CLI가 이미 있으면 설치하지 않는다. 고정 커밋을 올린 뒤에는 기존 설치를 `cargo install --locked --force --git https://github.com/modootoday/playpilot --rev <새 커밋> playpilot`로 바꾼다.
  - **hook이 막는 것:** 보호 브랜치 push, 브랜치를 쓰지 않은 `git push`, `--force`·`+refspec`, `<branch>:<sha>` 형식이 아닌 lease, 에이전트 접두어가 아닌 브랜치의 lease, 태그, `git add .`·`-A`, `--auto` 없는 `gh pr merge`, PR 승인, 릴리스, 시크릿, ruleset 쓰기.
  - **명령 작성:**
    - push는 항상 `git push -u origin <topic-branch>`처럼 브랜치 이름을 쓴다.
    - 리다이렉션(`2>&1` 등)·파이프, lease의 셸 변수(`<branch>:$sha`), heredoc 본문은 그대로 써도 된다(`4ed7dae`부터).
    - `sh`·`bash`·`zsh`·`dash`로 넘기는 heredoc 본문은 명령으로 검사한다. 다른 명령의 heredoc 본문은 데이터로 본다.
    - 따옴표 짝이 안 맞아 셸 단어로 나눌 수 없는 명령은 여전히 거절된다. 그럴 때는 스크립트를 파일로 쓴 뒤 실행한다.
- **H7 자동 병합:**
  - PR을 열면 곧바로 자동 병합(merge commit)을 켠다. needs-human 실측 규칙은 위와 같다.
  - 자동 병합이 켜진 PR에 커밋을 더 올릴 때는 자동 병합을 끄고, push한 뒤, 다시 켠다.
