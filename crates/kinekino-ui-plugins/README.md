# Product UI plugins

Rust product adapters consume canonical `media-subtitles` and `media-contracts` types. The first source is the subtitle conversion codec with an explicitly injected typed host call. Root assembly owns `ApplicationClientHandle`, request IDs and `RequestContext`; its closure calls `client.convert_subtitles(context, payload)`. This package never depends on the root SDK crate, and never parses subtitles or publishes files in production.

This is an isolated workspace pending SDK/PM integration; root Cargo/lock are unchanged. `infrastructure::meari_conversion::MeariSubtitleConversion` implements Meari PluginAdapter with host-supplied contract/provider/schema pins and per-invocation ticket context. The r2 fmt check, six tests, strict all-target Clippy and wasm32 library check passed. Three new tests register the real adapter for Native/Web target settings and cover canonical in-memory conversion success, canonical SDK error/lifetime, and grants/schema rejection. These target settings and WASM type checking do not prove browser execution or actual OS file support. No duplicate registry, dynamic loader, IPC daemon or JS runtime is provided. A browser without a compatible SDK transport uses the explicit Unsupported adapter; Rust traits alone do not provide a Web ABI.

Exact r2 logs/source/hashes are in `runtime/quality-review/player-ui-plugins-r2`; scope is recorded in `.spec/sots/verification/presentation/product-plugin-registry-2026-10-19.md`. Root ApplicationClient assembly, source callbacks, real Native/Web resource permissions and renderer/visual acceptance remain pending. Provider hashes are metadata, not a verified trust system.
